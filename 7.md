## Bab 0. Persiapan Lingkungan Belajar

### 0.1 Memasang Node.js

**Node.js** adalah _runtime_ yang memungkinkan JavaScript berjalan di luar browser, misalnya di server. Runtime adalah program yang menjalankan kode Anda dan menyediakan fitur tambahan seperti akses file dan jaringan.

Cara pemasangan yang direkomendasikan adalah memakai _version manager_ agar mudah berganti versi:

- `nvm` (Linux dan macOS), atau `nvm-windows`
- `fnm` (lintas platform, cepat)
- atau installer resmi dari situs nodejs.org

Setelah terpasang, cek versinya:

```bash
node --version
npm --version
```

### 0.2 Versi mana yang dipakai

Per Oktober 2026, kondisinya sebagai berikut:

|Versi|Status|Catatan|
|---|---|---|
|Node.js 22|Maintenance LTS|Masih menerima perbaikan keamanan, berakhir April 2027|
|Node.js 24|Active LTS|Pilihan paling aman untuk produksi saat ini, didukung hingga April 2028|
|Node.js 26|Current, dijadwalkan masuk LTS pada Oktober 2026|Rilis Mei 2026, mengaktifkan Temporal secara bawaan|

**LTS** (Long-Term Support) berarti versi yang mendapat dukungan jangka panjang. Untuk aplikasi produksi, gunakan versi LTS. Untuk belajar, gunakan Node.js 24 atau yang lebih baru agar fitur modern di buku ini bisa langsung dicoba.

Beberapa fitur terbaru membutuhkan versi tertentu, dan ditandai di tempatnya. Sebagai gambaran: iterator helpers dan method Set (Bab 6 dan 11) tersedia di Node.js 22 ke atas, `Promise.try` dan `RegExp.escape` membutuhkan Node.js 24 ke atas, dan Temporal aktif bawaan di Node.js 26.

Catatan penting: Node.js mengumumkan perubahan kebijakan rilis. Mulai Node.js 27, rilis mayor menjadi satu kali per tahun (setiap April), dan setiap rilis akan menjadi LTS. Penjelasan lebih lanjut ada di Bab 1.

### 0.3 Menyiapkan folder latihan

```bash
mkdir belajar-js-lanjutan
cd belajar-js-lanjutan
npm init -y
```

Buka file `package.json` yang dibuat, lalu tambahkan baris `"type": "module"`:

```json
{
  "name": "belajar-js-lanjutan",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "test": "node --test"
  }
}
```

Baris `"type": "module"` membuat semua file `.js` diperlakukan sebagai **ES Module** (ESM), sistem modul modern JavaScript. Seluruh contoh di buku ini memakai ESM kecuali dinyatakan lain. Perbedaannya dengan CommonJS dibahas di Bab 9.

### 0.4 Program pertama dan mode pantau

Buat file `halo.js`:

```js
console.log('Halo, Backend Developer');
console.log('Versi Node.js:', process.version);
```

Jalankan dengan mode pantau (_watch_) agar program otomatis dijalankan ulang saat Anda menyimpan perubahan:

```bash
node --watch halo.js
```

### 0.5 Editor dan alat bantu

- **Editor**: Visual Studio Code atau editor lain yang Anda nyaman.
- **Terminal**: biasakan bekerja dari terminal.
- **Klien HTTP**: `curl`, Postman, atau Insomnia untuk mencoba API.
- **Git**: simpan latihan Anda di repository Git agar riwayat perubahan tercatat.

## Bab 1. Peta JavaScript di Tahun 2026

### 1.1 JavaScript, ECMAScript, dan runtime

Tiga istilah ini sering tercampur:

- **JavaScript** adalah bahasa pemrogramannya.
- **ECMAScript** (disingkat ES) adalah _spesifikasi resmi_ bahasa tersebut. Setiap tahun ada edisi baru, misalnya ES2025 dan ES2026.
- **Runtime** adalah program yang menjalankan JavaScript: browser (Chrome, Firefox, Safari), Node.js, Deno, dan Bun.

Analogi sederhana: ECMAScript adalah buku resep resmi, JavaScript adalah masakannya, dan runtime adalah dapur tempat masakan itu dibuat. Dapur yang berbeda bisa mendukung resep baru pada waktu yang berbeda.

Node.js dan Chrome sama-sama memakai mesin **V8** (buatan Google) untuk mengeksekusi JavaScript. Karena itu, fitur bahasa di Node.js biasanya mengikuti versi V8 yang ia bawa. Contohnya, Node.js 26 membawa V8 versi 14.6.

### 1.2 Bagaimana fitur baru masuk ke bahasa

Komite **TC39** mengelola ECMAScript. Setiap usulan fitur (disebut _proposal_) melewati tahap:

|Tahap|Arti|
|---|---|
|Stage 0|Ide awal|
|Stage 1|Diusulkan secara resmi|
|Stage 2|Draf spesifikasi tersedia|
|Stage 3|Kandidat, menunggu implementasi dan masukan|
|Stage 4|Selesai, akan masuk edisi ECMAScript berikutnya|

Sebagai backend developer, aturan praktisnya: **jangan memakai fitur di bawah Stage 3 untuk produksi**, kecuali lewat alat transpiler yang Anda pahami risikonya.

### 1.3 Fitur penting berdasarkan edisi

Tabel berikut merangkum fitur yang paling relevan untuk backend. Pembagian fitur per edisi bisa sedikit berbeda antar sumber, jadi yang terpenting adalah mengecek ketersediaannya di tabel kompatibilitas MDN.

|Edisi|Fitur penting|
|---|---|
|ES2015|`let`, `const`, class, arrow function, Promise, modul, Map, Set, generator, destructuring|
|ES2017|`async` dan `await`, `Object.entries`|
|ES2018|Async iteration (`for await`), spread pada object|
|ES2020|Optional chaining `?.`, nullish coalescing `??`, BigInt, `Promise.allSettled`, `import()` dinamis|
|ES2021|`??=`, `Promise.any`, `replaceAll`|
|ES2022|Top-level await, class field dan private field `#`, `Array.at`, `Error` dengan `cause`, `Object.hasOwn`|
|ES2023|`toSorted`, `toReversed`, `with`, `findLast`|
|ES2024|`Object.groupBy`, `Map.groupBy`, `Promise.withResolvers`|
|ES2025|Iterator helpers, method pada Set (`union`, `intersection`, dan lainnya), `Promise.try`, `RegExp.escape`, `Float16Array`, import attributes untuk modul JSON|
|ES2026|**Temporal** (pengganti `Date`), `Error.isError`, `Math.sumPrecise`, konversi Base64 dan hex pada `Uint8Array`, `Array.fromAsync`|

Satu fitur lain yang patut diketahui adalah _explicit resource management_ dengan kata kunci `using`, yang membuat sumber daya (koneksi, file) otomatis dibersihkan saat keluar dari blok. Fitur ini sudah diimplementasikan di engine modern, tetapi cek status dan kompatibilitas pada runtime Anda sebelum memakainya.

### 1.4 Model rilis Node.js yang berubah

Hingga Node.js 26, ada dua rilis mayor per tahun dan hanya versi bernomor genap yang menjadi LTS. Berdasarkan pengumuman resmi tim Node.js, mulai Node.js 27 aturannya berubah:

|Aspek|Aturan baru|
|---|---|
|Rilis mayor|Satu kali per tahun, bulan April|
|Fase Alpha|6 bulan (Oktober sampai Maret), perubahan besar masih boleh|
|Fase Current|6 bulan (April sampai Oktober), masa stabilisasi|
|Fase LTS|30 bulan, hanya perbaikan keamanan dan bug penting|
|Status LTS|Setiap rilis menjadi LTS, tidak ada lagi pembedaan ganjil dan genap|

Implikasinya bagi Anda: tetap pakai versi **LTS** untuk produksi, dan jadwalkan upgrade rutin setahun sekali agar tidak tertinggal.

### 1.5 Cara memeriksa dukungan fitur

Tiga cara yang berguna:

```js
// 1. Deteksi fitur langsung (feature detection)
if (typeof Temporal === 'undefined') {
  console.log('Temporal belum tersedia di runtime ini');
}

// 2. Periksa versi dan komponen runtime
console.log(process.versions.node); // versi Node.js
console.log(process.versions.v8);   // versi mesin V8

// 3. Periksa keberadaan method tertentu
console.log(typeof Promise.try === 'function');
```

Cara ketiga: buka halaman fitur di MDN Web Docs, lalu lihat bagian "Browser compatibility" yang juga mencantumkan versi Node.js.

> **Intinya** Gunakan Node.js LTS untuk produksi. Pahami bahwa fitur bahasa datang dari spesifikasi ECMAScript, sedangkan ketersediaannya bergantung pada versi runtime Anda.

## Bab 2. Tipe Data, Nilai, dan Referensi Secara Mendalam

### 2.1 Tipe data di JavaScript

JavaScript memiliki **tujuh tipe primitif** dan satu tipe object:

|Tipe|Contoh|Catatan|
|---|---|---|
|`string`|`'halo'`|Teks, tidak bisa diubah (immutable)|
|`number`|`42`, `3.14`|Bilangan floating point 64-bit|
|`bigint`|`9007199254740993n`|Bilangan bulat sangat besar|
|`boolean`|`true`, `false`||
|`undefined`|`undefined`|Variabel belum diberi nilai|
|`null`|`null`|"Sengaja kosong"|
|`symbol`|`Symbol('id')`|Pengenal unik|
|`object`|`{}`, `[]`, fungsi|Semua selain primitif|

Keanehan terkenal: `typeof null` menghasilkan `'object'`. Ini bug sejarah yang dipertahankan demi kompatibilitas. Untuk memeriksa `null`, gunakan perbandingan langsung:

```js
const nilai = null;
console.log(typeof nilai);  // => 'object' (menyesatkan)
console.log(nilai === null); // => true
```

### 2.2 Nilai versus referensi

Ini konsep yang menjadi akar banyak bug.

- **Primitif** disalin berdasarkan _nilai_.
- **Object** (termasuk array dan fungsi) disalin berdasarkan _referensi_, yaitu "alamat" tempat object itu berada di memori.

```js
// Primitif: disalin nilainya
let a = 10;
let b = a;
b = 20;
console.log(a); // => 10 (tidak terpengaruh)

// Object: yang disalin adalah referensinya
const user1 = { nama: 'Sari' };
const user2 = user1;     // keduanya menunjuk object yang sama
user2.nama = 'Budi';
console.log(user1.nama); // => 'Budi' (ikut berubah)
```

Analogi: variabel primitif seperti kertas yang berisi angka, kalau difotokopi maka kopiannya independen. Variabel object seperti kertas yang berisi alamat rumah, kalau difotokopi maka dua kertas menunjuk rumah yang sama.

### 2.3 Menyalin object dengan benar

```js
const asli = {
  nama: 'Sari',
  alamat: { kota: 'Cilacap' },
  hobi: ['membaca', 'berenang'],
};

// Salinan dangkal (shallow copy): hanya level pertama yang disalin
const dangkal = { ...asli };
dangkal.alamat.kota = 'Semarang';
console.log(asli.alamat.kota); // => 'Semarang' (ikut berubah!)

// Salinan dalam (deep copy): seluruh struktur disalin
const dalam = structuredClone(asli);
dalam.alamat.kota = 'Bandung';
console.log(asli.alamat.kota); // => 'Semarang' (aman)
```

`structuredClone` tersedia bawaan di Node.js modern. Ia mendukung `Date`, `Map`, `Set`, dan struktur melingkar, tetapi **tidak** bisa menyalin fungsi.

> **Kesalahan umum** Mengubah object yang diterima sebagai parameter fungsi. Fungsi lain yang memegang referensi yang sama akan terkena dampaknya. Biasakan membuat salinan baru, bukan memodifikasi input.

### 2.4 Imutabilitas

`const` hanya mencegah **penugasan ulang variabel**, bukan perubahan isi object:

```js
const config = { port: 3000 };
config.port = 4000;   // diperbolehkan
// config = {};       // TypeError: Assignment to constant variable
```

Untuk mengunci object, gunakan `Object.freeze`. Namun ia bersifat dangkal:

```js
const konfigurasi = Object.freeze({
  port: 3000,
  db: { host: 'localhost' },
});

konfigurasi.port = 9999;       // diabaikan (error jika strict mode)
konfigurasi.db.host = 'x';     // tetap berhasil, karena freeze dangkal
console.log(konfigurasi.port); // => 3000
```

Method array modern yang tidak mengubah array asal (ES2023):

```js
const angka = [3, 1, 2];
const terurut = angka.toSorted();     // => [1, 2, 3]
const terbalik = angka.toReversed();  // => [2, 1, 3]
const diganti = angka.with(0, 99);    // => [99, 1, 2]
console.log(angka);                   // => [3, 1, 2] (asli tidak berubah)
```

### 2.5 Perbandingan dan konversi tipe

JavaScript punya dua operator kesamaan:

- `===` (strict equality): membandingkan nilai **dan** tipe, tanpa konversi.
- `==` (loose equality): melakukan konversi tipe terlebih dahulu, sering mengejutkan.

```js
console.log(0 == '');        // => true   (mengejutkan)
console.log(0 === '');       // => false
console.log(null == undefined);  // => true
console.log(null === undefined); // => false
console.log('5' == 5);       // => true
console.log('5' === 5);      // => false
```

**Aturan praktis: selalu gunakan `===` dan `!==`.**

Ada satu kasus khusus. `NaN` tidak sama dengan dirinya sendiri, dan `Object.is` menangani ini:

```js
console.log(NaN === NaN);          // => false
console.log(Number.isNaN(NaN));    // => true
console.log(Object.is(NaN, NaN));  // => true
```

**Truthy dan falsy.** Dalam kondisi `if`, nilai berikut dianggap _falsy_: `false`, `0`, `-0`, `0n`, `''`, `null`, `undefined`, `NaN`. Selain itu _truthy_, termasuk `'0'`, `[]`, dan `{}`.

Perbedaan penting antara `||` dan `??`:

```js
const port1 = 0 || 3000;   // => 3000 (karena 0 falsy)
const port2 = 0 ?? 3000;   // => 0    (?? hanya menimpa null dan undefined)
```

Gunakan `??` untuk nilai bawaan agar `0`, `''`, dan `false` yang valid tidak ikut tertimpa.

### 2.6 Presisi bilangan dan BigInt

Tipe `number` memakai floating point, sehingga ada masalah presisi:

```js
console.log(0.1 + 0.2);            // => 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);    // => false
console.log(Number.MAX_SAFE_INTEGER); // => 9007199254740991
```

Dampaknya untuk backend:

1. **Uang**: jangan simpan sebagai desimal. Simpan sebagai bilangan bulat satuan terkecil (misalnya sen atau rupiah penuh), atau gunakan library desimal.
2. **ID besar**: ID dari sistem lain (misalnya ID 64-bit) bisa melebihi batas aman. Perlakukan sebagai `string` atau `BigInt`.

```js
const idBesar = 9007199254740993n;      // akhiran n = BigInt
console.log(idBesar + 1n);              // => 9007199254740994n
// console.log(idBesar + 1);            // TypeError: tidak boleh campur BigInt dan number
```

Jebakan: `JSON.stringify` tidak mendukung BigInt dan akan melempar error. Ubah ke string dulu:

```js
const data = { id: 123n };
// JSON.stringify(data); // TypeError: Do not know how to serialize a BigInt
console.log(JSON.stringify(data, (kunci, nilai) =>
  typeof nilai === 'bigint' ? nilai.toString() : nilai
)); // => {"id":"123"}
```

### Latihan Bab 2

1. Tanpa menjalankan kode, tebak hasil: `[] == false`, `[] === false`, `null ?? 'x'`, `0 ?? 'x'`. Lalu verifikasi.
2. Tulis fungsi `ubahNama(user, namaBaru)` yang mengembalikan object baru tanpa mengubah `user` asal.
3. Buktikan bahwa `{ ...obj }` tidak cukup untuk object bersarang, lalu perbaiki dengan `structuredClone`.

## Bab 3. Scope, Hoisting, dan Closure

### 3.1 Scope

**Scope** adalah wilayah kode tempat sebuah variabel bisa diakses. Ada tiga jenis utama:

- **Global scope**: bisa diakses di mana saja.
- **Function scope**: variabel `var` di dalam fungsi hanya terlihat di fungsi itu.
- **Block scope**: variabel `let` dan `const` di dalam `{ ... }` hanya terlihat di blok itu.

```js
function contoh() {
  if (true) {
    var a = 1;   // function scope
    let b = 2;   // block scope
    const c = 3; // block scope
  }
  console.log(a); // => 1
  // console.log(b); // ReferenceError: b is not defined
}
contoh();
```

**Kebiasaan yang baik: pakai `const` secara bawaan, `let` bila perlu menugaskan ulang, dan hindari `var`.**

### 3.2 Hoisting dan Temporal Dead Zone

**Hoisting** adalah perilaku di mana deklarasi "diangkat" ke atas scope sebelum kode dijalankan.

```js
console.log(x); // => undefined (var di-hoist, nilainya belum ada)
var x = 5;

// console.log(y); // ReferenceError: Cannot access 'y' before initialization
let y = 5;
```

`let` dan `const` juga di-hoist, tetapi berada di **Temporal Dead Zone (TDZ)**, yaitu masa dari awal scope sampai baris deklarasinya. Mengakses variabel di TDZ melempar error. Ini justru bagus karena menangkap kesalahan lebih dini.

Deklarasi fungsi (`function nama() {}`) di-hoist **beserta isinya**, sehingga bisa dipanggil sebelum ditulis. Fungsi yang disimpan dalam variabel (`const f = () => {}`) tidak.

```js
sapa(); // => 'halo' (berhasil)
function sapa() { console.log('halo'); }

// tegur(); // ReferenceError (TDZ)
const tegur = () => console.log('hei');
```

### 3.3 Closure

**Closure** terjadi ketika sebuah fungsi "mengingat" variabel dari scope tempat ia dibuat, bahkan setelah scope tersebut selesai dieksekusi.

Analogi: fungsi membawa ransel berisi variabel-variabel dari tempat kelahirannya, dan ransel itu ikut ke mana pun fungsi dipanggil.

```js
function buatPenghitung() {
  let jumlah = 0;            // variabel "privat"
  return function () {
    jumlah += 1;
    return jumlah;
  };
}

const hitungA = buatPenghitung();
const hitungB = buatPenghitung();

console.log(hitungA()); // => 1
console.log(hitungA()); // => 2
console.log(hitungB()); // => 1 (punya ransel sendiri)
```

Variabel `jumlah` tidak bisa diakses dari luar, kecuali lewat fungsi yang dikembalikan. Inilah cara klasik membuat **enkapsulasi** (menyembunyikan data internal).

### 3.4 Penggunaan closure di backend

**Contoh 1: factory untuk logger dengan konteks tetap**

```js
function buatLogger(namaLayanan) {
  return (level, pesan) => {
    console.log(`[${new Date().toISOString()}] [${namaLayanan}] ${level}: ${pesan}`);
  };
}

const logUser = buatLogger('layanan-user');
const logBayar = buatLogger('layanan-pembayaran');

logUser('INFO', 'User berhasil dibuat');
logBayar('ERROR', 'Pembayaran gagal');
```

**Contoh 2: rate limiter sederhana**

```js
function buatRateLimiter(maksPermintaan, jendelaMs) {
  const catatan = new Map(); // kunci -> daftar waktu permintaan

  return function izinkan(kunci) {
    const sekarang = Date.now();
    const batasAwal = sekarang - jendelaMs;
    const riwayat = (catatan.get(kunci) ?? []).filter((t) => t > batasAwal);

    if (riwayat.length >= maksPermintaan) {
      catatan.set(kunci, riwayat);
      return false; // ditolak
    }
    riwayat.push(sekarang);
    catatan.set(kunci, riwayat);
    return true; // diizinkan
  };
}

const izinkan = buatRateLimiter(3, 1000);
console.log(izinkan('ip-1')); // => true
console.log(izinkan('ip-1')); // => true
console.log(izinkan('ip-1')); // => true
console.log(izinkan('ip-1')); // => false (lebih dari 3 dalam 1 detik)
```

### 3.5 Jebakan klasik: closure di dalam perulangan

```js
// Dengan var: semua callback berbagi satu variabel i
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log('var:', i), 0);
}
// => var: 3, var: 3, var: 3

// Dengan let: setiap iterasi punya variabel i sendiri
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log('let:', j), 0);
}
// => let: 0, let: 1, let: 2
```

> **Kesalahan umum** Closure menahan variabel tetap hidup di memori. Jika sebuah closure besar disimpan di tempat yang hidup lama (misalnya cache global), data yang ia tangkap tidak akan dibersihkan _garbage collector_. Ini penyebab umum kebocoran memori, dibahas di Bab 15.

## Bab 4. `this`, Prototype, dan Class

### 4.1 Memahami `this`

`this` adalah referensi ke "siapa yang memanggil fungsi ini". Nilainya **ditentukan saat fungsi dipanggil**, bukan saat fungsi ditulis (kecuali arrow function).

Aturan penentuan `this` secara berurutan:

1. **`new Fungsi()`**: `this` adalah object baru.
2. **`call`, `apply`, `bind`**: `this` ditentukan secara eksplisit.
3. **`objek.method()`**: `this` adalah `objek`.
4. **Panggilan biasa `fungsi()`**: `this` adalah `undefined` (dalam strict mode, termasuk semua ES Module).

```js
const kucing = {
  nama: 'Mimi',
  bicara() {
    return `${this.nama} berkata meong`;
  },
};

console.log(kucing.bicara()); // => 'Mimi berkata meong'

const lepas = kucing.bicara;  // method "dilepas" dari object
// console.log(lepas());      // TypeError: this adalah undefined

const terikat = kucing.bicara.bind(kucing); // diikat permanen ke kucing
console.log(terikat());       // => 'Mimi berkata meong'
```

**Arrow function** tidak punya `this` sendiri. Ia memakai `this` dari scope tempat ia ditulis:

```js
class Timer {
  detik = 0;

  mulai() {
    // Arrow function: this tetap menunjuk instance Timer
    setInterval(() => {
      this.detik += 1;
    }, 1000).unref();
  }
}
```

Aturan praktis: gunakan arrow function untuk callback, dan method biasa untuk method class atau object.

### 4.2 Prototype dan rantai prototype

Setiap object JavaScript memiliki tautan tersembunyi ke object lain yang disebut **prototype**. Ketika Anda mengakses properti yang tidak ada di sebuah object, JavaScript mencarinya ke prototype, lalu prototype dari prototype, dan seterusnya hingga `null`. Ini disebut **rantai prototype** (_prototype chain_).

```js
const hewan = {
  bernapas() { return `${this.nama} bernapas`; },
};

const kucing = Object.create(hewan); // kucing mewarisi dari hewan
kucing.nama = 'Mimi';

console.log(kucing.bernapas());                      // => 'Mimi bernapas'
console.log(Object.getPrototypeOf(kucing) === hewan); // => true
console.log(Object.hasOwn(kucing, 'nama'));          // => true  (milik sendiri)
console.log(Object.hasOwn(kucing, 'bernapas'));      // => false (diwarisi)
```

Mengapa penting untuk backend? Karena memahami prototype menjelaskan **prototype pollution**, kerentanan keamanan yang dibahas di Bab 18.

### 4.3 Class

Sintaks `class` adalah **pembungkus yang lebih rapi** untuk mekanisme prototype. Di balik layar tetap prototype.

```js
class Hewan {
  constructor(nama) {
    this.nama = nama;
  }

  bicara() {
    return `${this.nama} bersuara`;
  }
}

class Kucing extends Hewan {
  bicara() {
    return `${super.bicara()}: meong`;
  }
}

const mimi = new Kucing('Mimi');
console.log(mimi.bicara());           // => 'Mimi bersuara: meong'
console.log(mimi instanceof Hewan);   // => true
```

### 4.4 Fitur class modern

**Private field** dengan awalan `#` benar-benar tidak bisa diakses dari luar class:

```js
class RekeningBank {
  #saldo = 0;                 // private field
  static #jumlahRekening = 0; // private static

  constructor(pemilik) {
    this.pemilik = pemilik;
    RekeningBank.#jumlahRekening += 1;
  }

  setor(jumlah) {
    if (jumlah <= 0) throw new RangeError('Jumlah harus positif');
    this.#saldo += jumlah;
    return this;              // memungkinkan method chaining
  }

  get saldo() {               // getter: dibaca seperti properti
    return this.#saldo;
  }

  #catat(pesan) {             // private method
    console.log(`[${this.pemilik}] ${pesan}`);
  }

  tarik(jumlah) {
    if (jumlah > this.#saldo) throw new Error('Saldo tidak cukup');
    this.#saldo -= jumlah;
    this.#catat(`tarik ${jumlah}`);
    return this;
  }

  static get total() {
    return RekeningBank.#jumlahRekening;
  }
}

const rek = new RekeningBank('Sari');
rek.setor(1000).tarik(300);
console.log(rek.saldo);          // => 700
console.log(RekeningBank.total); // => 1
// console.log(rek.#saldo);      // SyntaxError: field privat
```

**Static initialization block** untuk inisialisasi rumit pada level class:

```js
class Konfigurasi {
  static nilai;
  static {
    Konfigurasi.nilai = { dimuat: new Date().toISOString() };
  }
}
```

### 4.5 Komposisi lebih baik daripada pewarisan

Pewarisan yang dalam (misalnya `A extends B extends C extends D`) cepat menjadi sulit dipahami. Prinsip umum di backend adalah **komposisi**: menyusun object dari bagian-bagian kecil, bukan mewarisi dari class besar.

```js
class UserService {
  constructor({ repository, logger, mailer }) {
    this.repository = repository; // dependensi disuntikkan dari luar
    this.logger = logger;
    this.mailer = mailer;
  }

  async daftar(data) {
    const user = await this.repository.simpan(data);
    this.logger.info(`User ${user.id} dibuat`);
    await this.mailer.kirimSelamatDatang(user);
    return user;
  }
}
```

Dengan pola ini, `UserService` mudah diuji karena `repository`, `logger`, dan `mailer` bisa diganti tiruan (_mock_). Pola ini dibahas lebih lanjut di Bab 17.

### 4.6 Jebakan umum pada class

- Lupa memanggil `super(...)` di constructor class turunan sebelum memakai `this`.
- Memakai method class sebagai callback tanpa `bind`, sehingga `this` hilang:

```js
class Penghitung {
  jumlah = 0;
  tambah() { this.jumlah += 1; }
}

const p = new Penghitung();
const f = p.tambah;
// f(); // TypeError: this adalah undefined

// Solusi 1: bind
const g = p.tambah.bind(p);
g();

// Solusi 2: bungkus dengan arrow function
const h = () => p.tambah();
h();
```

> **Intinya** `this` ditentukan saat pemanggilan. Class adalah sintaks rapi di atas prototype. Utamakan komposisi dan injeksi dependensi untuk kode backend yang mudah diuji.

## Bab 5. Fungsi Tingkat Lanjut dan Pemrograman Fungsional

### 5.1 Fungsi adalah nilai

Di JavaScript, fungsi adalah **warga kelas satu** (_first-class citizen_). Artinya fungsi bisa disimpan di variabel, dikirim sebagai argumen, dan dikembalikan dari fungsi lain.

```js
const kali2 = (x) => x * 2;

function terapkan(fungsi, nilai) {
  return fungsi(nilai);
}

console.log(terapkan(kali2, 5)); // => 10
```

Fungsi yang menerima atau mengembalikan fungsi lain disebut **higher-order function** (HOF). Contoh bawaan: `map`, `filter`, `reduce`.

```js
const pesanan = [
  { id: 1, total: 50000, status: 'lunas' },
  { id: 2, total: 120000, status: 'menunggu' },
  { id: 3, total: 80000, status: 'lunas' },
];

const totalLunas = pesanan
  .filter((p) => p.status === 'lunas')
  .map((p) => p.total)
  .reduce((jumlah, nilai) => jumlah + nilai, 0);

console.log(totalLunas); // => 130000
```

### 5.2 Fungsi murni dan efek samping

**Fungsi murni** (_pure function_) selalu menghasilkan keluaran yang sama untuk masukan yang sama, dan tidak mengubah apa pun di luar dirinya (tidak ada _efek samping_).

```js
// Murni
const tambahPajak = (harga, persen) => harga * (1 + persen / 100);

// Tidak murni: bergantung pada dan mengubah state luar
let totalGlobal = 0;
function tambahKeTotal(x) {
  totalGlobal += x;
}
```

Backend tentu butuh efek samping (menulis ke database, mengirim email). Strateginya: **pisahkan logika murni dari kode yang punya efek samping**. Logika murni mudah diuji, sedangkan efek samping dipusatkan di satu lapisan.

### 5.3 Parameter default, rest, dan spread

```js
// Parameter default
function sapa(nama = 'Tamu', salam = 'Halo') {
  return `${salam}, ${nama}`;
}

// Rest: mengumpulkan sisa argumen menjadi array
function jumlahkan(...angka) {
  return angka.reduce((a, b) => a + b, 0);
}
console.log(jumlahkan(1, 2, 3, 4)); // => 10

// Spread: menyebar isi array atau object
const a = [1, 2];
const b = [...a, 3, 4];             // => [1, 2, 3, 4]
const opsi = { ...{ port: 3000 }, port: 8080 }; // => { port: 8080 }
```

Pola yang sangat umum di backend adalah **menerima satu object opsi** dengan destructuring dan nilai default:

```js
function buatServer({ port = 3000, host = '0.0.0.0', log = true } = {}) {
  return { port, host, log };
}

console.log(buatServer());                 // => { port: 3000, host: '0.0.0.0', log: true }
console.log(buatServer({ port: 8080 }));   // => { port: 8080, host: '0.0.0.0', log: true }
```

Tanda `= {}` di akhir membuat fungsi tetap aman dipanggil tanpa argumen.

### 5.4 Currying dan partial application

**Currying** mengubah fungsi berargumen banyak menjadi rangkaian fungsi berargumen satu.

```js
const tambah = (a) => (b) => a + b;
const tambah10 = tambah(10);
console.log(tambah10(5)); // => 15
```

Contoh lebih berguna: membuat validator yang bisa dipakai ulang.

```js
const minPanjang = (n) => (teks) => teks.length >= n;
const wajibDiisi = (teks) => teks.trim() !== '';

const validasiPassword = (teks) => minPanjang(8)(teks) && wajibDiisi(teks);
console.log(validasiPassword('rahasia123')); // => true
```

### 5.5 Komposisi fungsi: `pipe` dan `compose`

Menyambung beberapa fungsi kecil menjadi satu alur:

```js
const pipe = (...fungsi) => (nilaiAwal) =>
  fungsi.reduce((hasil, fn) => fn(hasil), nilaiAwal);

const bersihkan = (s) => s.trim();
const hurufKecil = (s) => s.toLowerCase();
const gantiSpasi = (s) => s.replaceAll(' ', '-');

const buatSlug = pipe(bersihkan, hurufKecil, gantiSpasi);
console.log(buatSlug('  Belajar JavaScript Lanjutan ')); // => 'belajar-javascript-lanjutan'
```

Konsep yang sama menjadi fondasi **middleware** pada framework backend, dibahas di Bab 17.

### 5.6 Memoization

**Memoization** menyimpan hasil pemanggilan fungsi supaya perhitungan yang sama tidak diulang.

```js
function memoize(fn) {
  const cache = new Map();
  return function (...args) {
    const kunci = JSON.stringify(args);
    if (cache.has(kunci)) return cache.get(kunci);
    const hasil = fn.apply(this, args);
    cache.set(kunci, hasil);
    return hasil;
  };
}

const lambat = (n) => {
  let total = 0;
  for (let i = 0; i < 1e7; i++) total += i % n;
  return total;
};

const cepat = memoize(lambat);
console.time('pertama');
cepat(7);
console.timeEnd('pertama'); // lambat
console.time('kedua');
cepat(7);
console.timeEnd('kedua');   // hampir instan
```

> **Kesalahan umum** Cache tanpa batas akan tumbuh terus dan menghabiskan memori. Di produksi, selalu beri batas ukuran atau masa kedaluwarsa (lihat contoh LRU cache di Bab 15).

### 5.7 Method array modern yang wajib dikuasai

```js
const produk = [
  { nama: 'Pensil', kategori: 'alat tulis', harga: 3000 },
  { nama: 'Buku', kategori: 'alat tulis', harga: 15000 },
  { nama: 'Teh', kategori: 'minuman', harga: 5000 },
];

// Mengelompokkan (ES2024)
const perKategori = Object.groupBy(produk, (p) => p.kategori);
// => { 'alat tulis': [...2 item], minuman: [...1 item] }

// Mencari dari belakang (ES2023)
const terakhirMurah = produk.findLast((p) => p.harga < 10000);

// Mengambil elemen dengan indeks negatif
const terakhir = produk.at(-1);

// flatMap: map lalu ratakan satu level
const kata = ['halo dunia', 'js lanjut'].flatMap((s) => s.split(' '));
// => ['halo', 'dunia', 'js', 'lanjut']

// Object.entries dan fromEntries: mengubah bentuk object
const harga = { a: 100, b: 200 };
const diskon = Object.fromEntries(
  Object.entries(harga).map(([k, v]) => [k, v * 0.9])
);
// => { a: 90, b: 180 }
```

## Bab 6. Iterator, Generator, dan Iterator Helpers

### 6.1 Iterable dan iterator

Apa pun yang bisa dipakai di `for...of` disebut **iterable**: array, string, Map, Set, dan lainnya. Sebuah iterable punya method `[Symbol.iterator]()` yang mengembalikan **iterator**, yaitu object dengan method `next()` yang mengembalikan `{ value, done }`.

```js
const iter = [10, 20][Symbol.iterator]();
console.log(iter.next()); // => { value: 10, done: false }
console.log(iter.next()); // => { value: 20, done: false }
console.log(iter.next()); // => { value: undefined, done: true }
```

Anda bisa membuat iterable sendiri:

```js
class Rentang {
  constructor(awal, akhir) {
    this.awal = awal;
    this.akhir = akhir;
  }

  [Symbol.iterator]() {
    let sekarang = this.awal;
    const akhir = this.akhir;
    return {
      next: () =>
        sekarang <= akhir
          ? { value: sekarang++, done: false }
          : { value: undefined, done: true },
    };
  }
}

console.log([...new Rentang(1, 5)]); // => [1, 2, 3, 4, 5]
```

### 6.2 Generator

**Generator** adalah fungsi yang bisa "berhenti sementara" dan dilanjutkan kembali. Ditandai dengan `function*` dan `yield`. Generator menulis iterator dengan jauh lebih ringkas:

```js
function* rentang(awal, akhir) {
  for (let i = awal; i <= akhir; i++) {
    yield i;      // berhenti di sini, kirim nilai, lanjut saat diminta lagi
  }
}

console.log([...rentang(1, 5)]); // => [1, 2, 3, 4, 5]
```

Kekuatan utama generator adalah **evaluasi malas** (_lazy evaluation_): nilai hanya dihitung saat diminta. Ini memungkinkan urutan tak hingga tanpa menghabiskan memori:

```js
function* bilanganAsli() {
  let n = 1;
  while (true) yield n++;
}
```

### 6.3 Iterator helpers

Sejak ES2025, iterator (termasuk yang dihasilkan generator) punya method seperti array: `map`, `filter`, `take`, `drop`, `flatMap`, `reduce`, `toArray`, `forEach`, `some`, `every`, `find`. Semuanya bekerja **malas**, satu elemen per satu.

```js
const hasil = bilanganAsli()
  .filter((n) => n % 2 === 0) // hanya genap
  .map((n) => n * n)          // kuadratkan
  .take(5)                    // ambil 5 pertama
  .toArray();

console.log(hasil); // => [4, 16, 36, 64, 100]
```

Tanpa iterator helpers, Anda tidak bisa memakai `.filter` pada generator tak hingga, dan jika mengubahnya ke array dulu, program akan macet selamanya. Method ini tersedia di Node.js 22 ke atas.

Gunakan `Iterator.from()` untuk membungkus iterable apa pun:

```js
const set = new Set([1, 2, 3, 4]);
console.log(Iterator.from(set).map((x) => x * 10).toArray()); // => [10, 20, 30, 40]
```

### 6.4 Kasus pakai di backend

**Memproses data besar tanpa memuat semuanya.** Misalnya membaca ribuan baris dari database secara bertahap:

```js
function* ambilHalaman(totalData, ukuranHalaman) {
  for (let mulai = 0; mulai < totalData; mulai += ukuranHalaman) {
    console.log(`memuat halaman mulai ${mulai}`);
    yield Array.from(
      { length: Math.min(ukuranHalaman, totalData - mulai) },
      (_, i) => ({ id: mulai + i + 1 })
    );
  }
}

const hasilAkhir = ambilHalaman(1000, 100)
  .flatMap((halaman) => halaman)
  .filter((row) => row.id % 250 === 0)
  .take(2)
  .toArray();

console.log(hasilAkhir); // => [{ id: 250 }, { id: 500 }]
// Hanya 5 halaman yang dimuat, bukan 10
```

Karena `take(2)` berhenti setelah dua hasil, halaman sisanya tidak pernah dimuat. Versi asinkron dari pola ini (async generator) dibahas di Bab 7.

## Bab 7. Pemrograman Asinkron

Bab ini adalah salah satu yang terpenting untuk backend. Hampir semua pekerjaan server (membaca database, memanggil API lain, membaca file) bersifat asinkron.

### 7.1 Mengapa asinkron

JavaScript berjalan pada **satu thread utama**. Artinya hanya satu bagian kode yang dieksekusi pada satu waktu. Jika Anda menunggu database selama 100 ms secara _blocking_, seluruh server tidak bisa melayani siapa pun selama 100 ms itu.

Solusinya adalah **non-blocking I/O**: Anda meminta pekerjaan dilakukan, lalu melanjutkan hal lain, dan diberi tahu saat hasilnya siap.

Analogi: kasir restoran yang menerima pesanan lalu langsung melayani pelanggan berikutnya, sementara dapur memasak. Kasir tidak berdiri menunggu satu pesanan matang.

### 7.2 Call stack, task queue, dan microtask queue

Model mental yang perlu dihafal:

|Komponen|Fungsi|
|---|---|
|**Call stack**|Tumpukan fungsi yang sedang dieksekusi|
|**Task queue** (macrotask)|Antrian callback seperti `setTimeout`, I/O selesai|
|**Microtask queue**|Antrian prioritas tinggi: callback `.then`, `await`, `queueMicrotask`|
|**Event loop**|Pengawas yang memindahkan tugas dari antrian ke stack saat stack kosong|

Aturan emas: setelah stack kosong, event loop **mengosongkan seluruh microtask terlebih dulu**, baru mengambil satu macrotask berikutnya.

```js
console.log('1: sinkron');

setTimeout(() => console.log('2: setTimeout (macrotask)'), 0);

Promise.resolve().then(() => console.log('3: promise (microtask)'));

queueMicrotask(() => console.log('4: queueMicrotask (microtask)'));

console.log('5: sinkron');

// Urutan keluaran:
// 1: sinkron
// 5: sinkron
// 3: promise (microtask)
// 4: queueMicrotask (microtask)
// 2: setTimeout (macrotask)
```

Pahami urutan ini sampai Anda bisa menebaknya tanpa menjalankan kode.

### 7.3 Dari callback ke Promise

Gaya lama memakai **callback**:

```js
import { readFile } from 'node:fs';

readFile('a.txt', 'utf8', (err, isi) => {
  if (err) return console.error(err);
  console.log(isi);
});
```

Jika beberapa operasi bergantung satu sama lain, kode menjadi menjorok dalam ("callback hell"). **Promise** menyelesaikan ini.

**Promise** adalah object yang mewakili hasil operasi yang belum selesai. Ia punya tiga keadaan:

- _pending_: belum selesai
- _fulfilled_: berhasil, punya nilai
- _rejected_: gagal, punya alasan (error)

```js
const janji = new Promise((resolve, reject) => {
  setTimeout(() => resolve('selesai'), 500);
});

janji
  .then((nilai) => console.log(nilai)) // => 'selesai'
  .catch((err) => console.error(err))
  .finally(() => console.log('dibersihkan'));
```

### 7.4 async dan await

`async/await` adalah sintaks yang membuat kode asinkron terbaca seperti kode sinkron. Ini yang akan Anda pakai 95 persen waktu.

```js
import { readFile } from 'node:fs/promises';

async function bacaKonfigurasi(path) {
  try {
    const teks = await readFile(path, 'utf8'); // menunggu tanpa memblokir thread
    return JSON.parse(teks);
  } catch (err) {
    throw new Error(`Gagal membaca konfigurasi ${path}`, { cause: err });
  }
}
```

Fakta penting:

- Fungsi `async` **selalu mengembalikan Promise**.
- `await` hanya menjeda fungsi tempat ia berada, bukan seluruh program.
- Di ES Module, Anda bisa memakai `await` di level paling atas (_top-level await_).

### 7.5 Serial versus paralel

Ini sumber masalah performa nomor satu.

```js
import { setTimeout as tidur } from 'node:timers/promises';

const ambilUser = async (id) => { await tidur(100); return { id }; };

// Serial: total sekitar 300 ms
async function serial() {
  const a = await ambilUser(1);
  const b = await ambilUser(2);
  const c = await ambilUser(3);
  return [a, b, c];
}

// Paralel: total sekitar 100 ms
async function paralel() {
  return Promise.all([ambilUser(1), ambilUser(2), ambilUser(3)]);
}
```

Gunakan paralel jika operasi **tidak saling bergantung**. Gunakan serial jika operasi berikutnya butuh hasil operasi sebelumnya.

### 7.6 Kombinator Promise

|Method|Perilaku|
|---|---|
|`Promise.all([...])`|Menunggu **semua** berhasil. Jika satu gagal, langsung gagal.|
|`Promise.allSettled([...])`|Menunggu semua selesai, berhasil atau gagal. Tidak pernah reject.|
|`Promise.race([...])`|Hasil dari yang **pertama selesai** (berhasil atau gagal).|
|`Promise.any([...])`|Hasil dari yang **pertama berhasil**. Gagal hanya jika semua gagal.|

```js
const hasil = await Promise.allSettled([
  fetch('https://contoh.com/a'),
  fetch('https://contoh.com/b'),
]);

for (const item of hasil) {
  if (item.status === 'fulfilled') console.log('berhasil', item.value.status);
  else console.log('gagal', item.reason.message);
}
```

Tambahan modern:

```js
// Promise.withResolvers (ES2024): mengambil resolve dan reject ke luar
const { promise, resolve, reject } = Promise.withResolvers();
setTimeout(() => resolve('siap'), 100);
console.log(await promise); // => 'siap'

// Promise.try (ES2025, perlu Node.js 24 ke atas): menangani fungsi yang bisa sinkron atau asinkron secara seragam
const hasilTry = await Promise.try(() => JSON.parse('{ rusak'))
  .catch((err) => `ditangkap: ${err.name}`);
console.log(hasilTry); // => 'ditangkap: SyntaxError'
```

### 7.7 Kesalahan umum pada async

**1. `forEach` tidak menunggu `await`.**

```js
// SALAH: forEach tidak peduli pada Promise yang dikembalikan callback
items.forEach(async (item) => {
  await simpan(item);
});
console.log('selesai'); // tercetak SEBELUM semua simpan selesai

// BENAR (serial)
for (const item of items) {
  await simpan(item);
}

// BENAR (paralel)
await Promise.all(items.map((item) => simpan(item)));
```

**2. Lupa `await`.** Fungsi tetap berjalan, tetapi Anda mendapat Promise, bukan hasilnya, dan error-nya menjadi _unhandled rejection_.

**3. `return` tanpa `await` di dalam `try`.** Error dari Promise yang dikembalikan tidak ditangkap oleh `catch` di fungsi yang sama:

```js
async function salah() {
  try {
    return operasiYangMungkinGagal();       // catch TIDAK menangkap
  } catch (e) { /* tidak pernah dipanggil untuk Promise yang gagal */ }
}

async function benar() {
  try {
    return await operasiYangMungkinGagal(); // catch menangkap
  } catch (e) { /* ditangani di sini */ }
}
```

**4. Promise `Promise.all` dengan ribuan item sekaligus.** Menembak 10.000 permintaan HTTP bersamaan bisa membanjiri server tujuan atau menghabiskan koneksi. Gunakan pembatas konkurensi (7.9).

### 7.8 Pembatalan dan batas waktu dengan AbortController

Operasi asinkron yang menggantung tanpa batas waktu adalah sumber masalah produksi. Gunakan `AbortSignal`:

```js
async function ambilDenganTimeout(url, ms = 3000) {
  const respons = await fetch(url, { signal: AbortSignal.timeout(ms) });
  if (!respons.ok) throw new Error(`HTTP ${respons.status}`);
  return respons.json();
}

try {
  const data = await ambilDenganTimeout('https://contoh.com/api', 2000);
} catch (err) {
  if (err.name === 'TimeoutError') console.error('Permintaan melewati batas waktu');
  else throw err;
}
```

Pembatalan manual:

```js
const pengendali = new AbortController();
setTimeout(() => pengendali.abort(), 1000);

try {
  await fetch('https://contoh.com/lambat', { signal: pengendali.signal });
} catch (err) {
  if (err.name === 'AbortError') console.log('dibatalkan');
}
```

Aturan praktis backend: **setiap panggilan ke layanan eksternal harus punya timeout.**

### 7.9 Pembatas konkurensi

Menjalankan banyak tugas dengan batas jumlah yang berjalan bersamaan:

```js
export async function mapLimit(daftar, batas, kerja) {
  const hasil = new Array(daftar.length);
  let berikutnya = 0;

  async function pekerja() {
    while (true) {
      const i = berikutnya++;
      if (i >= daftar.length) return;
      hasil[i] = await kerja(daftar[i], i);
    }
  }

  const jumlahPekerja = Math.min(batas, daftar.length);
  await Promise.all(Array.from({ length: jumlahPekerja }, () => pekerja()));
  return hasil;
}

// Pemakaian: unduh 100 URL, maksimal 5 sekaligus
// const halaman = await mapLimit(urls, 5, (url) => fetch(url).then((r) => r.text()));
```

Cara kerjanya: kita membuat `batas` buah "pekerja". Masing-masing mengambil item berikutnya dari daftar bersama sampai habis. Karena JavaScript satu thread, `berikutnya++` aman dari _race condition_.

### 7.10 Retry dengan exponential backoff

Panggilan jaringan bisa gagal sementara. Mencoba ulang dengan jeda yang makin lama (dan sedikit acak) adalah praktik standar:

```js
import { setTimeout as tidur } from 'node:timers/promises';

export async function coba(fn, { percobaan = 3, dasarMs = 200, signal } = {}) {
  let ke = 0;
  while (true) {
    try {
      return await fn({ ke, signal });
    } catch (err) {
      if (ke >= percobaan || signal?.aborted) throw err;
      const jeda = dasarMs * 2 ** ke;            // 200, 400, 800, ...
      const acak = Math.random() * jeda * 0.5;   // jitter, mencegah serentak
      await tidur(jeda + acak, undefined, { signal });
      ke += 1;
    }
  }
}
```

Catatan: hanya coba ulang error yang _sementara_ (timeout, 503). Jangan coba ulang error permanen (400, 404), dan pastikan operasi bersifat **idempoten** (aman diulang) sebelum di-retry.

### 7.11 Async iterator dan `for await`

Untuk data yang datang bertahap secara asinkron, gunakan **async generator** (`async function*`) dan konsumsi dengan `for await`:

```js
import { setTimeout as tidur } from 'node:timers/promises';

async function* ambilHalaman(maks) {
  for (let halaman = 1; halaman <= maks; halaman++) {
    await tidur(50); // pura-pura memanggil API
    yield { halaman, data: [`item-${halaman}-a`, `item-${halaman}-b`] };
  }
}

for await (const { halaman, data } of ambilHalaman(3)) {
  console.log(`halaman ${halaman}:`, data);
}

// Mengumpulkan semuanya menjadi array (ES2026)
const semua = await Array.fromAsync(ambilHalaman(3));
```

Stream di Node.js juga merupakan async iterable, sehingga bisa dibaca dengan `for await` (Bab 13).

2. Ubah fungsi `ambilUser` di atas agar kadang gagal, lalu bungkus dengan `coba(...)`.

## Bab 8. Event Loop Node.js dan Cara Menghindari Blocking

### 8.1 Arsitektur singkat Node.js

Node.js terdiri atas tiga komponen utama:

- **V8**: mesin yang mengeksekusi JavaScript Anda.
- **libuv**: pustaka C yang menangani event loop, I/O jaringan, dan **thread pool**.
- **API Node.js**: modul seperti `fs`, `http`, `crypto`.

Kode JavaScript Anda berjalan di satu thread, tetapi operasi I/O dikerjakan oleh sistem operasi atau thread pool libuv di belakang layar. Ketika selesai, hasilnya dikembalikan ke event loop.

### 8.2 Fase-fase event loop

Event loop Node.js berputar melalui fase-fase berikut secara berurutan:

|Urutan|Fase|Yang dijalankan|
|---|---|---|
|1|**timers**|Callback `setTimeout` dan `setInterval` yang waktunya sudah tiba|
|2|**pending callbacks**|Callback I/O tertentu yang ditunda|
|3|**idle, prepare**|Internal|
|4|**poll**|Mengambil kejadian I/O baru dan menjalankan callback I/O|
|5|**check**|Callback `setImmediate`|
|6|**close callbacks**|Misalnya `socket.on('close')`|

Di antara setiap callback, Node.js mengosongkan antrian `process.nextTick`, lalu antrian microtask Promise.

### 8.3 `nextTick`, microtask, `setImmediate`

```js
import { readFile } from 'node:fs';

readFile(import.meta.filename, () => {
  // Di dalam callback I/O, setImmediate SELALU lebih dulu dari setTimeout 0
  setTimeout(() => console.log('setTimeout'), 0);
  setImmediate(() => console.log('setImmediate'));
});
// => setImmediate, lalu setTimeout
```

Di luar callback I/O, urutan `setTimeout(0)` dan `setImmediate` tidak dijamin.

Prioritas umum: `process.nextTick` lebih dulu dari microtask Promise pada konteks CommonJS atau di dalam callback. Pada top-level ES Module, urutannya bisa terbalik karena modul itu sendiri dieksekusi di dalam microtask. Pelajaran praktisnya: **jangan menggantungkan logika pada urutan nextTick versus Promise**. Untuk menunda pekerjaan, pilih `queueMicrotask` (sangat singkat) atau `setImmediate` (memberi kesempatan I/O berjalan).

### 8.4 Thread pool libuv

Beberapa operasi tidak punya dukungan asinkron langsung dari OS, sehingga dijalankan di **thread pool** yang secara bawaan berisi **4 thread**:

- operasi file system (`fs`)
- `dns.lookup`
- sebagian fungsi `crypto` (misalnya `pbkdf2`, `scrypt`, `randomBytes`)
- kompresi `zlib`

Jika Anda menjalankan lebih dari 4 operasi berat ini bersamaan, sisanya antre. Ukuran pool dapat diubah dengan variabel lingkungan `UV_THREADPOOL_SIZE` (misalnya `UV_THREADPOOL_SIZE=8`), tetapi tidak ada gunanya melebihi jumlah core CPU secara signifikan.

### 8.5 Musuh utama: blocking event loop

Selama kode sinkron yang lama berjalan, **tidak ada permintaan lain yang bisa dilayani**.

```js
import { createServer } from 'node:http';

createServer((req, res) => {
  if (req.url === '/berat') {
    // BURUK: memblokir event loop selama beberapa detik
    let total = 0;
    for (let i = 0; i < 5e9; i++) total += i;
    res.end(String(total));
    return;
  }
  res.end('ringan');
}).listen(3000);
```

Saat seseorang membuka `/berat`, permintaan ke `/` ikut macet. Penyebab blocking yang sering ditemui:

- loop dan perhitungan CPU berat (hashing sinkron, kompresi, pemrosesan gambar);
- `JSON.parse` atau `JSON.stringify` pada data raksasa;
- API sinkron seperti `fs.readFileSync` di dalam handler permintaan;
- regex yang rumit (ReDoS, Bab 18);
- query atau pemrosesan yang mengembalikan jutaan baris sekaligus.

### 8.6 Mengukur kesehatan event loop

```js
import { monitorEventLoopDelay } from 'node:perf_hooks';

const histogram = monitorEventLoopDelay({ resolution: 20 });
histogram.enable();

setInterval(() => {
  const p99 = histogram.percentile(99) / 1e6; // nanodetik -> milidetik
  console.log(`event loop delay p99: ${p99.toFixed(1)} ms`);
  histogram.reset();
}, 5000).unref();
```

Nilai delay yang tinggi menandakan ada sesuatu yang memblokir. Pantau metrik ini di produksi.

### 8.7 Strategi mengatasi pekerjaan berat

1. **Pindahkan ke worker thread** untuk pekerjaan CPU murni (Bab 14).
2. **Pecah pekerjaan menjadi potongan kecil** dan beri jeda dengan `setImmediate`:

```js
async function prosesBesar(daftar, proses) {
  const ukuranPotongan = 1000;
  for (let i = 0; i < daftar.length; i += ukuranPotongan) {
    for (const item of daftar.slice(i, i + ukuranPotongan)) proses(item);
    // beri kesempatan event loop melayani permintaan lain
    await new Promise((selesai) => setImmediate(selesai));
  }
}
```

3. **Gunakan versi asinkron** dari API: `fs.promises.readFile`, bukan `readFileSync`.
4. **Gunakan stream** untuk data besar, bukan memuat semuanya ke memori (Bab 13).
5. **Pindahkan ke layanan terpisah** atau antrian kerja (_job queue_) untuk tugas yang sangat berat atau lama.

Kapan `Sync` boleh dipakai? Saat **startup** aplikasi (membaca konfigurasi sekali) atau pada skrip CLI sederhana. Jangan di jalur permintaan.

### Latihan Bab 8

1. Jalankan server contoh di atas, buka `/berat` di satu tab dan `/` di tab lain, amati dampaknya. Lalu perbaiki dengan worker thread setelah membaca Bab 14.
2. Pasang `monitorEventLoopDelay` dan buktikan nilainya naik saat ada loop berat.
3. Tulis eksperimen: jalankan 8 pemanggilan `crypto.pbkdf2` bersamaan, ukur waktunya dengan `UV_THREADPOOL_SIZE=4` dan `UV_THREADPOOL_SIZE=8`.

## Bab 9. Sistem Modul: ESM dan CommonJS

### 9.1 Mengapa ada modul

**Modul** adalah file yang punya scope sendiri dan secara eksplisit menyatakan apa yang dibagikan ke file lain. Modul membuat kode terorganisir, tidak saling menimpa variabel, dan mudah diuji.

Node.js mengenal dua sistem modul:

|Aspek|CommonJS (CJS)|ES Module (ESM)|
|---|---|---|
|Sintaks|`require()` dan `module.exports`|`import` dan `export`|
|Dimuat|Sinkron|Asinkron|
|Standar|Khas Node.js|Standar resmi ECMAScript|
|Top-level await|Tidak bisa|Bisa|
|Aktivasi|Bawaan untuk `.js`, atau ekstensi `.cjs`|`"type": "module"` di `package.json`, atau ekstensi `.mjs`|

Untuk proyek baru di 2026, **gunakan ESM**. CommonJS tetap perlu dipahami karena banyak kode lama dan library masih memakainya.

### 9.2 Sintaks ESM

**Ekspor bernama** (_named export_) dan **ekspor default**:

```js
// matematika.js
export const PI = 3.14159;

export function luasLingkaran(r) {
  return PI * r * r;
}

export default function kuadrat(x) {
  return x * x;
}
```

```js
// utama.js
import kuadrat, { PI, luasLingkaran } from './matematika.js';
import { luasLingkaran as luas } from './matematika.js'; // alias
import * as mat from './matematika.js';                  // semua sebagai namespace

console.log(kuadrat(4));        // => 16
console.log(mat.PI);            // => 3.14159
```

Aturan penting ESM di Node.js:

- **Ekstensi file wajib ditulis** pada import relatif: `'./matematika.js'`, bukan `'./matematika'`.
- Modul bawaan Node.js diimpor dengan awalan `node:`, misalnya `import { readFile } from 'node:fs/promises'`. Awalan ini menegaskan bahwa itu modul bawaan, bukan paket dari npm.
- Saran gaya: utamakan **ekspor bernama** daripada default. Nama yang konsisten memudahkan pencarian, refactor, dan _auto-complete_.

### 9.3 Variabel khusus modul

Di ESM tidak ada `__dirname` dan `__filename`. Gantinya:

```js
console.log(import.meta.url);      // URL file ini, misal file:///proyek/src/app.js
console.log(import.meta.filename); // path absolut file ini
console.log(import.meta.dirname);  // path absolut folder file ini

import { join } from 'node:path';
const lokasiData = join(import.meta.dirname, 'data', 'users.json');
```

### 9.4 Import dinamis dan top-level await

```js
// Import dinamis: dimuat saat dibutuhkan, mengembalikan Promise
async function muatPlugin(nama) {
  const modul = await import(`./plugin-${nama}.js`);
  return modul.default;
}

// Top-level await: boleh di level paling atas file ESM
import { readFile } from 'node:fs/promises';
const konfigurasi = JSON.parse(await readFile('./config.json', 'utf8'));
```

Gunakan top-level await dengan bijak. Modul yang melakukan `await` lama saat dimuat akan **menunda** semua modul yang mengimpornya.

### 9.5 Mengimpor JSON dengan import attributes

```js
import konfigurasi from './config.json' with { type: 'json' };
console.log(konfigurasi.port);
```

Bagian `with { type: 'json' }` wajib agar runtime tahu bahwa file itu dimaksudkan sebagai data, bukan kode.

### 9.6 Interoperabilitas ESM dan CommonJS

- **ESM mengimpor CJS**: bisa, dengan `import paket from 'paket-cjs'`.
- **CJS mengimpor ESM**: pada Node.js versi modern, `require()` sudah bisa memuat ESM sinkron selama modul tersebut tidak memakai top-level await. Pada versi lama, harus memakai `import()` dinamis.
- Anda bisa membuat `require` di ESM jika sangat terpaksa:

```js
import { createRequire } from 'node:module';
const require = createRequire(import.meta.url);
const paketLama = require('paket-cjs');
```

### 9.7 Mengatur paket dengan `exports` dan `imports`

Pada `package.json`, field `exports` menentukan **pintu masuk resmi** sebuah paket, sehingga pengguna tidak bisa mengimpor file internal sembarangan:

```json
{
  "name": "pustaka-saya",
  "type": "module",
  "exports": {
    ".": "./src/index.js",
    "./util": "./src/util.js"
  }
}
```

Field `imports` membuat **alias internal** yang rapi dan menghindari import relatif panjang seperti `../../../utils/log.js`. Alias wajib diawali `#`:

```json
{
  "imports": {
    "#lib/*": "./src/lib/*"
  }
}
```

```js
import { log } from '#lib/logger.js';
```

### 9.8 Siklus dependensi

Jika `a.js` mengimpor `b.js` dan `b.js` mengimpor `a.js` (_circular dependency_), Anda bisa mendapat nilai yang belum diinisialisasi. Cara mengatasi: ekstrak bagian bersama ke modul ketiga, atau susun ulang tanggung jawab antar modul agar arah dependensi satu arah.

### 9.9 Struktur proyek yang direkomendasikan

```text
proyek/
  package.json
  src/
    server.js          // titik masuk: menyalakan server
    app.js             // merakit aplikasi
    config.js          // membaca dan memvalidasi konfigurasi
    routes/            // definisi rute
    services/          // logika bisnis
    repositories/      // akses data
    lib/               // utilitas umum
  test/
```

1. Ubah proyek latihan Anda menjadi struktur di atas dengan alias `#lib/*`.
2. Buat modul `config.js` yang membaca `process.env` sekali dan mengekspor object konfigurasi beku (`Object.freeze`).
3. Cobalah memuat modul ESM dari file `.cjs` memakai `import()` dinamis.

## Bab 10. Penanganan Error yang Benar

### 10.1 Dua jenis error

Pembedaan paling penting dalam penanganan error backend:

|Jenis|Penyebab|Contoh|Tindakan|
|---|---|---|---|
|**Operational error**|Kondisi di luar kendali kode yang wajar terjadi|Database mati, timeout, input pengguna salah, file tidak ada|Tangani: kembalikan respons yang sesuai, coba ulang, catat log|
|**Programmer error**|Bug di kode|Memanggil method pada `undefined`, salah tipe argumen|Jangan ditutupi. Catat log lengkap, perbaiki kodenya|

Menangani operational error adalah tugas rutin. Programmer error sebaiknya memicu kegagalan yang terlihat agar bug ditemukan, bukan disembunyikan.

### 10.2 Dasar try, catch, finally

```js
try {
  const data = JSON.parse('{ rusak');
} catch (err) {
  console.error(err.name);    // => 'SyntaxError'
  console.error(err.message); // pesan penjelasan
} finally {
  console.log('selalu dijalankan, berhasil atau gagal');
}
```

Beberapa tipe error bawaan: `Error`, `TypeError`, `RangeError`, `SyntaxError`, `ReferenceError`.

JavaScript membolehkan `throw` apa saja (misalnya string atau angka), tetapi **selalu lempar object `Error`** agar Anda mendapat stack trace.

```js
// Buruk
throw 'sesuatu gagal';

// Baik
throw new Error('sesuatu gagal');
```

### 10.3 Error kustom

```js
export class AppError extends Error {
  constructor(message, { status = 500, code = 'INTERNAL_ERROR', cause, expose = status < 500 } = {}) {
    super(message, { cause });
    this.name = this.constructor.name;
    this.status = status;   // kode HTTP yang sesuai
    this.code = code;       // kode mesin yang stabil untuk klien
    this.expose = expose;   // aman ditampilkan ke klien atau tidak
  }
}

export class NotFoundError extends AppError {
  constructor(sumber = 'Sumber daya') {
    super(`${sumber} tidak ditemukan`, { status: 404, code: 'NOT_FOUND' });
  }
}

export class ValidationError extends AppError {
  constructor(message = 'Data tidak valid', opsi = {}) {
    super(message, { status: 400, code: 'VALIDATION_ERROR', ...opsi });
  }
}
```

Dengan kelas kustom, lapisan paling luar (handler HTTP) bisa menerjemahkan error ke respons yang tepat secara terpusat, tanpa `if` berulang di setiap rute.

### 10.4 Error cause: menyimpan konteks

Sejak ES2022, error bisa membawa **penyebab aslinya** lewat opsi `cause`:

```js
async function muatUser(id) {
  try {
    return await db.query('SELECT * FROM users WHERE id = $1', [id]);
  } catch (err) {
    throw new AppError('Gagal memuat user', { status: 503, code: 'DB_UNAVAILABLE', cause: err });
  }
}
```

Ini mempertahankan rantai penyebab: pesan ramah untuk lapisan atas, dan detail teknis asli tetap tersedia untuk log.

### 10.5 Aturan emas penanganan error

1. **Tangkap error hanya jika Anda bisa melakukan sesuatu yang berguna** (pulihkan, ubah ke error yang lebih bermakna, atau catat dan lempar lagi). `catch` kosong adalah musuh.
2. **Jangan menelan error.** Kode berikut berbahaya:

```js
try {
  await simpanPesanan(pesanan);
} catch (err) {
  // kosong: pesanan hilang tanpa jejak
}
```

3. **Jangan membocorkan detail internal ke klien.** Stack trace, query SQL, dan path file adalah informasi berharga bagi penyerang. Kirim pesan umum, catat detailnya di log.
4. **Tangani error di perbatasan sistem.** Biarkan error naik ke handler pusat, jangan menangani di setiap fungsi kecil.
5. **Selalu `await` atau `.catch` setiap Promise.**

### 10.6 Promise yang tidak tertangani dan error global

Promise yang ditolak tanpa penangan memicu kejadian `unhandledRejection`. Pada Node.js modern, perilaku bawaannya adalah **mematikan proses**, dan itu memang disengaja.

```js
process.on('unhandledRejection', (alasan) => {
  console.error('Promise tidak tertangani:', alasan);
  // Catat log, lalu matikan proses secara terkendali
  process.exitCode = 1;
  setImmediate(() => process.exit(1));
});

process.on('uncaughtException', (err) => {
  console.error('Exception tidak tertangani:', err);
  process.exit(1);
});
```

Setelah `uncaughtException`, aplikasi berada dalam **keadaan tidak pasti**. Cara yang benar adalah mencatat log lalu **keluar**, dan membiarkan pengelola proses (Docker, systemd, PM2, Kubernetes) menyalakannya kembali. Jangan mencoba "melanjutkan seperti biasa".

### 10.7 Mengumpulkan banyak error: AggregateError

`Promise.any` dan operasi paralel bisa menghasilkan banyak error sekaligus. `AggregateError` membungkusnya:

```js
try {
  await Promise.any([
    Promise.reject(new Error('server A mati')),
    Promise.reject(new Error('server B mati')),
  ]);
} catch (err) {
  console.log(err.constructor.name);         // => 'AggregateError'
  console.log(err.errors.map((e) => e.message)); // => ['server A mati', 'server B mati']
}
```

### 10.8 Memeriksa apakah suatu nilai adalah error

Pemeriksaan `instanceof Error` bisa keliru jika error berasal dari _realm_ lain (misalnya dari modul `vm`). Fitur baru `Error.isError()` (ES2026) mengatasinya. Karena baru, pastikan runtime Anda mendukungnya, atau gunakan `instanceof Error` sebagai cadangan:

```js
const adalahError = (nilai) =>
  typeof Error.isError === 'function' ? Error.isError(nilai) : nilai instanceof Error;
```

### 10.9 Penangan error terpusat

Pola yang akan Anda pakai di proyek akhir:

```js
function ubahKeRespons(err) {
  if (err instanceof AppError) {
    return {
      status: err.status,
      body: { error: { code: err.code, message: err.expose ? err.message : 'Terjadi kesalahan pada server' } },
    };
  }
  // Error tak dikenal: perlakukan sebagai bug
  return {
    status: 500,
    body: { error: { code: 'INTERNAL_ERROR', message: 'Terjadi kesalahan pada server' } },
  };
}
```

## Bab 11. Struktur Data Modern dan Metaprogramming

### 11.1 Map dan object biasa

`Map` adalah koleksi pasangan kunci-nilai yang lebih fleksibel dibanding object biasa:

|Aspek|Object|Map|
|---|---|---|
|Tipe kunci|String atau Symbol|**Apa saja** (object, fungsi, angka)|
|Urutan|Umumnya urutan penyisipan, ada aturan khusus untuk kunci angka|**Pasti** urutan penyisipan|
|Ukuran|Dihitung manual|`map.size`|
|Performa tambah dan hapus sering|Kurang optimal|Dioptimalkan|
|Risiko kunci bentrok dengan prototype|Ada|Tidak ada|

```js
const sesi = new Map();
sesi.set('token-abc', { userId: 1, kadaluarsa: Date.now() + 3600_000 });
console.log(sesi.get('token-abc'));
console.log(sesi.has('token-xyz')); // => false
sesi.delete('token-abc');

// Mengelompokkan dengan Map.groupBy (ES2024)
const pesanan = [
  { id: 1, status: 'lunas' },
  { id: 2, status: 'menunggu' },
  { id: 3, status: 'lunas' },
];
const kelompok = Map.groupBy(pesanan, (p) => p.status);
console.log(kelompok.get('lunas').length); // => 2
```

Gunakan `Map` untuk **kamus dinamis** (kunci tidak diketahui sebelumnya, misalnya cache atau penghitung per user). Gunakan object untuk **rekaman dengan bentuk tetap** (misalnya data user).

### 11.2 Set dan operasi himpunan

`Set` menyimpan nilai unik. Sejak ES2025 tersedia operasi himpunan bawaan (Node.js 22 ke atas):

```js
const peranA = new Set(['admin', 'editor']);
const peranB = new Set(['editor', 'viewer']);

console.log(peranA.union(peranB));               // admin, editor, viewer
console.log(peranA.intersection(peranB));        // editor
console.log(peranA.difference(peranB));          // admin
console.log(peranA.symmetricDifference(peranB)); // admin, viewer
console.log(peranA.isSubsetOf(new Set(['admin', 'editor', 'viewer']))); // => true

// Menghapus duplikat dari array
const unik = [...new Set([1, 2, 2, 3, 3, 3])]; // => [1, 2, 3]
```

### 11.3 WeakMap, WeakSet, dan WeakRef

`WeakMap` dan `WeakSet` menyimpan kunci object dengan **referensi lemah**: jika tidak ada lagi yang memegang object tersebut, ia boleh dibersihkan _garbage collector_ dan entrinya hilang otomatis.

```js
const metadata = new WeakMap();

function tandai(objek, info) {
  metadata.set(objek, info); // tidak mencegah objek dibersihkan
}
```

Kegunaan: menyimpan data tambahan milik object tanpa risiko kebocoran memori, atau menandai object yang sudah diproses. `WeakRef` dan `FinalizationRegistry` adalah alat lanjutan yang waktunya tidak terprediksi, jadi hindari kecuali benar-benar paham.

### 11.4 Symbol

`Symbol` membuat pengenal yang dijamin unik. Berguna untuk kunci properti yang tidak boleh bentrok, dan untuk "protokol" bahasa seperti `Symbol.iterator` dan `Symbol.asyncIterator`.

```js
const ID_INTERNAL = Symbol('idInternal');
const user = { nama: 'Sari', [ID_INTERNAL]: 123 };

console.log(Object.keys(user));      // => ['nama'] (symbol tidak ikut)
console.log(JSON.stringify(user));   // => {"nama":"Sari"}
```

### 11.5 Proxy dan Reflect

**Proxy** membungkus sebuah object dan memungkinkan Anda mencegat operasi dasar seperti membaca, menulis, dan menghapus properti. **Reflect** menyediakan versi standar dari operasi-operasi itu.

```js
function buatTervalidasi(target, aturan) {
  return new Proxy(target, {
    set(objek, kunci, nilai, penerima) {
      const periksa = aturan[kunci];
      if (periksa && !periksa(nilai)) {
        throw new TypeError(`Nilai tidak valid untuk "${String(kunci)}": ${nilai}`);
      }
      return Reflect.set(objek, kunci, nilai, penerima);
    },
  });
}

const user = buatTervalidasi({}, {
  umur: (n) => Number.isInteger(n) && n >= 0,
  email: (s) => typeof s === 'string' && s.includes('@'),
});

user.umur = 25;           // ok
// user.umur = -5;        // TypeError
```

Proxy adalah dasar banyak library (ORM, state management, validasi). Gunakan dengan hemat karena ia membuat perilaku kode kurang kasatmata dan menambah beban performa.

### 11.6 Destructuring, optional chaining, dan operator modern

```js
const respons = {
  data: { user: { nama: 'Sari', alamat: null } },
  meta: { halaman: 1 },
};

// Destructuring bersarang dengan alias dan default
const {
  data: { user: { nama, umur = 0 } },
  meta: { halaman: noHalaman },
} = respons;

// Optional chaining: berhenti dan mengembalikan undefined jika ada yang null/undefined
console.log(respons.data.user.alamat?.kota);     // => undefined (tanpa error)
console.log(respons.data.user.hobi?.[0]);         // => undefined
console.log(respons.data.user.sapa?.());          // => undefined

// Nullish coalescing dan logical assignment
const port = process.env.PORT ?? 3000;
const opsi = {};
opsi.batas ??= 100;   // isi hanya jika null atau undefined
opsi.log ||= true;    // isi jika falsy
opsi.ketat &&= false; // ubah hanya jika truthy
```

### 11.7 Getter, setter, dan descriptor properti

Setiap properti punya "atribut" tersembunyi: `writable`, `enumerable`, `configurable`. Anda bisa mengaturnya dengan `Object.defineProperty`:

```js
const akun = {};
Object.defineProperty(akun, 'id', {
  value: 'abc123',
  writable: false,     // tidak bisa diubah
  enumerable: true,    // muncul di Object.keys
  configurable: false, // tidak bisa dihapus atau didefinisikan ulang
});

akun.id = 'xyz';       // diabaikan (error di strict mode)
console.log(akun.id);  // => 'abc123'
```

### 11.8 Serialisasi JSON dengan kontrol penuh

```js
const data = {
  nama: 'Sari',
  password: 'rahasia',
  dibuat: new Date('2026-10-01T00:00:00Z'),
};

// Replacer: menyaring field sensitif
const aman = JSON.stringify(data, (kunci, nilai) =>
  kunci === 'password' ? undefined : nilai
);
console.log(aman); // => {"nama":"Sari","dibuat":"2026-10-01T00:00:00.000Z"}

// toJSON: kendali ada di tangan object itu sendiri
class User {
  constructor(nama, passwordHash) {
    this.nama = nama;
    this.passwordHash = passwordHash;
  }
  toJSON() {
    return { nama: this.nama }; // passwordHash tidak pernah ikut
  }
}
console.log(JSON.stringify(new User('Sari', 'hash'))); // => {"nama":"Sari"}
```

Merancang `toJSON` pada model data adalah lapisan pertahanan murah agar field sensitif tidak bocor ke respons API.

## Bab 12. Tanggal dan Waktu dengan Temporal

### 12.1 Masalah pada `Date`

Object `Date` bawaan JavaScript terkenal bermasalah:

- **Dapat diubah** (_mutable_), mudah menimbulkan bug.
- Bulan dimulai dari **0** (Januari = 0).
- Hanya mengenal zona waktu lokal sistem dan UTC.
- Hasil parsing string tidak konsisten antar format.
- Aritmetika tanggal (tambah 1 bulan) harus ditulis manual dan rawan salah.

```js
const d = new Date(2026, 9, 1); // bulan 9 = OKTOBER, bukan September
console.log(d.getMonth());       // => 9
```

### 12.2 Temporal: pengganti modern

**Temporal** adalah API tanggal dan waktu baru yang mencapai Stage 4 pada pertemuan TC39 Maret 2026 dan menjadi bagian ECMAScript 2026. Temporal sudah aktif secara bawaan di Node.js 26. Pada versi lebih lama, Anda bisa memakai polyfill resmi komunitas (`@js-temporal/polyfill`). Periksa selalu ketersediaan di runtime Anda:

```js
console.log(typeof Temporal); // => 'object' jika tersedia
```

Keunggulan Temporal:

- Semua object **immutable**: operasi mengembalikan object baru.
- Bulan dimulai dari **1**.
- Dukungan zona waktu IANA yang sesungguhnya (misalnya `Asia/Jakarta`).
- Tipe-tipe terpisah untuk kebutuhan berbeda, sehingga lebih sulit salah pakai.

### 12.3 Tipe-tipe utama

|Tipe|Mewakili|Contoh pemakaian|
|---|---|---|
|`Temporal.Instant`|Satu titik waktu absolut (tanpa zona)|Timestamp di database, log, `created_at`|
|`Temporal.ZonedDateTime`|Titik waktu + zona waktu + kalender|Jadwal rapat di Jakarta|
|`Temporal.PlainDate`|Tanggal saja, tanpa jam dan zona|Tanggal lahir, tanggal jatuh tempo|
|`Temporal.PlainTime`|Jam saja|Jam buka toko|
|`Temporal.PlainDateTime`|Tanggal dan jam tanpa zona|Waktu "dinding" tanpa konteks zona|
|`Temporal.Duration`|Rentang waktu|"3 hari 4 jam"|

### 12.4 Contoh pemakaian

```js
// Waktu sekarang sebagai titik absolut
const sekarang = Temporal.Now.instant();
console.log(sekarang.toString()); // contoh: 2026-10-01T05:30:12.123456789Z

// Waktu sekarang di Jakarta
const diJakarta = Temporal.Now.zonedDateTimeISO('Asia/Jakarta');
console.log(diJakarta.toString()); // contoh: 2026-10-01T12:30:12.123+07:00[Asia/Jakarta]

// Membuat tanggal (bulan dimulai dari 1)
const tanggal = Temporal.PlainDate.from('2026-10-01');
console.log(tanggal.year, tanggal.month, tanggal.day); // => 2026 10 1

// Aritmetika yang aman
const jatuhTempo = tanggal.add({ days: 30 });
console.log(jatuhTempo.toString()); // => 2026-10-31

const bulanDepan = tanggal.add({ months: 1 });
console.log(bulanDepan.toString()); // => 2026-11-01

// Selisih dua tanggal
const mulai = Temporal.PlainDate.from('2026-01-01');
const akhir = Temporal.PlainDate.from('2026-10-01');
console.log(mulai.until(akhir, { largestUnit: 'day' }).days); // => 273

// Perbandingan
console.log(Temporal.PlainDate.compare(mulai, akhir)); // => -1 (mulai lebih awal)

// Konversi antar zona
const instan = Temporal.Instant.from('2026-10-01T00:00:00Z');
console.log(instan.toZonedDateTimeISO('Asia/Jakarta').toString());
// => 2026-10-01T07:00:00+07:00[Asia/Jakarta]
console.log(instan.toZonedDateTimeISO('Asia/Jayapura').toString());
// => 2026-10-01T09:00:00+09:00[Asia/Jayapura]
```

### 12.5 Praktik terbaik waktu di backend

1. **Simpan dan kirim waktu dalam UTC** (`Instant`, format ISO 8601 dengan akhiran `Z`). Konversi ke zona pengguna hanya saat menampilkan.
2. Gunakan `PlainDate` untuk hal yang memang bukan titik waktu, seperti tanggal lahir.
3. **Jangan** menghitung "tambah 24 jam" untuk "besok", karena hari saat perubahan jam musim (DST) tidak selalu 24 jam di beberapa zona. Gunakan `ZonedDateTime.add({ days: 1 })`.
4. Jangan menyimpan offset (`+07:00`) saja jika Anda butuh aturan zona. Simpan nama zona (`Asia/Jakarta`).
5. Untuk mengukur durasi eksekusi kode, gunakan `performance.now()`, bukan tanggal.

### 12.6 Sampai Temporal tersedia di mana-mana

Jika target runtime Anda belum mendukung Temporal, pilihannya adalah memasang polyfill, atau tetap memakai `Date` dengan disiplin:

- Selalu bekerja dalam UTC (`Date.now()`, `toISOString()`).
- Hindari parsing string non-ISO.
- Bungkus logika tanggal di satu modul agar mudah diganti ke Temporal nanti.

## Bab 13. Buffer, Binary, dan Stream

### 13.1 Data biner: ArrayBuffer, TypedArray, dan Buffer

Komputer menyimpan semua data sebagai bita (_byte_). JavaScript menyediakan:

- **`ArrayBuffer`**: blok memori mentah dengan ukuran tetap.
- **TypedArray** (`Uint8Array`, `Int32Array`, `Float64Array`, dan lainnya): "jendela" untuk membaca dan menulis `ArrayBuffer` sebagai tipe tertentu.
- **`Buffer`**: khusus Node.js, turunan dari `Uint8Array` dengan tambahan banyak method praktis.

```js
const buf = Buffer.from('Halo Dunia', 'utf8');
console.log(buf);                      // => <Buffer 48 61 6c 6f 20 44 75 6e 69 61>
console.log(buf.length);               // => 10 (jumlah bita)
console.log(buf.toString('hex'));      // => '48616c6f2044756e6961'
console.log(buf.toString('base64'));   // => 'SGFsbyBEdW5pYQ=='

// Dari Base64 kembali ke teks
const asal = Buffer.from('SGFsbyBEdW5pYQ==', 'base64').toString('utf8');
console.log(asal); // => 'Halo Dunia'
```

Perhatikan: `buf.length` adalah jumlah **bita**, bukan jumlah karakter. Karakter non-ASCII memakai lebih dari satu bita.

```js
console.log('é'.length);                    // => 1
console.log(Buffer.byteLength('é', 'utf8')); // => 2
```

Perbandingan bita yang aman dan menyatukan buffer:

```js
const a = Buffer.from([1, 2, 3]);
const b = Buffer.from([4, 5]);
console.log(Buffer.concat([a, b]));        // => <Buffer 01 02 03 04 05>
console.log(a.equals(Buffer.from([1, 2, 3]))); // => true
```

Pada ES2026 ditambahkan konversi Base64 dan hex bawaan pada `Uint8Array` (`toBase64`, `fromBase64`, `toHex`, `fromHex`). Cek dukungan runtime Anda sebelum memakainya, dan gunakan `Buffer` jika belum tersedia.

### 13.2 Mengapa stream

Bayangkan Anda ingin mengirim file video 4 GB ke pengguna. Jika memakai `readFile`, seluruh 4 GB dimuat ke RAM sebelum dikirim, sehingga memori habis dan respons lambat.

**Stream** memproses data **potongan demi potongan** (_chunk_). Memori yang dipakai kecil dan konstan, berapa pun ukuran datanya.

Analogi: menyalurkan air lewat pipa, bukan memindahkan seluruh isi kolam dengan ember sekaligus.

Empat jenis stream di Node.js:

|Jenis|Fungsi|Contoh|
|---|---|---|
|**Readable**|Sumber data|`fs.createReadStream`, request HTTP di server|
|**Writable**|Tujuan data|`fs.createWriteStream`, response HTTP di server|
|**Duplex**|Bisa baca dan tulis|Socket TCP|
|**Transform**|Duplex yang mengubah data|`zlib.createGzip`, enkripsi|

### 13.3 Contoh: menyalin dan mengompres file besar

```js
import { createReadStream, createWriteStream } from 'node:fs';
import { createGzip } from 'node:zlib';
import { pipeline } from 'node:stream/promises';

await pipeline(
  createReadStream('besar.log'),
  createGzip(),
  createWriteStream('besar.log.gz'),
);
console.log('selesai');
```

Selalu gunakan `pipeline` (bukan `.pipe()` manual). `pipeline` menangani **penutupan sumber daya dan penyebaran error** dengan benar, sehingga tidak ada file handle yang bocor ketika salah satu tahap gagal.

### 13.4 Membuat Transform sendiri

```js
import { Transform } from 'node:stream';
import { pipeline } from 'node:stream/promises';
import { createReadStream, createWriteStream } from 'node:fs';

const hurufBesar = new Transform({
  transform(chunk, encoding, callback) {
    callback(null, chunk.toString().toUpperCase());
  },
});

await pipeline(
  createReadStream('masuk.txt'),
  hurufBesar,
  createWriteStream('keluar.txt'),
);
```

Cara yang lebih ringkas di JavaScript modern: pakai **async generator** sebagai tahap di `pipeline`:

```js
await pipeline(
  createReadStream('masuk.txt', { encoding: 'utf8' }),
  async function* (sumber) {
    for await (const potongan of sumber) {
      yield potongan.toUpperCase();
    }
  },
  createWriteStream('keluar.txt'),
);
```

### 13.5 Backpressure

**Backpressure** adalah mekanisme "rem": jika tujuan menerima data lebih lambat daripada sumber mengirimnya, sumber diminta berhenti sejenak agar memori tidak membengkak.

```js
// Pola manual, hanya untuk memahami konsepnya
const tulis = createWriteStream('keluaran.txt');

async function tulisBanyak(jumlah) {
  for (let i = 0; i < jumlah; i++) {
    const lancar = tulis.write(`baris ${i}\n`);
    if (!lancar) {
      // buffer internal penuh: tunggu sampai kosong lagi
      await new Promise((selesai) => tulis.once('drain', selesai));
    }
  }
  tulis.end();
}
```

`pipeline` mengurus backpressure otomatis. Itulah alasan lain memakainya.

### 13.6 Membaca stream dengan for await

```js
import { createReadStream } from 'node:fs';
import { createInterface } from 'node:readline';

// Membaca file baris demi baris, aman untuk file berukuran gigabita
const baris = createInterface({
  input: createReadStream('data.csv'),
  crlfDelay: Infinity,
});

let jumlah = 0;
for await (const barisIni of baris) {
  if (barisIni.includes('ERROR')) jumlah++;
}
console.log(`jumlah baris ERROR: ${jumlah}`);
```

### 13.7 Web Streams

Node.js juga mendukung **Web Streams API** (standar browser: `ReadableStream`, `WritableStream`, `TransformStream`). Ini penting karena `fetch` mengembalikan body berupa Web Stream, dan kode bisa dibagi antara browser dan server.

```js
import { Readable } from 'node:stream';

const respons = await fetch('https://contoh.com/data-besar');
// Mengubah Web Stream menjadi stream Node.js
const nodeStream = Readable.fromWeb(respons.body);
```

### 13.8 Stream di server HTTP

```js
import { createServer } from 'node:http';
import { createReadStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';

createServer(async (req, res) => {
  if (req.url === '/unduh') {
    res.writeHead(200, { 'content-type': 'text/plain; charset=utf-8' });
    try {
      await pipeline(createReadStream('laporan-besar.txt'), res);
    } catch (err) {
      console.error('Unduhan terputus:', err.message);
    }
    return;
  }
  res.writeHead(404).end();
}).listen(3000);
```

## Bab 14. Paralelisme: Worker Threads dan Konteks Asinkron

### 14.1 Konkurensi versus paralelisme

Dua istilah yang sering tertukar:

- **Konkurensi** (_concurrency_): mengelola banyak tugas yang berjalan **bergantian**, dalam satu thread. Inilah yang dilakukan event loop untuk pekerjaan I/O.
- **Paralelisme** (_parallelism_): beberapa tugas benar-benar berjalan **bersamaan** di beberapa core CPU.

Untuk pekerjaan yang banyak menunggu (database, jaringan), konkurensi sudah cukup. Untuk pekerjaan yang banyak menghitung (enkripsi massal, pengolahan gambar, parsing besar), Anda butuh paralelisme.

### 14.2 Worker threads

`worker_threads` menjalankan JavaScript di thread terpisah dengan event loop dan memori sendiri. Komunikasi dilakukan lewat **pesan** yang disalin (atau dipindahkan).

Contoh dalam satu file: menghitung Fibonacci berat di beberapa worker sekaligus.

```js
import { Worker, isMainThread, parentPort, workerData } from 'node:worker_threads';

function fib(n) {
  return n < 2 ? n : fib(n - 1) + fib(n - 2);
}

if (isMainThread) {
  // Kode ini berjalan di thread utama
  const jalankanDiWorker = (n) =>
    new Promise((selesai, gagal) => {
      const worker = new Worker(new URL(import.meta.url), { workerData: { n } });
      worker.once('message', selesai);
      worker.once('error', gagal);
      worker.once('exit', (kode) => {
        if (kode !== 0) gagal(new Error(`Worker berhenti dengan kode ${kode}`));
      });
    });

  console.time('paralel');
  const hasil = await Promise.all([40, 41, 42].map(jalankanDiWorker));
  console.timeEnd('paralel');
  console.log(hasil);
} else {
  // Kode ini berjalan di dalam worker
  parentPort.postMessage(fib(workerData.n));
}
```

Perhatikan bahwa thread utama tetap responsif selama worker bekerja.

### 14.3 Kapan memakai worker, kapan tidak

|Pakai worker|Jangan pakai worker|
|---|---|
|Hashing, enkripsi, kompresi data besar|Menunggu database atau HTTP (sudah asinkron)|
|Pengolahan gambar atau PDF|Pekerjaan singkat (biaya membuat worker lebih mahal)|
|Parsing atau transformasi data raksasa|Akses data yang sering dibagi antar worker tanpa perlu|
|Perhitungan numerik berat||

Membuat worker baru untuk setiap permintaan itu mahal. Pada produksi gunakan **worker pool** (kumpulan worker yang dipakai ulang), misalnya lewat library `piscina`.

### 14.4 Memori bersama

Secara bawaan, pesan antar thread **disalin**. Untuk data biner besar, Anda bisa **memindahkan** kepemilikan (_transfer_) atau **berbagi** memori:

```js
const bersama = new SharedArrayBuffer(4);
const penghitung = new Int32Array(bersama);

// Atomics menjamin operasi tidak terganggu thread lain
Atomics.add(penghitung, 0, 1);
console.log(Atomics.load(penghitung, 0)); // => 1
```

Memori bersama menimbulkan risiko _race condition_. Gunakan hanya jika Anda benar-benar membutuhkannya, dan selalu lewat `Atomics`.

### 14.5 Proses anak dan cluster

- **`child_process`** menjalankan program lain atau skrip Node.js terpisah sebagai proses baru. Gunakan `execFile` atau `spawn` dengan argumen berbentuk array. **Hindari `exec` dengan string gabungan dari input pengguna** karena rawan _command injection_ (Bab 18).
- **`cluster`** menjalankan beberapa proses Node.js yang berbagi satu port, memanfaatkan semua core CPU. Pada penerapan modern, skala horizontal biasanya diatur di luar aplikasi: beberapa instance container di belakang _load balancer_, atau pengelola proses seperti PM2.

### 14.6 AsyncLocalStorage: konteks per permintaan

Masalah klasik: bagaimana menyertakan **ID permintaan** pada setiap baris log di seluruh kode, tanpa mengoper parameter `requestId` ke tiap fungsi?

Jawabannya `AsyncLocalStorage`, yang menyimpan data yang "mengikuti" rantai pemanggilan asinkron:

```js
import { AsyncLocalStorage } from 'node:async_hooks';
import { randomUUID } from 'node:crypto';
import { setTimeout as tidur } from 'node:timers/promises';

const konteks = new AsyncLocalStorage();

function log(pesan) {
  const id = konteks.getStore()?.requestId ?? '-';
  console.log(`[${id}] ${pesan}`);
}

async function layananDalam() {
  await tidur(10);
  log('di dalam layanan, requestId otomatis tersedia');
}

async function tangani(nama) {
  await konteks.run({ requestId: randomUUID().slice(0, 8) }, async () => {
    log(`mulai ${nama}`);
    await layananDalam();
    log(`selesai ${nama}`);
  });
}

await Promise.all([tangani('A'), tangani('B')]);
// Setiap baris log membawa requestId yang benar untuk permintaannya sendiri,
// walaupun A dan B berjalan bersamaan.
```

Pola ini dipakai untuk logging terstruktur, _tracing_, dan menyimpan informasi pengguna yang sedang login selama satu permintaan.

## Bab 15. Memori dan Performa

### 15.1 Bagaimana JavaScript mengelola memori

Anda tidak mengalokasikan dan membebaskan memori secara manual. Mesin V8 memiliki **garbage collector** (GC) yang secara otomatis membersihkan object yang sudah **tidak dapat dijangkau** dari kode Anda.

Ruang memori utama (_heap_) dibagi dua generasi:

- **Young generation**: tempat object baru. Dibersihkan sangat sering dan cepat. Sebagian besar object mati muda.
- **Old generation**: object yang bertahan lama. Dibersihkan lebih jarang tetapi lebih mahal.

Hal penting: GC bisa menjeda eksekusi sejenak. GC yang terlalu sering atau lama menandakan penggunaan memori yang tidak sehat.

### 15.2 Memantau penggunaan memori

```js
function laporMemori() {
  const m = process.memoryUsage();
  const mb = (bita) => (bita / 1024 / 1024).toFixed(1);
  console.log({
    rss: `${mb(m.rss)} MB`,             // total memori proses di RAM
    heapTotal: `${mb(m.heapTotal)} MB`, // heap yang dialokasikan
    heapUsed: `${mb(m.heapUsed)} MB`,   // heap yang benar-benar terpakai
    external: `${mb(m.external)} MB`,   // memori di luar heap (mis. Buffer)
  });
}

laporMemori();
```

Batas heap dapat diatur dengan opsi `--max-old-space-size` (dalam MB):

```bash
node --max-old-space-size=2048 server.js
```

Menaikkan batas hanya menunda masalah jika ada kebocoran. Perbaiki penyebabnya.

### 15.3 Penyebab umum kebocoran memori

Kebocoran terjadi ketika object yang sebenarnya tak dibutuhkan lagi **masih dapat dijangkau**, sehingga GC tidak bisa membersihkannya.

**1. Cache atau koleksi global tanpa batas**

```js
const cacheTanpaBatas = new Map();

function ambilUser(id) {
  if (!cacheTanpaBatas.has(id)) cacheTanpaBatas.set(id, muatDariDb(id));
  return cacheTanpaBatas.get(id); // tumbuh selamanya
}
```

**2. Event listener yang tidak dilepas**

```js
import { EventEmitter } from 'node:events';
const bus = new EventEmitter();

function tangani() {
  // Setiap pemanggilan menambah listener baru dan tidak pernah dilepas
  bus.on('pesan', () => { /* ... */ });
}
```

Node.js memberi peringatan `MaxListenersExceededWarning` saat listener berlebihan. Jangan abaikan peringatan itu.

**3. Timer yang tidak dibersihkan**: `setInterval` yang tidak pernah di-`clearInterval`, dan menahan referensi ke data.

**4. Closure yang menangkap data besar** (Bab 3).

**5. Promise yang tidak pernah selesai** dan menahan semua yang ia referensikan.

### 15.4 Solusi: cache dengan batas, LRU

**LRU** (_Least Recently Used_) membuang item yang paling lama tidak dipakai ketika penuh. `Map` mengingat urutan penyisipan, sehingga cocok:

```js
export class LruCache {
  #maks;
  #peta = new Map();

  constructor(maks) {
    this.#maks = maks;
  }

  get(kunci) {
    if (!this.#peta.has(kunci)) return undefined;
    const nilai = this.#peta.get(kunci);
    this.#peta.delete(kunci);       // pindahkan ke posisi paling baru
    this.#peta.set(kunci, nilai);
    return nilai;
  }

  set(kunci, nilai) {
    if (this.#peta.has(kunci)) this.#peta.delete(kunci);
    this.#peta.set(kunci, nilai);
    if (this.#peta.size > this.#maks) {
      const tertua = this.#peta.keys().next().value; // kunci pertama = paling lama
      this.#peta.delete(tertua);
    }
  }

  get ukuran() {
    return this.#peta.size;
  }
}

const cache = new LruCache(2);
cache.set('a', 1);
cache.set('b', 2);
cache.get('a');      // 'a' menjadi yang terbaru
cache.set('c', 3);   // 'b' dibuang karena paling lama tidak dipakai
console.log(cache.get('b')); // => undefined
```

Untuk produksi dengan banyak instance server, pertimbangkan cache terpusat seperti Redis, karena cache dalam memori tidak dibagi antar proses.

### 15.5 Mengukur, bukan menebak

Aturan emas optimasi: **ukur dulu, optimalkan bagian yang terbukti lambat**. Optimasi prematur membuang waktu dan membuat kode rumit.

```js
import { performance } from 'node:perf_hooks';

const mulai = performance.now();
await kerjaanYangDiukur();
const durasi = performance.now() - mulai;
console.log(`durasi: ${durasi.toFixed(2)} ms`);

// Penanda dan pengukuran bernama
performance.mark('awal');
await kerjaanYangDiukur();
performance.mark('akhir');
performance.measure('kerja', 'awal', 'akhir');
console.log(performance.getEntriesByName('kerja')[0].duration);
```

Alat profiling bawaan:

|Alat|Fungsi|
|---|---|
|`node --inspect server.js`|Membuka debugger yang bisa dihubungkan Chrome DevTools lewat `chrome://inspect`|
|`node --cpu-prof server.js`|Menghasilkan profil CPU (`.cpuprofile`) untuk menemukan fungsi paling lambat|
|`node --heap-prof server.js`|Menghasilkan profil alokasi memori|
|`v8.writeHeapSnapshot()`|Menyimpan snapshot heap, lalu dibandingkan di DevTools untuk mencari kebocoran|

Cara mencari kebocoran secara umum: ambil snapshot pertama, beri beban pada aplikasi, ambil snapshot kedua, lalu bandingkan object apa yang bertambah.

### 15.6 Kesalahan performa yang paling sering di backend

1. **Masalah N+1 query**: mengambil daftar, lalu melakukan satu query per item.

```js
// Buruk: 1 query daftar + N query detail
const pesanan = await db.pesanan.semua();
for (const p of pesanan) {
  p.pelanggan = await db.pelanggan.cari(p.pelangganId);
}

// Baik: 2 query total
const semuaPesanan = await db.pesanan.semua();
const ids = [...new Set(semuaPesanan.map((p) => p.pelangganId))];
const pelangganList = await db.pelanggan.cariBanyak(ids);
const peta = new Map(pelangganList.map((x) => [x.id, x]));
for (const p of semuaPesanan) p.pelanggan = peta.get(p.pelangganId);
```

2. **Tidak ada paginasi**: mengembalikan jutaan baris sekaligus.
3. **Operasi sinkron di jalur permintaan** (Bab 8).
4. **Serialisasi JSON berulang** untuk data yang sama. Cache hasilnya.
5. **Tidak ada indeks database** pada kolom yang sering dicari.
6. **Kode bentuk object tidak konsisten**. V8 mengoptimalkan object yang selalu punya properti sama dalam urutan sama. Inisialisasi semua properti di constructor, dan hindari `delete` pada properti.

Node.js modern menyertakan banyak fitur yang dulu membutuhkan paket tambahan. Mengurangi dependensi berarti permukaan serangan lebih kecil dan upgrade lebih mudah. Beberapa fitur di bawah ini berstatus eksperimental atau berubah antar versi, jadi **cek dokumentasi versi yang Anda pakai**.

Nama flag dan tingkat stabilitasnya telah berubah antar versi, jadi baca dokumentasi untuk versi Node.js Anda. Fitur ini membantu membatasi dampak jika ada dependensi yang berbahaya.

### 16.6 Konfigurasi aplikasi yang sehat

Prinsip _twelve-factor_: **konfigurasi berasal dari variabel lingkungan**, bukan ditanam di kode. Validasi sekali saat startup, dan **gagal cepat** jika ada yang kurang:

```js
// src/config.js
function wajib(nama) {
  const nilai = process.env[nama];
  if (!nilai) throw new Error(`Variabel lingkungan ${nama} wajib diisi`);
  return nilai;
}

function angka(nama, bawaan) {
  const mentah = process.env[nama];
  if (mentah === undefined) return bawaan;
  const n = Number(mentah);
  if (!Number.isFinite(n)) throw new Error(`${nama} harus berupa angka`);
  return n;
}

export const config = Object.freeze({
  lingkungan: process.env.NODE_ENV ?? 'development',
  port: angka('PORT', 3000),
  urlDatabase: wajib('DATABASE_URL'),
});
```

Jangan pernah menyimpan rahasia (password, API key) di repository Git.

## Bab 17. Pola Desain untuk Backend

**Pola desain** (_design pattern_) adalah solusi yang sudah teruji untuk masalah yang sering muncul. Berikut pola yang paling berguna di backend JavaScript.

### 17.1 Arsitektur berlapis

Pisahkan kode berdasarkan tanggung jawab:

```text
Permintaan HTTP
      |
  [ Route / Controller ]   <- menerima permintaan, validasi input, kirim respons
      |
  [ Service ]               <- logika bisnis
      |
  [ Repository ]            <- akses data (database, API luar)
      |
   Database
```

Aturan emasnya: **lapisan atas boleh memanggil lapisan bawah, tidak sebaliknya**, dan logika bisnis tidak boleh bergantung pada detail HTTP. Dengan begitu logika bisnis bisa diuji tanpa server dan dipakai ulang (misalnya dari CLI atau antrian kerja).

### 17.2 Injeksi dependensi manual

Alih-alih membuat dependensi di dalam class, **terima dari luar**. Tidak butuh framework khusus:

```js
// repository
export function buatUserRepository(db) {
  return {
    async cariById(id) {
      return db.query('SELECT * FROM users WHERE id = $1', [id]);
    },
    async simpan(user) {
      return db.query('INSERT INTO users (nama) VALUES ($1) RETURNING *', [user.nama]);
    },
  };
}

// service
export function buatUserService({ userRepository, logger }) {
  return {
    async daftar(data) {
      if (!data.nama) throw new ValidationError('Nama wajib diisi');
      const user = await userRepository.simpan(data);
      logger.info(`user ${user.id} dibuat`);
      return user;
    },
  };
}

// composition root: satu tempat merakit semuanya
const db = await sambungkanDatabase();
const userRepository = buatUserRepository(db);
const userService = buatUserService({ userRepository, logger: console });
```

Tempat tunggal merakit semua dependensi disebut **composition root**, biasanya di `app.js`. Saat menguji, Anda tinggal mengganti `userRepository` dengan versi tiruan di memori.

### 17.3 Pola Repository

Repository menyembunyikan **cara** data disimpan. Service hanya tahu "simpan user" dan "cari user", bukan apakah itu PostgreSQL, MongoDB, atau memori. Manfaat: Anda bisa mengganti database atau menguji tanpa database sungguhan.

```js
// Versi tiruan di memori, ideal untuk pengujian
export function buatUserRepositoryMemori() {
  const data = new Map();
  let urutan = 1;
  return {
    async simpan(user) {
      const baru = { id: urutan++, ...user };
      data.set(baru.id, baru);
      return baru;
    },
    async cariById(id) {
      return data.get(id) ?? null;
    },
  };
}
```

### 17.4 Observer dengan EventEmitter

`EventEmitter` memungkinkan komponen berkomunikasi tanpa saling mengenal. Cocok untuk efek samping sekunder, misalnya mengirim email setelah user mendaftar:

```js
import { EventEmitter } from 'node:events';

class UserEvents extends EventEmitter {}
export const userEvents = new UserEvents();

// Pendaftar event
userEvents.on('user:dibuat', async (user) => {
  try {
    await kirimEmailSelamatDatang(user);
  } catch (err) {
    console.error('Email gagal dikirim:', err);
  }
});

// Pemicu event (di dalam service)
userEvents.emit('user:dibuat', { id: 1, email: 'sari@contoh.com' });
```

Hati-hati: handler `async` pada `EventEmitter` yang melempar error akan menjadi _unhandled rejection_. Selalu bungkus dengan `try/catch` di dalam handler, seperti contoh di atas. Untuk pekerjaan yang harus dijamin selesai, gunakan antrian kerja yang tahan gagal, bukan event dalam proses.

### 17.5 Strategy

Memilih algoritma saat runtime tanpa rantai `if...else` panjang:

```js
const strategiBiayaKirim = {
  reguler: (beratKg) => 9000 + beratKg * 2000,
  ekspres: (beratKg) => 20000 + beratKg * 4000,
  hariIni: (beratKg) => 35000 + beratKg * 6000,
};

function hitungBiayaKirim(jenis, beratKg) {
  const strategi = strategiBiayaKirim[jenis];
  if (!strategi) throw new ValidationError(`Jenis pengiriman tidak dikenal: ${jenis}`);
  return strategi(beratKg);
}
```

Menambah jenis pengiriman cukup menambah satu entri, tanpa mengubah fungsi inti.

### 17.6 Middleware: rantai pemrosesan

Hampir semua framework web memakai pola middleware: permintaan melewati serangkaian fungsi, masing-masing bisa bertindak sebelum dan sesudah memanggil yang berikutnya.

```js
export function compose(daftarMiddleware) {
  return function jalankan(ctx) {
    let terakhir = -1;

    function kirim(i) {
      if (i <= terakhir) {
        return Promise.reject(new Error('next() dipanggil lebih dari sekali'));
      }
      terakhir = i;
      const fn = daftarMiddleware[i];
      if (!fn) return Promise.resolve();
      try {
        return Promise.resolve(fn(ctx, () => kirim(i + 1)));
      } catch (err) {
        return Promise.reject(err);
      }
    }

    return kirim(0);
  };
}
```

Penjelasan alurnya: `kirim(0)` menjalankan middleware pertama dan memberinya fungsi `next` yang akan memanggil `kirim(1)`, dan seterusnya. Karena `next()` mengembalikan Promise, middleware bisa melakukan `await next()` lalu bertindak **setelah** semua middleware di bawahnya selesai (misalnya mencatat durasi total permintaan).

### 17.7 Factory dan modul sebagai singleton

- **Factory**: fungsi yang membuat dan mengembalikan object yang sudah dikonfigurasi, seperti `buatLogger` dan `buatRateLimiter` di Bab 3.
- **Singleton**: pada ESM, sebuah modul hanya dievaluasi **sekali** dan hasilnya di-cache. Karena itu, mengekspor satu instance dari sebuah modul otomatis menjadikannya singleton. Tidak perlu pola `getInstance()` ala bahasa lain.

3. Ganti `if...else` panjang di salah satu kode lama Anda dengan pola Strategy.

## Bab 18. Keamanan pada Level Bahasa dan Runtime

Bab ini membahas keamanan yang terkait langsung dengan JavaScript dan Node.js. Keamanan web secara luas (autentikasi, OWASP, HTTPS, dan lainnya) adalah topik tersendiri pada jalur Backend Developer.

### 18.1 Prototype pollution

Seperti dibahas di Bab 4, semua object mewarisi dari `Object.prototype`. **Prototype pollution** terjadi ketika penyerang berhasil menyisipkan properti ke prototype tersebut, sehingga **semua object** di aplikasi ikut terpengaruh.

Contoh fungsi gabung (_merge_) yang rentan:

```js
function gabung(target, sumber) {
  for (const kunci in sumber) {
    if (typeof sumber[kunci] === 'object' && sumber[kunci] !== null) {
      target[kunci] = gabung(target[kunci] ?? {}, sumber[kunci]);
    } else {
      target[kunci] = sumber[kunci];
    }
  }
  return target;
}

// Input dari penyerang, misalnya dari body permintaan
const jahat = JSON.parse('{"__proto__": {"admin": true}}');
gabung({}, jahat);

console.log({}.admin); // => true  (semua object sekarang punya admin!)
```

Akibatnya, pemeriksaan seperti `if (user.admin)` bisa lolos untuk semua orang.

Pertahanan:

1. **Blokir kunci berbahaya** (`__proto__`, `constructor`, `prototype`) pada fungsi yang menggabungkan atau menyalin object dari input luar.
2. Gunakan **`Map`** atau **`Object.create(null)`** untuk kamus yang kuncinya berasal dari pengguna.
3. Periksa kepemilikan dengan `Object.hasOwn(obj, kunci)`, bukan operator `in` atau akses langsung.
4. **Validasi input dengan skema** (hanya izinkan field yang Anda harapkan), jangan menggabungkan body permintaan mentah ke object internal.
5. Perbarui dependensi secara berkala, karena banyak kasus nyata terjadi di library merge dan utilitas.
6. Node.js memiliki opsi `--disable-proto` untuk menonaktifkan `__proto__`. Pertimbangkan sebagai lapisan tambahan setelah memeriksa dampaknya.

### 18.2 Injection

**Injection** terjadi ketika input pengguna diperlakukan sebagai **kode atau perintah**.

**SQL injection**: jangan menyusun query dengan penggabungan string.

```js
// BERBAHAYA
const query = `SELECT * FROM users WHERE email = '${email}'`;
// Jika email = "x' OR '1'='1" maka seluruh tabel terbaca

// AMAN: query berparameter
await db.query('SELECT * FROM users WHERE email = $1', [email]);
```

**Command injection**: jangan memasukkan input ke string perintah shell.

```js
import { execFile } from 'node:child_process';

// BERBAHAYA: exec(`convert ${namaFile} out.png`) -> namaFile bisa berisi "; rm -rf /"

// AMAN: argumen dikirim sebagai array, tidak melewati shell
execFile('convert', [namaFile, 'out.png'], (err, stdout) => { /* ... */ });
```

Hindari juga `eval()` dan `new Function()` dengan input pengguna.

### 18.3 Path traversal

Jika Anda menyajikan file berdasarkan nama dari pengguna, penyerang bisa mengirim `../../etc/passwd`.

```js
import { resolve, sep } from 'node:path';

const FOLDER_PUBLIK = resolve('./publik');

export function jalurAman(masukan) {
  const target = resolve(FOLDER_PUBLIK, masukan);
  const didalamFolder = target === FOLDER_PUBLIK || target.startsWith(FOLDER_PUBLIK + sep);
  if (!didalamFolder) throw new Error('Akses ditolak');
  return target;
}

// jalurAman('foto/a.png')       -> diizinkan
// jalurAman('../../etc/passwd') -> Error
```

### 18.4 ReDoS: serangan lewat regex

**ReDoS** (_Regular expression Denial of Service_) terjadi saat sebuah regex memiliki pola yang menyebabkan waktu pencocokan meledak secara eksponensial pada input tertentu. Karena regex berjalan di thread utama, satu permintaan jahat bisa membekukan seluruh server.

```js
// Pola rentan: kuantifier bersarang
const rentan = /^(a+)+$/;
// Pada string seperti 'aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!' waktu eksekusi sangat lama.
// Jangan menjalankannya dengan string panjang di mesin Anda.
```

Pertahanan: hindari kuantifier bersarang seperti `(a+)+` dan `(a*)*`, batasi panjang input sebelum dicocokkan, dan gunakan alat pemeriksa regex.

Jika Anda perlu **memasukkan input pengguna ke dalam regex**, escape terlebih dahulu dengan `RegExp.escape()` (ES2025, perlu Node.js 24 ke atas):

```js
const cari = 'harga (promo)?';
const aman = new RegExp(RegExp.escape(cari), 'i'); // karakter khusus diperlakukan sebagai teks biasa
```

### 18.5 Menyimpan password dan membuat token

**Jangan pernah** menyimpan password mentah, dan jangan memakai hash cepat (MD5, SHA-256 polos) untuk password. Gunakan fungsi hash yang **sengaja lambat dan berbumbu** (_salted_). Node.js menyediakan `scrypt` bawaan:

```js
import { scrypt, randomBytes, timingSafeEqual } from 'node:crypto';
import { promisify } from 'node:util';

const scryptAsync = promisify(scrypt);

export async function hashPassword(password) {
  const garam = randomBytes(16);
  const kunci = await scryptAsync(password, garam, 64);
  return `${garam.toString('hex')}:${kunci.toString('hex')}`;
}

export async function cocokkanPassword(password, tersimpan) {
  const [garamHex, kunciHex] = tersimpan.split(':');
  const kunciUji = await scryptAsync(password, Buffer.from(garamHex, 'hex'), 64);
  // Perbandingan waktu-konstan mencegah serangan timing
  return timingSafeEqual(kunciUji, Buffer.from(kunciHex, 'hex'));
}
```

Pada produksi, banyak tim memakai library Argon2 atau bcrypt yang sudah matang. Yang terpenting adalah memahami prinsipnya.

Untuk token acak (sesi, reset password), gunakan sumber acak kriptografis, bukan `Math.random()`:

```js
import { randomBytes, randomUUID } from 'node:crypto';

const token = randomBytes(32).toString('base64url'); // 256 bit acak
const id = randomUUID();
```

### 18.6 Keamanan rantai pasok dependensi

Ekosistem npm besar, dan itu juga berarti besar peluang penyerang menyisipkan paket berbahaya. Kampanye paket npm berbahaya dan ekstensi editor palsu yang menargetkan developer terus dilaporkan oleh peneliti keamanan. Kebiasaan yang disarankan:

1. Kurangi dependensi. Gunakan fitur bawaan Node.js bila cukup (Bab 16).
2. Selalu commit `package-lock.json` dan pasang dengan `npm ci` di CI dan produksi, agar versinya persis.
3. Periksa nama paket dengan teliti untuk menghindari _typosquatting_ (nama yang mirip dengan paket populer).
4. Jalankan `npm audit` secara berkala dan perbarui dependensi yang rentan.
5. Waspadai skrip `postinstall`. Untuk paket yang tidak dipercaya, pertimbangkan `npm install --ignore-scripts`.
6. Periksa reputasi paket: jumlah pengunduh, pemelihara, riwayat rilis, dan aktivitas repository.
7. Pasang ekstensi editor hanya dari penerbit yang tepercaya.
8. Batasi hak akses proses (model izin pada Bab 16) dan jangan menjalankan aplikasi sebagai root.

### 18.7 Perlindungan dasar server

```js
import { createServer } from 'node:http';

const server = createServer(handler);

server.requestTimeout = 30_000;   // batas waktu total menerima satu permintaan
server.headersTimeout = 10_000;   // batas waktu menerima header
server.maxHeadersCount = 100;     // batasi jumlah header
server.keepAliveTimeout = 5_000;  // batas koneksi menganggur
```

Praktik lain yang penting:

- **Batasi ukuran body** (contoh ada di proyek akhir).
- **Terapkan rate limiting** (Bab 3) agar tidak dibanjiri permintaan.
- **Beri timeout** pada semua panggilan keluar (Bab 7).
- **Validasi semua input** di perbatasan: tipe, panjang, format, rentang.
- Jangan percaya header dari klien (`x-forwarded-for` bisa dipalsukan kecuali berasal dari proxy tepercaya Anda).
- **Waspadai SSRF** (_Server-Side Request Forgery_) bila server Anda mengambil URL yang diberikan pengguna: validasi tujuan dan blokir alamat jaringan internal.
- Jangan membocorkan stack trace dan detail internal pada respons error (Bab 10).

## Bab 19. Pengujian dengan Test Runner Bawaan

### 19.1 Mengapa menguji

Pengujian otomatis memberi Anda keberanian mengubah kode tanpa takut merusak yang sudah jalan. Untuk backend, pengujian adalah syarat sebelum kode layak dirilis.

Jenis pengujian umum:

|Jenis|Cakupan|Kecepatan|
|---|---|---|
|**Unit**|Satu fungsi atau class, tanpa dependensi luar|Sangat cepat|
|**Integrasi**|Beberapa komponen bekerja bersama (misalnya service + database tes)|Sedang|
|**End-to-end**|Seluruh sistem dari sisi klien|Lambat|

Proporsi sehat: banyak unit test, cukup integration test, sedikit end-to-end.

### 19.2 Test runner bawaan Node.js

Node.js menyertakan `node:test` dan `node:assert`, sehingga Anda bisa menguji tanpa library tambahan.

```js
// src/lib/map-limit.js sudah dibuat di Bab 7
// test/map-limit.test.js
import { test, describe } from 'node:test';
import assert from 'node:assert/strict';
import { setTimeout as tidur } from 'node:timers/promises';
import { mapLimit } from '../src/lib/map-limit.js';

describe('mapLimit', () => {
  test('menjaga urutan hasil sesuai urutan input', async () => {
    const hasil = await mapLimit([3, 1, 2], 2, async (x) => {
      await tidur(x * 10);
      return x * 2;
    });
    assert.deepEqual(hasil, [6, 2, 4]);
  });

  test('tidak melebihi batas konkurensi', async () => {
    let aktif = 0;
    let puncak = 0;
    const daftar = Array.from({ length: 10 }, (_, i) => i);

    await mapLimit(daftar, 3, async () => {
      aktif++;
      puncak = Math.max(puncak, aktif);
      await tidur(10);
      aktif--;
    });

    assert.equal(puncak, 3);
  });
});
```

Jalankan:

```bash
node --test                 # menjalankan semua file *.test.js
node --test --watch         # mengulang otomatis saat file berubah
```

Test runner bawaan juga mendukung pelaporan cakupan kode (_coverage_). Nama flag-nya bisa berbeda antar versi, jadi lihat dokumentasi `node:test` untuk versi Anda.

### 19.3 Assertion yang sering dipakai

```js
import assert from 'node:assert/strict';

assert.equal(1 + 1, 2);                       // sama (===)
assert.notEqual(1, 2);
assert.deepEqual({ a: 1 }, { a: 1 });         // sama isi, bukan referensi
assert.ok(nilaiTruthy);
assert.throws(() => JSON.parse('{ rusak'), SyntaxError);

// Untuk fungsi async yang diharapkan gagal
await assert.rejects(
  () => bacaKonfigurasi('tidak-ada.json'),
  { name: 'Error', message: /Gagal membaca/ }
);
```

Selalu impor dari `node:assert/strict` agar `equal` berarti `===`, bukan `==`.

### 19.4 Mock dan spy

Gunakan `mock.fn` untuk fungsi tiruan yang mencatat pemanggilannya:

```js
import { test, mock } from 'node:test';
import assert from 'node:assert/strict';
import { coba } from '../src/lib/coba.js';

test('coba berhenti setelah berhasil dan mencoba sesuai kebutuhan', async () => {
  const fn = mock.fn(async ({ ke }) => {
    if (ke < 2) throw new Error('gagal sementara');
    return 'ok';
  });

  const hasil = await coba(fn, { percobaan: 3, dasarMs: 1 });

  assert.equal(hasil, 'ok');
  assert.equal(fn.mock.callCount(), 3); // 2 gagal + 1 berhasil
});
```

Untuk menguji kode yang bergantung pada waktu (`setTimeout`, `Date`), runner ini menyediakan `mock.timers` yang memajukan jam palsu tanpa menunggu sungguhan. Lihat dokumentasi untuk sintaksnya.

### 19.5 Menguji dengan injeksi dependensi

### 19.6 Pengujian integrasi server HTTP

Anda bisa menyalakan server pada **port acak** (`listen(0)`) lalu memanggilnya dengan `fetch`:

```js
import { test, before, after } from 'node:test';
import assert from 'node:assert/strict';
import { createServer } from 'node:http';

let server;
let alamat;

before(async () => {
  server = createServer((req, res) => {
    res.writeHead(200, { 'content-type': 'application/json' });
    res.end(JSON.stringify({ status: 'ok' }));
  });
  await new Promise((selesai) => server.listen(0, selesai));
  alamat = `http://127.0.0.1:${server.address().port}`;
});

after(() => server.close());

test('GET / mengembalikan status ok', async () => {
  const respons = await fetch(alamat);
  assert.equal(respons.status, 200);
  assert.deepEqual(await respons.json(), { status: 'ok' });
});
```

### 19.7 Praktik pengujian yang baik

1. Satu test menguji satu hal, dengan nama yang menjelaskan perilaku yang diharapkan.
2. Test harus **deterministik**: tidak bergantung pada waktu sebenarnya, urutan, atau jaringan luar.
3. Uji **kasus batas dan kegagalan**, bukan hanya jalur bahagia.
4. Jangan menguji detail implementasi, uji perilaku yang terlihat dari luar.
5. Jalankan seluruh test di CI pada setiap perubahan kode.

### 20.5 `src/lib/compose.js`

```js
export function compose(daftarMiddleware) {
  return function jalankan(ctx) {
    let terakhir = -1;

    function kirim(i) {
      if (i <= terakhir) {
        return Promise.reject(new Error('next() dipanggil lebih dari sekali'));
      }
      terakhir = i;
      const fn = daftarMiddleware[i];
      if (!fn) return Promise.resolve();
      try {
        return Promise.resolve(fn(ctx, () => kirim(i + 1)));
      } catch (err) {
        return Promise.reject(err);
      }
    }

    return kirim(0);
  };
}
```

### 20.6 `src/lib/router.js`

Router mini yang mendukung parameter jalur seperti `/tugas/:id`:

```js
import { NotFoundError } from './errors.js';

export function buatRouter() {
  const daftarRute = [];

  function tambah(metode, jalur, handler) {
    const namaParameter = [];
    const pola = new RegExp(
      '^' +
        jalur.replace(/:([A-Za-z0-9_]+)/g, (_, nama) => {
          namaParameter.push(nama);
          return '([^/]+)';
        }) +
        '$'
    );
    daftarRute.push({ metode, pola, namaParameter, handler });
  }

  async function middleware(ctx) {
    for (const rute of daftarRute) {
      if (rute.metode !== ctx.method) continue;
      const cocok = rute.pola.exec(ctx.path);
      if (!cocok) continue;
      ctx.params = Object.fromEntries(
        rute.namaParameter.map((nama, i) => [nama, decodeURIComponent(cocok[i + 1])])
      );
      return rute.handler(ctx);
    }
    throw new NotFoundError('Rute');
  }

  const router = { middleware };
  for (const metode of ['GET', 'POST', 'PATCH', 'DELETE']) {
    router[metode.toLowerCase()] = (jalur, handler) => tambah(metode, jalur, handler);
  }
  return router;
}
```

Catatan: pola jalur di router mini ini belum meng-escape karakter khusus regex seperti titik. Untuk proyek sungguhan, gunakan router yang sudah matang atau `URLPattern`.

### 20.7 `src/app.js`

```js
import { randomUUID } from 'node:crypto';
import { compose } from './lib/compose.js';
import { AppError, NotFoundError, ValidationError } from './lib/errors.js';
import { log } from './lib/context.js';
import { buatRouter } from './lib/router.js';

// ---------- Penyimpanan (dalam memori) ----------
const daftarTugas = new Map();

// ---------- Middleware ----------
async function pencatatLog(ctx, next) {
  const mulai = performance.now();
  await next();
  log('info', 'permintaan selesai', {
    metode: ctx.method,
    jalur: ctx.path,
    status: ctx.status,
    ms: Math.round(performance.now() - mulai),
  });
}

async function penangananError(ctx, next) {
  try {
    await next();
  } catch (err) {
    const dikenal = err instanceof AppError;
    ctx.status = dikenal ? err.status : 500;
    if (ctx.status >= 500) {
      log('error', err.message, { stack: err.stack });
    }
    ctx.body = {
      error: {
        code: dikenal ? err.code : 'INTERNAL_ERROR',
        message: dikenal && err.expose ? err.message : 'Terjadi kesalahan pada server',
      },
    };
  }
}

const BATAS_BODY = 1_000_000; // 1 MB

async function bacaJson(req) {
  const potongan = [];
  let ukuran = 0;
  for await (const chunk of req) {
    ukuran += chunk.length;
    if (ukuran > BATAS_BODY) {
      throw new AppError('Body terlalu besar', { status: 413, code: 'PAYLOAD_TOO_LARGE' });
    }
    potongan.push(chunk);
  }
  if (ukuran === 0) return undefined;
  try {
    return JSON.parse(Buffer.concat(potongan).toString('utf8'));
  } catch (cause) {
    throw new ValidationError('Body bukan JSON yang valid', { cause });
  }
}

async function pembacaBody(ctx, next) {
  if (['POST', 'PATCH'].includes(ctx.method)) {
    ctx.input = await bacaJson(ctx.req);
  }
  await next();
}

// ---------- Rute ----------
const router = buatRouter();

router.get('/health', (ctx) => {
  ctx.body = { status: 'ok', uptimeDetik: Math.round(process.uptime()) };
});

router.get('/tugas', (ctx) => {
  ctx.body = { data: [...daftarTugas.values()] };
});

router.post('/tugas', (ctx) => {
  const judul = ctx.input?.judul;
  if (typeof judul !== 'string' || judul.trim() === '') {
    throw new ValidationError('Field "judul" wajib berupa teks yang tidak kosong');
  }
  const tugas = {
    id: randomUUID(),
    judul: judul.trim(),
    selesai: false,
    dibuat: new Date().toISOString(),
  };
  daftarTugas.set(tugas.id, tugas);
  ctx.status = 201;
  ctx.body = { data: tugas };
});

router.get('/tugas/:id', (ctx) => {
  const tugas = daftarTugas.get(ctx.params.id);
  if (!tugas) throw new NotFoundError('Tugas');
  ctx.body = { data: tugas };
});

router.patch('/tugas/:id', (ctx) => {
  const tugas = daftarTugas.get(ctx.params.id);
  if (!tugas) throw new NotFoundError('Tugas');

  const { judul, selesai } = ctx.input ?? {};
  if (judul !== undefined) {
    if (typeof judul !== 'string' || judul.trim() === '') {
      throw new ValidationError('Field "judul" tidak valid');
    }
    tugas.judul = judul.trim();
  }
  if (selesai !== undefined) {
    if (typeof selesai !== 'boolean') {
      throw new ValidationError('Field "selesai" harus boolean');
    }
    tugas.selesai = selesai;
  }
  ctx.body = { data: tugas };
});

router.delete('/tugas/:id', (ctx) => {
  if (!daftarTugas.delete(ctx.params.id)) throw new NotFoundError('Tugas');
  ctx.status = 204;
});

// ---------- Perakitan ----------
export const app = compose([pencatatLog, penangananError, pembacaBody, router.middleware]);
```

Perhatikan urutan middleware. `pencatatLog` berada paling luar sehingga bisa mencatat status akhir. `penangananError` membungkus semua yang di bawahnya, sehingga error dari `pembacaBody` dan rute ditangkap di satu tempat.

### 20.8 `src/server.js`

```js
import { createServer } from 'node:http';
import { app } from './app.js';
import { jalankanDenganKonteks, log } from './lib/context.js';

const PORT = Number(process.env.PORT ?? 3000);

const server = createServer((req, res) => {
  jalankanDenganKonteks(async () => {
    const url = new URL(req.url, `http://${req.headers.host ?? 'localhost'}`);
    const ctx = {
      req,
      method: req.method,
      path: url.pathname,
      query: Object.fromEntries(url.searchParams),
      params: {},
      input: undefined,
      status: 200,
      body: undefined,
    };

    try {
      await app(ctx);
    } catch (err) {
      // Jaring pengaman terakhir, seharusnya jarang terjadi
      log('error', 'kegagalan tak tertangani', { stack: err.stack });
      ctx.status = 500;
      ctx.body = { error: { code: 'INTERNAL_ERROR', message: 'Terjadi kesalahan pada server' } };
    }

    const muatan = ctx.body === undefined ? '' : JSON.stringify(ctx.body);
    res.writeHead(ctx.status, {
      'content-type': 'application/json; charset=utf-8',
      'content-length': Buffer.byteLength(muatan),
    });
    res.end(muatan);
  });
});

// Perlindungan dasar terhadap klien lambat
server.requestTimeout = 30_000;
server.headersTimeout = 10_000;

server.listen(PORT, () => log('info', `server berjalan di port ${PORT}`));

// ---------- Graceful shutdown ----------
function matikan(sinyal) {
  log('info', `menerima ${sinyal}, mematikan server`);
  server.close(() => {
    log('info', 'server berhenti');
    process.exit(0);
  });
  server.closeIdleConnections();
  // Jika masih ada koneksi menggantung, paksa keluar setelah 10 detik
  setTimeout(() => process.exit(1), 10_000).unref();
}

process.on('SIGINT', () => matikan('SIGINT'));
process.on('SIGTERM', () => matikan('SIGTERM'));

process.on('unhandledRejection', (alasan) => {
  log('error', 'unhandledRejection', { alasan: String(alasan) });
  process.exit(1);
});
process.on('uncaughtException', (err) => {
  log('error', 'uncaughtException', { stack: err.stack });
  process.exit(1);
});
```

### 20.10 Pengujian

Buat `test/app.test.js` memakai pola Bab 19.6: nyalakan server pada port acak, panggil dengan `fetch`, dan periksa status serta isi respons. Untuk itu, pisahkan pembuatan server dari `listen` agar mudah diuji (misalnya ekspor fungsi `buatServer()` dari file tersendiri).

### 20.11 Tantangan lanjutan

Kerjakan secara bertahap setelah versi dasar berjalan:

1. **Persistensi**: simpan tugas ke file JSON atau SQLite, bukan hanya memori.
2. **Validasi skema**: ganti validasi manual dengan fungsi validator yang bisa dipakai ulang.
3. **Paginasi dan filter**: `GET /tugas?selesai=true&halaman=2&ukuran=10`.
4. **Autentikasi**: middleware yang memeriksa token pada header `authorization`.
5. **Rate limiting**: pasang `buatRateLimiter` dari Bab 3 sebagai middleware per alamat IP.
6. **Timeout permintaan** dengan `AbortSignal.timeout` yang diteruskan ke operasi data.
7. **Metrik**: ekspos pemantauan event loop (Bab 8) pada endpoint `/health`.
8. **Refactor ke arsitektur berlapis** (Bab 17): pisahkan route, service, dan repository.
9. **Konfigurasi** dari variabel lingkungan dengan validasi (Bab 16).
10. **Migrasi ke framework** (Fastify, Express, atau Hono) dan bandingkan apa yang Anda dapat dan apa yang hilang. Setelah membangun sendiri, Anda akan benar-benar paham apa yang dilakukan framework tersebut.

## Lampiran B. Daftar Periksa Developer Backend JavaScript

Gunakan daftar ini untuk menilai kesiapan Anda dan meninjau kode.

**Bahasa dan konsep inti**

- [ ] Saya bisa menjelaskan perbedaan nilai dan referensi, serta menyalin object dengan benar.
- [ ] Saya paham closure dan bisa menggunakannya untuk enkapsulasi.
- [ ] Saya bisa menentukan nilai `this` dalam berbagai situasi pemanggilan.
- [ ] Saya paham rantai prototype dan hubungannya dengan class.
- [ ] Saya selalu memakai `===` dan `??` pada tempat yang tepat.

**Asinkron dan runtime**

- [ ] Saya bisa menebak urutan keluaran campuran `setTimeout`, Promise, dan `await`.
- [ ] Saya membedakan kasus serial dan paralel, dan tidak memakai `forEach` dengan `await`.
- [ ] Semua panggilan keluar punya timeout.
- [ ] Saya tahu apa yang memblokir event loop dan cara menghindarinya.
- [ ] Saya memakai stream untuk data besar, dengan `pipeline`.

**Struktur dan kualitas**

- [ ] Proyek memakai ESM dengan struktur folder yang jelas.
- [ ] Error dibedakan antara operasional dan bug, dengan kelas error kustom dan penangan terpusat.
- [ ] Logika bisnis terpisah dari HTTP, dan dependensi disuntikkan.
- [ ] Ada pengujian otomatis untuk logika penting.
- [ ] Konfigurasi berasal dari variabel lingkungan dan divalidasi saat startup.

**Keamanan dan operasional**

- [ ] Input divalidasi di perbatasan, query berparameter, tidak ada `eval`.
- [ ] Password di-hash dengan algoritma yang tepat, token dibuat dengan sumber acak kriptografis.
- [ ] Tidak ada rahasia di repository, dependensi diaudit, lockfile dikunci.
- [ ] Ada graceful shutdown dan penanganan `unhandledRejection`.
- [ ] Penggunaan memori dan event loop dipantau.
