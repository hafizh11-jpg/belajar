## Tentang Buku Ini

### Untuk siapa buku ini?

Buku ini untuk Anda yang:

- sudah pernah menulis program sederhana (variabel, `if`, perulangan, dan fungsi dasar),
- ingin memahami JavaScript lebih dalam, bukan hanya "bisa jalan",
- ingin berkarier sebagai Backend Developer dengan JavaScript dan Node.js.

Jika Anda benar-benar belum pernah memprogram, pelajari dulu dasar-dasarnya (variabel, kondisi, perulangan) selama satu atau dua minggu, lalu kembali ke buku ini.

### Apa itu Backend Developer?

Backend Developer membangun bagian aplikasi yang **tidak terlihat oleh pengguna**: server, logika bisnis, database, dan API (Application Programming Interface). Contoh: saat Anda menekan tombol "Pesan" di aplikasi toko online, yang menyimpan pesanan ke database, menghitung total harga, dan mengirim notifikasi adalah kode backend.

JavaScript adalah salah satu bahasa yang paling banyak dipakai untuk backend karena dijalankan oleh **Node.js**, sebuah runtime (lingkungan penjalan program) yang memungkinkan JavaScript berjalan di luar browser.

### Cara memakai buku ini

1. **Ketik sendiri semua kode.** Jangan hanya menyalin. Mengetik melatih otot ingatan dan membuat Anda menemui error, yang merupakan bagian terpenting dari belajar.
2. **Jalankan setiap contoh** dan ubah sedikit nilainya. Tanyakan pada diri sendiri: "Apa yang terjadi kalau ini saya ganti?"
3. **Kerjakan latihan** di akhir bab sebelum lanjut.
4. **Jangan terburu-buru.** Bab 7 (asynchronous) adalah bab paling penting sekaligus paling sulit. Wajar kalau perlu dibaca dua atau tiga kali.

### Konvensi penulisan

- Komentar dan teks di dalam kode ditulis dalam bahasa Indonesia agar mudah dipahami.
- Nama variabel dan fungsi memakai bahasa Inggris, karena itulah standar di industri dan dokumentasi resmi.
- Istilah teknis ditulis dalam bahasa aslinya (misalnya _callback_, _promise_, _runtime_) dan dijelaskan saat pertama kali muncul. Ringkasannya ada di [Lampiran B](#lampiran-b-glosarium).
- Blok bertanda **Catatan** berisi informasi tambahan, dan blok **Kesalahan umum** berisi jebakan yang sering dialami pemula.

### Versi teknologi yang dipakai

Status per akhir September 2026 (selalu periksa kembali di [https://nodejs.org/en/about/previous-releases](https://nodejs.org/en/about/previous-releases) karena jadwal dapat berubah):

|Versi Node.js|Status|Keterangan|
|---|---|---|
|Node.js 22|Maintenance LTS|Dukungan berakhir 30 April 2027|
|Node.js 24|Active LTS|Pindah ke Maintenance pada Oktober 2026, berakhir 30 April 2028|

**Rekomendasi untuk Anda:** pakai **Node.js 24 LTS atau Node.js 26**. Hampir semua kode di buku ini berjalan di Node.js 22 ke atas. Fitur yang butuh versi lebih baru akan diberi tanda **(Node 26+)**, misalnya Temporal API di Bab 11.

## Bab 1. Menyiapkan Lingkungan Kerja

### Tujuan belajar

Setelah bab ini Anda mampu:

- menjelaskan apa itu Node.js dan bagaimana bedanya dengan JavaScript di browser,
- memasang Node.js dan menjalankan file JavaScript,
- membuat proyek dengan `package.json` yang memakai ES Modules,
- memakai fitur `--watch` dan `--env-file` bawaan Node.js.

### 1.1 Apa itu Node.js?

**JavaScript** adalah bahasa pemrograman. **Node.js** adalah _runtime_ yang menjalankan JavaScript di luar browser, dibangun di atas mesin **V8** (mesin JavaScript milik Google Chrome).

Perbedaan penting antara JavaScript di browser dan di Node.js:

|Aspek|Browser|Node.js|
|---|---|---|
|Objek global utama|`window`, `document`|`globalThis`, `process`|
|Akses file di komputer|Tidak (demi keamanan)|Ya, lewat modul `fs`|
|Manipulasi tampilan (DOM)|Ya|Tidak ada DOM|
|Membuat server HTTP|Tidak|Ya, lewat modul `http`|
|Tujuan|Antarmuka pengguna|Server, tools, skrip, API|

Ada runtime lain seperti **Deno** dan **Bun**. Bahasanya tetap JavaScript, sehingga ilmu di buku ini tetap berguna. Namun Node.js adalah yang paling luas dipakai di industri, sehingga menjadi fokus kita.

### 1.2 Memasang Node.js

Ada dua cara umum:

1. **Installer resmi** dari [https://nodejs.org](https://nodejs.org). Pilih versi LTS. Cara termudah untuk pemula.
2. **Version manager** seperti `nvm` (Linux/macOS), `fnm`, atau `nvm-windows`. Cara ini memungkinkan Anda berpindah versi Node.js per proyek. Sangat berguna saat sudah bekerja di beberapa proyek.

Setelah terpasang, buka terminal dan cek:

```bash
node -v
npm -v
```

Keduanya harus menampilkan nomor versi. `npm` (Node Package Manager) adalah alat untuk memasang paket (library) pihak ketiga, dan otomatis terpasang bersama Node.js.

### 1.3 Editor dan alat bantu

- **Editor:** Visual Studio Code (gratis) sudah lebih dari cukup.
- **Terminal:** Terminal bawaan sistem operasi, atau terminal terpadu di VS Code.
- **Git:** untuk menyimpan riwayat perubahan kode. Sangat disarankan sejak awal.
- **Ekstensi VS Code yang berguna:** ESLint dan Prettier (dibahas di Bab 12).

### 1.4 Program pertama

Buat folder `belajar-js`, lalu buat file `halo.js`:

```js
// halo.js
const nama = "Budi";
console.log(`Halo, ${nama}! Selamat datang di dunia backend.`);
console.log("Versi Node.js Anda:", process.version);
```

Jalankan:

```bash
node halo.js
```

`console.log` mencetak teks ke terminal. `process` adalah objek global milik Node.js yang berisi informasi tentang program yang sedang berjalan.

### 1.5 Membuat proyek dengan package.json

`package.json` adalah "kartu identitas" proyek: nama, versi, daftar dependensi (paket yang dipakai), dan skrip perintah.

```bash
mkdir proyek-latihan
cd proyek-latihan
npm init -y
```

Buka `package.json` dan ubah menjadi seperti ini:

```json
{
  "name": "proyek-latihan",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node src/index.js",
    "dev": "node --watch src/index.js",
    "test": "node --test"
  },
  "engines": {
    "node": ">=24"
  }
}
```

Penjelasan bagian penting:

- `"type": "module"` membuat semua file `.js` diperlakukan sebagai **ES Modules** (`import`/`export`). Ini standar modern dan dijelaskan di Bab 6.
- `"scripts"` adalah pintasan perintah. `npm run dev` akan menjalankan `node --watch src/index.js`.
- `"engines"` mendeklarasikan versi Node.js minimum yang dibutuhkan proyek.
- `"private": true` mencegah proyek terpublikasi tidak sengaja ke npm.

Buat `src/index.js`:

```js
// src/index.js
console.log("Server latihan siap dijalankan");
```

Jalankan dengan `npm run dev`. Sekarang setiap kali Anda menyimpan file, Node.js otomatis menjalankan ulang program. Fitur `--watch` ini bawaan Node.js, sehingga Anda tidak perlu lagi memasang `nodemon`.

### 1.6 Variabel lingkungan dengan --env-file

Backend selalu butuh konfigurasi yang berbeda antar lingkungan (lokal, staging, produksi), misalnya port server dan alamat database. Konfigurasi ini disimpan sebagai **environment variable**, bukan ditulis langsung di kode.

Buat file `.env`:

```
PORT=3000
APP_NAME=Latihan Backend
```

Jalankan:

```bash
node --env-file=.env src/index.js
```

Baca di kode:

```js
const port = Number(process.env.PORT ?? 3000);
console.log(`${process.env.APP_NAME} berjalan di port ${port}`);
```

Catatan: semua nilai di `process.env` selalu bertipe **string**, sehingga angka harus dikonversi dengan `Number()`.

**Kesalahan umum:** meng-commit file `.env` ke Git. File ini sering berisi password dan kunci rahasia. Tambahkan `.env` ke file `.gitignore`.

### 1.7 Struktur folder yang disarankan

```
proyek-latihan/
  src/
    index.js
  test/
  .env
  .gitignore
  package.json
```

### Latihan Bab 1

1. Pasang Node.js LTS dan tampilkan versinya lewat terminal.
2. Buat proyek baru dengan `"type": "module"` dan skrip `dev` yang memakai `--watch`.
3. Buat file `.env` berisi `NAMA=NamaAnda`, lalu cetak `Halo, NamaAnda` dari kode menggunakan `process.env`.
4. Cetak `typeof window` dan `typeof process` di Node.js. Apa hasilnya dan mengapa?

Petunjuk nomor 4: `typeof` pada variabel yang tidak dideklarasikan menghasilkan `"undefined"` tanpa error. Di Node.js tidak ada `window`.

## Bab 2. Mengokohkan Fondasi Bahasa

### Tujuan belajar

- membedakan tipe data primitif dan objek,
- memahami `var`, `let`, `const`, scope, dan hoisting,
- memakai perbandingan yang benar dan memahami _truthy/falsy_,
- memakai operator modern: `?.`, `??`, `??=`, `||=`, `&&=`.

Bab ini terlihat seperti pengulangan, tetapi banyak _bug_ di dunia nyata berasal dari salah paham pada hal-hal dasar ini. Jangan dilewati.

### 2.1 Tipe data

JavaScript memiliki 7 tipe **primitif** dan 1 tipe **objek**:

|Tipe|Contoh|Catatan|
|---|---|---|
|`string`|`"halo"`|Teks|
|`number`|`42`, `3.14`|Semua angka desimal 64-bit|
|`bigint`|`9007199254740993n`|Bilangan bulat sangat besar|
|`boolean`|`true`, `false`||
|`undefined`|`undefined`|Variabel belum diberi nilai|
|`null`|`null`|"Sengaja kosong"|
|`symbol`|`Symbol("id")`|Pengenal unik (jarang dipakai langsung)|
|`object`|`{}`, `[]`, fungsi|Array, fungsi, tanggal, semuanya objek|

Perbedaan besar: **primitif disalin berdasarkan nilai, objek disalin berdasarkan referensi.**

```js
let a = 10;
let b = a;
b = 20;
console.log(a); // 10, tidak ikut berubah

const p1 = { nama: "Sari" };
const p2 = p1;          // p2 menunjuk ke objek yang SAMA
p2.nama = "Dewi";
console.log(p1.nama);   // "Dewi", ikut berubah
```

Analogi: primitif itu seperti fotokopi selembar kertas (isinya sama, tapi terpisah). Objek itu seperti tautan Google Docs (dua orang membuka dokumen yang sama).

`typeof` menampilkan tipe suatu nilai:

```js
typeof "halo";     // "string"
typeof 42;         // "number"
typeof undefined;  // "undefined"
typeof null;       // "object"  <- bug lama JavaScript yang tidak diperbaiki
typeof [];         // "object"
typeof (() => {}); // "function"
```

Untuk mengecek array pakai `Array.isArray(x)`. Untuk mengecek `null` pakai `x === null`.

### 2.2 var, let, dan const

|Kata kunci|Scope|Bisa diubah?|Saran|
|---|---|---|---|
|`var`|Fungsi|Ya|Hindari|
|`let`|Blok `{ }`|Ya|Pakai jika nilai akan berubah|
|`const`|Blok `{ }`|Tidak bisa di-_assign_ ulang|Pakai sebagai default|

Aturan praktis: **mulai dengan `const`**, ubah ke `let` hanya jika memang perlu di-_assign_ ulang, dan **jangan pakai `var`**.

`const` hanya mengunci _penunjuk_, bukan isi objeknya:

```js
const user = { nama: "Sari" };
user.nama = "Dewi";   // boleh, isi objek berubah
// user = {};          // TypeError: tidak boleh assign ulang
```

**Scope** adalah wilayah di mana sebuah variabel dapat diakses:

```js
if (true) {
  let dalamBlok = "hanya di sini";
  var bocor = "var menembus blok";
}
// console.log(dalamBlok); // ReferenceError
console.log(bocor);        // "var menembus blok"
```

**Hoisting** adalah perilaku JavaScript yang "mengangkat" deklarasi ke atas scope. Variabel `let`/`const` memang terangkat, tetapi berada dalam _Temporal Dead Zone_ (TDZ): tidak boleh dipakai sebelum baris deklarasinya.

```js
console.log(x); // undefined (var terangkat dan diisi undefined)
var x = 5;

// console.log(y); // ReferenceError: Cannot access 'y' before initialization
let y = 5;
```

### 2.3 Perbandingan: === versus ==

`==` melakukan **type coercion** (konversi tipe otomatis) sehingga hasilnya sering mengejutkan. `===` membandingkan nilai **dan** tipe tanpa konversi.

```js
0 == "";         // true   (mengejutkan)
"1" == 1;        // true
null == undefined; // true
0 === "";        // false
"1" === 1;       // false
```

**Aturan: selalu pakai `===` dan `!==`.**

Perhatikan bahwa objek dibandingkan berdasarkan referensi:

```js
{ a: 1 } === { a: 1 };  // false, dua objek berbeda
[] === [];              // false
```

Untuk membandingkan isi, Anda perlu membandingkan properti satu per satu atau memakai fungsi pembanding (misalnya `assert.deepStrictEqual` di pengujian).

Kasus khusus `NaN` (Not a Number): `NaN === NaN` bernilai `false`. Pakai `Number.isNaN(x)`.

### 2.4 Truthy dan falsy

Dalam kondisi `if`, setiap nilai dianggap `true` atau `false`. Hanya ada **8 nilai falsy**:

```
false, 0, -0, 0n, "" (string kosong), null, undefined, NaN
```

Semua nilai lain adalah _truthy_, termasuk `"0"`, `"false"`, `[]` (array kosong), dan `{}` (objek kosong).

```js
if ([]) console.log("array kosong itu truthy");
if ("0") console.log("string '0' itu truthy");
```

### 2.5 Operator modern

**Optional chaining `?.`** mengakses properti bersarang tanpa error jika ada bagian yang `null` atau `undefined`:

```js
const order = { customer: { alamat: null } };

// Tanpa ?. akan error: Cannot read properties of null
const kota = order.customer.alamat?.kota;
console.log(kota); // undefined

// Bisa untuk pemanggilan fungsi dan indeks array
order.hitungOngkir?.();
const item = order.items?.[0];
```

**Nullish coalescing `??`** memberi nilai default hanya jika sisi kiri `null` atau `undefined`. Bedakan dengan `||` yang menganggap semua nilai falsy sebagai "kosong":

```js
const config = { port: 0, nama: "" };

console.log(config.port || 3000);  // 3000  (salah! 0 adalah port yang disengaja)
console.log(config.port ?? 3000);  // 0     (benar)
console.log(config.nama ?? "anonim"); // ""  (string kosong dipertahankan)
```

**Logical assignment** menyingkat pola "isi jika kosong":

```js
const opsi = { timeout: null, retry: 0 };

opsi.timeout ??= 5000;  // isi hanya jika null/undefined -> 5000
opsi.retry ||= 3;       // isi jika falsy -> 3 (hati-hati, 0 tertimpa)
opsi.aktif &&= false;   // ubah hanya jika sudah truthy
```

**Template literal** memakai backtick dan `${ }`:

```js
const produk = "Kopi";
const harga = 25000;
console.log(`Harga ${produk}: Rp${harga.toLocaleString("id-ID")}`);
// Harga Kopi: Rp25.000
```

### 2.6 Kesalahan umum

- Memakai `||` untuk nilai default padahal `0`, `false`, atau `""` adalah nilai yang sah. Pakai `??`.
- Membandingkan objek dengan `===` dan berharap isinya dibandingkan.
- Lupa bahwa `process.env.X` selalu string. `"false"` itu truthy!
- Menganggap `const` membuat objek tidak bisa diubah. Untuk itu ada `Object.freeze()`.

### Latihan Bab 2

1. Tanpa menjalankannya, tebak hasil: `0 == false`, `null === undefined`, `[] == false`, `Number.isNaN("abc")`. Lalu cek di Node.js.
2. Tulis fungsi `ambilPort(env)` yang mengembalikan `Number(env.PORT)` atau `3000` jika `PORT` tidak ada. Pastikan `PORT=0` tetap menghasilkan `0`.
3. Diberikan `const data = { user: { profil: { umur: 0 } } }`, tampilkan umur dengan default `18` secara aman, sehingga hasilnya tetap `0`.

## Bab 3. Fungsi Tingkat Lanjut

### Tujuan belajar

- membedakan deklarasi fungsi, ekspresi fungsi, dan arrow function,
- memakai parameter default, _rest_, _spread_, dan _destructuring_ pada parameter,
- memahami _closure_ dan _higher-order function_,
- menulis _pure function_ dan memahami _side effect_.

Fungsi adalah unit bangunan utama di JavaScript. Di backend, hampir semua yang Anda tulis (handler request, validator, service) adalah fungsi.

### 3.1 Tiga cara menulis fungsi

```js
// 1. Deklarasi fungsi (terangkat/hoisted, bisa dipanggil sebelum ditulis)
function tambah(a, b) {
  return a + b;
}

// 2. Ekspresi fungsi (disimpan di variabel, tidak terangkat)
const kurang = function (a, b) {
  return a - b;
};

// 3. Arrow function (ringkas, tidak punya `this` sendiri)
const kali = (a, b) => a * b;
const kuadrat = (n) => n * n;          // satu parameter
const buatSapaan = () => "Halo";       // tanpa parameter
const buatUser = (nama) => ({ nama }); // mengembalikan objek: bungkus dengan ( )
```

Kapan memakai yang mana? Arrow function cocok untuk callback pendek dan fungsi kecil. Deklarasi fungsi cocok untuk fungsi utama yang butuh nama jelas. Perbedaan perilaku `this` dibahas di Bab 5.

### 3.2 Parameter: default, rest, dan spread

```js
// Parameter default
function sapa(nama = "Tamu", sapaan = "Halo") {
  return `${sapaan}, ${nama}!`;
}
sapa();              // "Halo, Tamu!"
sapa("Budi");        // "Halo, Budi!"

// Rest parameter: mengumpulkan sisa argumen menjadi array
function jumlahkan(...angka) {
  return angka.reduce((total, n) => total + n, 0);
}
jumlahkan(1, 2, 3, 4); // 10

// Spread: "membuka" array atau objek
const a = [1, 2];
const b = [...a, 3, 4];        // [1, 2, 3, 4]
const defaults = { port: 3000, debug: false };
const config = { ...defaults, debug: true }; // { port: 3000, debug: true }
```

**Destructuring pada parameter** sangat lazim di backend karena membuat fungsi mudah dibaca ketika parameternya banyak. Ini sering disebut _named parameters_:

```js
function buatPesanan({ produkId, jumlah = 1, catatan = "" }) {
  return { produkId, jumlah, catatan };
}

buatPesanan({ produkId: 7, catatan: "Tanpa gula" });
// urutan tidak penting dan maknanya jelas saat dipanggil
```

Bandingkan dengan `buatPesanan(7, 1, "Tanpa gula")`, di mana pembaca kode harus menebak arti tiap angka.

### 3.3 Fungsi sebagai nilai (first-class function)

Di JavaScript, fungsi adalah nilai biasa: bisa disimpan di variabel, dimasukkan ke array, dikirim sebagai argumen, dan dikembalikan dari fungsi lain.

Fungsi yang menerima atau mengembalikan fungsi lain disebut **higher-order function**. Anda sudah sering memakainya:

```js
const harga = [10000, 25000, 5000];

const denganPajak = harga.map((h) => h * 1.11);
const mahal = harga.filter((h) => h > 8000);
const total = harga.reduce((sum, h) => sum + h, 0);
```

Membuat higher-order function sendiri:

```js
function ulangi(kali, aksi) {
  for (let i = 0; i < kali; i++) aksi(i);
}
ulangi(3, (i) => console.log("Percobaan ke-", i + 1));
```

Fungsi `aksi` yang dikirim sebagai argumen disebut **callback**: "fungsi yang akan dipanggil balik nanti".

### 3.4 Closure

**Closure** terjadi ketika sebuah fungsi "mengingat" variabel dari scope tempat ia dibuat, bahkan setelah scope tersebut selesai dijalankan.

```js
function buatCounter() {
  let hitungan = 0;          // variabel "privat"
  return () => {
    hitungan += 1;
    return hitungan;
  };
}

const counterA = buatCounter();
const counterB = buatCounter();

counterA(); // 1
counterA(); // 2
counterB(); // 1  (punya `hitungan` sendiri)
```

Analogi: closure seperti ransel. Fungsi yang dikembalikan membawa ransel berisi variabel dari tempat kelahirannya, dan isi ransel itu tidak bisa diakses dari luar.

Kegunaan closure di backend:

- **Factory function** yang menghasilkan fungsi terkonfigurasi (misalnya membuat logger dengan prefix tertentu).
- **Enkapsulasi state** tanpa class.
- **Middleware** di framework seperti Express dan Fastify.

```js
function buatLogger(prefix) {
  return (pesan) => console.log(`[${prefix}] ${pesan}`);
}

const logAuth = buatLogger("AUTH");
const logDb = buatLogger("DB");
logAuth("Pengguna berhasil login"); // [AUTH] Pengguna berhasil login
logDb("Koneksi dibuka");            // [DB] Koneksi dibuka
```

**Kesalahan umum: closure di dalam loop dengan `var`.**

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Mencetak 3, 3, 3  (semua closure berbagi satu variabel i)

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// Mencetak 0, 1, 2  (let membuat variabel baru di setiap putaran)
```

### 3.5 Pure function dan side effect

**Pure function** adalah fungsi yang:

1. selalu menghasilkan keluaran yang sama untuk masukan yang sama, dan
2. tidak mengubah apa pun di luar dirinya (tidak ada _side effect_).

```js
// Pure
const hitungTotal = (harga, jumlah) => harga * jumlah;

// Tidak pure: mengubah data di luar dan bergantung pada waktu
let saldo = 100;
function tarik(n) {
  saldo -= n;                // side effect: mengubah variabel luar
  return new Date();         // hasil berbeda tiap dipanggil
}
```

Contoh side effect: menulis ke database, mencetak log, mengubah variabel global, memanggil API luar. Backend tentu butuh side effect (itulah tugas utamanya), tetapi praktik yang baik adalah **memisahkan logika murni dari operasi ber-side-effect**. Logika murni sangat mudah diuji.

```js
// Logika murni: mudah diuji
function hitungDiskon(total, kodePromo) {
  if (kodePromo === "HEMAT10") return total * 0.1;
  return 0;
}

// Fungsi dengan side effect memanggil logika murni
async function prosesPesanan(pesanan, db) {
  const diskon = hitungDiskon(pesanan.total, pesanan.kodePromo);
  await db.simpan({ ...pesanan, diskon });
}
```

Perhatikan bahwa `{ ...pesanan, diskon }` membuat objek baru, bukan mengubah `pesanan` yang masuk. Kebiasaan tidak memodifikasi argumen (_immutability_) menghindari bug yang sulit dilacak.

### 3.6 Memoization: contoh penerapan closure

_Memoization_ menyimpan hasil pemanggilan fungsi agar perhitungan mahal tidak diulang.

```js
function memoize(fn) {
  const cache = new Map();
  return (arg) => {
    if (cache.has(arg)) return cache.get(arg);
    const hasil = fn(arg);
    cache.set(arg, hasil);
    return hasil;
  };
}

const kuadratLambat = (n) => {
  console.log("menghitung...");
  return n * n;
};
const kuadratCepat = memoize(kuadratLambat);

kuadratCepat(9); // menghitung... lalu 81
kuadratCepat(9); // 81 langsung dari cache
```

Catatan: `cache` di atas tumbuh tanpa batas. Di server yang berjalan berbulan-bulan, ini bisa menjadi _memory leak_. Di produksi, batasi ukuran cache atau pakai layanan seperti Redis.

### 3.7 Kesalahan umum

- Menulis arrow function yang mengembalikan objek tanpa tanda kurung: `() => { a: 1 }` dianggap blok kode, bukan objek. Tulis `() => ({ a: 1 })`.
- Lupa `return` pada fungsi bertubuh `{ }`. Arrow function tanpa kurung kurawal me-_return_ otomatis, dengan kurung kurawal tidak.
- Mengubah argumen objek langsung (_mutation_) sehingga pemanggil terkejut datanya berubah.

2. Tulis `hitungPajak({ harga, persen = 11 })` sebagai pure function.
3. Tulis fungsi `sekali(fn)` yang membungkus `fn` sehingga hanya bisa dipanggil satu kali; pemanggilan berikutnya mengembalikan hasil pertama.
4. Perbaiki kode loop `var` di 3.4 tanpa mengganti `var` menjadi `let` (petunjuk: bungkus dengan fungsi yang segera dipanggil).

## Bab 4. Objek, Array, dan Struktur Data Modern

### Tujuan belajar

- memanipulasi objek dengan _destructuring_, _spread_, dan `Object.entries`,
- memilih metode array yang tepat dan memahami mana yang mengubah data asli,
- membedakan salinan dangkal (_shallow copy_) dan salinan dalam (_deep copy_),
- memakai `Map`, `Set`, `Object.groupBy`, dan metode himpunan modern.

Data di backend hampir selalu berbentuk objek dan array: hasil query database, isi request, respons API. Menguasai bab ini membuat pekerjaan sehari-hari jauh lebih cepat.

### 4.1 Objek modern

```js
const nama = "Sari";
const umur = 27;

// Shorthand property dan computed key
const kunci = "kota";
const user = {
  nama,                 // sama dengan nama: nama
  umur,
  [kunci]: "Cirebon",   // nama properti dihitung dari variabel
  sapa() {              // shorthand method
    return `Halo, saya ${this.nama}`;
  },
};
```

**Destructuring** mengambil nilai dari objek atau array ke variabel:

```js
const { nama: namaLengkap, kota, negara = "Indonesia" } = user;
// namaLengkap = "Sari", kota = "Cirebon", negara = "Indonesia" (default)

// Bersarang
const respons = { data: { user: { id: 5, email: "a@b.com" } } };
const { data: { user: { id, email } } } = respons;

// Array
const [pertama, kedua, ...sisa] = [10, 20, 30, 40];
// pertama = 10, kedua = 20, sisa = [30, 40]

// Menukar nilai tanpa variabel bantu
let x = 1, y = 2;
[x, y] = [y, x];
```

**Metode `Object` yang wajib dikenal:**

```js
const stok = { apel: 5, jeruk: 0, mangga: 12 };

Object.keys(stok);     // ["apel", "jeruk", "mangga"]
Object.values(stok);   // [5, 0, 12]
Object.entries(stok);  // [["apel", 5], ["jeruk", 0], ["mangga", 12]]

// Mengubah objek: entries -> proses -> fromEntries
const stokDouble = Object.fromEntries(
  Object.entries(stok).map(([buah, jumlah]) => [buah, jumlah * 2])
);
// { apel: 10, jeruk: 0, mangga: 24 }

// Mengecek kepemilikan properti dengan aman
Object.hasOwn(stok, "apel");  // true
"apel" in stok;               // true (juga mengecek rantai prototype)
```

### 4.2 Salinan dangkal dan salinan dalam

Spread dan `Object.assign` hanya membuat **salinan dangkal**: properti tingkat pertama disalin, tetapi objek di dalamnya tetap berbagi referensi.

```js
const asli = { nama: "Sari", alamat: { kota: "Cirebon" } };

const dangkal = { ...asli };
dangkal.alamat.kota = "Bandung";
console.log(asli.alamat.kota); // "Bandung"  (ikut berubah!)

// Salinan dalam bawaan
const dalam = structuredClone(asli);
dalam.alamat.kota = "Jakarta";
console.log(asli.alamat.kota); // tetap "Bandung"
```

`structuredClone` mampu menyalin `Date`, `Map`, `Set`, dan struktur bersarang. Namun ia tidak dapat menyalin fungsi (akan melempar error).

Untuk membuat objek tidak bisa diubah, pakai `Object.freeze()`. Perlu diingat, freeze juga dangkal.

### 4.3 Metode array

Array punya banyak metode. Kelompokkan agar mudah diingat.

**Transformasi dan pencarian** (tidak mengubah array asli):

```js
const produk = [
  { id: 1, nama: "Kopi", harga: 25000, kategori: "minuman" },
  { id: 2, nama: "Teh", harga: 15000, kategori: "minuman" },
  { id: 3, nama: "Roti", harga: 12000, kategori: "makanan" },
];

produk.map((p) => p.nama);                    // ["Kopi", "Teh", "Roti"]
produk.filter((p) => p.harga > 13000);        // Kopi dan Teh
produk.find((p) => p.id === 3);               // objek Roti (atau undefined)
produk.findLast((p) => p.kategori === "minuman"); // objek Teh
produk.some((p) => p.harga > 20000);          // true
produk.every((p) => p.harga > 20000);         // false
produk.map((p) => p.harga).includes(12000);   // true
produk.at(-1);                                // elemen terakhir (Roti)

// reduce: meringkas array menjadi satu nilai
const total = produk.reduce((sum, p) => sum + p.harga, 0); // 52000

// flat dan flatMap
[[1, 2], [3, [4]]].flat();       // [1, 2, 3, [4]]
[[1, 2], [3, [4]]].flat(Infinity); // [1, 2, 3, 4]
["a b", "c d"].flatMap((s) => s.split(" ")); // ["a", "b", "c", "d"]
```

**Versi yang tidak mengubah data asli** (tersedia di Node.js modern):

```js
const angka = [3, 1, 2];

angka.toSorted();          // [1, 2, 3]  (angka tetap [3, 1, 2])
angka.toReversed();        // [2, 1, 3]
angka.with(0, 99);         // [99, 1, 2]
angka.toSpliced(1, 1);     // [3, 2]

// Bandingkan dengan yang MENGUBAH data asli:
angka.sort();              // angka menjadi [1, 2, 3]
angka.reverse();
angka.splice(1, 1);
angka.push(4);
```

Sebaiknya biasakan memakai `toSorted`, `toReversed`, dan `toSpliced` supaya data asli tidak berubah tanpa disadari.

**Kesalahan umum: `sort()` tanpa fungsi pembanding mengurutkan sebagai string.**

```js
[10, 9, 1, 100].toSorted();               // [1, 10, 100, 9]  (salah untuk angka)
[10, 9, 1, 100].toSorted((a, b) => a - b); // [1, 9, 10, 100]  (benar)

// Mengurutkan teks bahasa Indonesia dengan benar
["zebra", "apel", "Cabai"].toSorted((a, b) => a.localeCompare(b, "id"));
```

### 4.4 Mengelompokkan data: Object.groupBy

Pekerjaan yang sangat sering: mengelompokkan data berdasarkan suatu kunci. Dulu ini perlu `reduce` yang panjang. Sekarang ada `Object.groupBy` dan `Map.groupBy`.

```js
const perKategori = Object.groupBy(produk, (p) => p.kategori);
// {
//   minuman: [ {Kopi}, {Teh} ],
//   makanan: [ {Roti} ]
// }

// Catatan: hasil Object.groupBy adalah objek tanpa prototype (null prototype),
// sehingga aman dari tabrakan nama seperti "toString". Ia belum punya method objek biasa.

// Map.groupBy dipakai jika kuncinya bukan string
const perMahal = Map.groupBy(produk, (p) => p.harga > 13000);
perMahal.get(true);   // [Kopi, Teh]
```

### 4.5 Map dan Set

**Map** adalah pasangan kunci-nilai seperti objek, tetapi kuncinya boleh tipe apa saja, urutan sisipan terjaga, dan ada properti `.size`.

```js
const cache = new Map();
cache.set("user:1", { nama: "Sari" });
cache.set(42, "kuncinya angka");

cache.get("user:1");   // { nama: "Sari" }
cache.has(42);         // true
cache.delete(42);
cache.size;            // 1

for (const [kunci, nilai] of cache) {
  console.log(kunci, nilai);
}
```

Kapan memakai `Map` daripada objek biasa?

|Situasi|Pilihan|
|---|---|
|Struktur tetap dengan nama properti yang sudah diketahui (data user, konfigurasi)|Objek|
|Kamus dinamis dengan kunci dari data (cache, pengindeks)|`Map`|
|Kunci bukan string|`Map`|
|Sering menambah dan menghapus kunci|`Map`|
|Perlu diubah ke JSON|Objek (Map tidak otomatis jadi JSON)|

**Set** menyimpan nilai unik:

```js
const tag = new Set(["js", "node", "js", "api"]);
tag.size;         // 3
tag.has("node");  // true
[...new Set([1, 1, 2, 3, 3])]; // [1, 2, 3]  (cara cepat menghapus duplikat)
```

**Operasi himpunan** kini tersedia langsung di `Set` (Node.js 22 ke atas):

```js
const a = new Set([1, 2, 3]);
const b = new Set([3, 4]);

a.union(b);                // Set {1, 2, 3, 4}
a.intersection(b);         // Set {3}
a.difference(b);           // Set {1, 2}
a.symmetricDifference(b);  // Set {1, 2, 4}
a.isSubsetOf(b);           // false
```

Contoh nyata: mencari izin (permission) yang belum dimiliki pengguna.

```js
const izinDibutuhkan = new Set(["baca", "tulis", "hapus"]);
const izinDimiliki = new Set(["baca"]);
const kurang = izinDibutuhkan.difference(izinDimiliki); // Set {"tulis", "hapus"}
```

**(Node 26+)** `Map` mendapat metode `getOrInsert` dan `getOrInsertComputed` untuk pola "ambil, atau buat jika belum ada":

```js
const grup = new Map();
// Cara lama
if (!grup.has("a")) grup.set("a", []);
grup.get("a").push(1);

// Cara baru (Node 26+)
grup.getOrInsert("b", []).push(2);
grup.getOrInsertComputed("c", () => []).push(3); // fungsi hanya jalan jika kunci belum ada
```

**WeakMap** dan **WeakSet** menyimpan referensi "lemah": jika objek kuncinya tidak dipakai lagi di tempat lain, ia bisa dibersihkan otomatis oleh _garbage collector_. Berguna untuk menyimpan metadata tanpa risiko _memory leak_. Anda akan jarang memakainya langsung, tetapi bagus untuk diketahui.

## Bab 5. Prototype, Class, dan this

### Tujuan belajar

- memahami aturan nilai `this`,
- menjelaskan prototype chain secara sederhana,
- menulis `class` lengkap dengan _private field_, getter, setter, dan `static`,
- memilih antara pewarisan (_inheritance_) dan komposisi (_composition_).

### 5.1 Memahami this

`this` adalah "siapa yang memanggil fungsi ini". Nilainya **ditentukan saat fungsi dipanggil**, bukan saat ditulis (kecuali arrow function).

```js
const user = {
  nama: "Sari",
  sapa() {
    return `Halo, saya ${this.nama}`;
  },
};

user.sapa();          // "Halo, saya Sari"  (this = user, karena dipanggil lewat user.)

const lepas = user.sapa;
// lepas();           // TypeError: this adalah undefined (kode ESM berjalan di strict mode)
```

Ini alasan mengapa bug `this` sering muncul saat method dikirim sebagai callback:

```js
class Penghitung {
  jumlah = 0;
  tambah() {
    this.jumlah++;
  }
}
const p = new Penghitung();

const { tambah } = p;
// tambah();                 // TypeError: this adalah undefined
// setTimeout(p.tambah, 100); // SALAH: this bukan lagi p (di Node.js berisi objek Timeout),
//                            // sehingga p.jumlah tidak pernah bertambah

setTimeout(() => p.tambah(), 100);   // Solusi 1: bungkus dengan arrow function
setTimeout(p.tambah.bind(p), 100);   // Solusi 2: bind
```

Aturan ringkas:

|Cara pemanggilan|Nilai `this`|
|---|---|
|`obj.method()`|`obj`|
|`fungsi()` biasa|`undefined` (strict mode / ESM)|
|`new Kelas()`|Objek baru yang dibuat|
|`fn.call(x)`, `fn.apply(x)`, `fn.bind(x)`|`x`|
|Arrow function|Mengikuti `this` di tempat arrow itu **ditulis**|

Arrow function tidak punya `this` sendiri, sehingga cocok untuk callback di dalam method, tetapi **tidak cocok** sebagai method objek yang butuh `this` dari pemanggil.

### 5.2 Prototype: cara JavaScript mewariskan perilaku

Setiap objek punya tautan tersembunyi ke objek lain yang disebut **prototype**. Ketika Anda mengakses properti yang tidak ada pada objek, JavaScript mencarinya di prototype-nya, lalu prototype dari prototype, dan seterusnya sampai `null`. Rangkaian ini disebut **prototype chain**.

```js
const hewan = {
  bernapas() {
    return "menarik napas";
  },
};

const kucing = Object.create(hewan); // kucing menunjuk hewan sebagai prototype-nya
kucing.suara = "meong";

kucing.suara;        // "meong"          (milik sendiri)
kucing.bernapas();   // "menarik napas"  (ditemukan di prototype)
Object.getPrototypeOf(kucing) === hewan; // true
```

Analogi: bayangkan Anda bertanya pada seorang karyawan. Jika ia tidak tahu, ia bertanya ke atasannya, lalu ke atasannya lagi, sampai ke direktur. Jika tidak ada yang tahu, jawabannya `undefined`.

Mengapa ini penting? Karena `class` di JavaScript sebenarnya adalah **penulisan yang lebih rapi di atas prototype**. Memahami ini membantu Anda mengerti pesan error dan perilaku aneh.

### 5.3 Class

```js
class Rekening {
  // Private field: hanya dapat diakses dari dalam class
  #saldo = 0;

  // Field publik
  pemilik;

  // Static: milik class, bukan milik instance
  static #jumlahRekening = 0;
  static totalRekening() {
    return Rekening.#jumlahRekening;
  }

  constructor(pemilik, saldoAwal = 0) {
    this.pemilik = pemilik;
    this.#saldo = saldoAwal;
    Rekening.#jumlahRekening++;
  }

  // Getter: diakses seperti properti
  get saldo() {
    return this.#saldo;
  }

  setor(jumlah) {
    if (jumlah <= 0) throw new RangeError("Jumlah setoran harus positif");
    this.#saldo += jumlah;
    return this; // memungkinkan chaining
  }

  tarik(jumlah) {
    if (jumlah > this.#saldo) throw new Error("Saldo tidak cukup");
    this.#saldo -= jumlah;
    return this;
  }
}

const r = new Rekening("Sari", 100000);
r.setor(50000).tarik(30000);
console.log(r.saldo);           // 120000
// console.log(r.#saldo);       // SyntaxError: field privat
// r.saldo = 1;                 // TypeError di ESM (strict mode): getter tanpa setter
console.log(Rekening.totalRekening()); // 1
```

Poin penting:

- **`#nama`** adalah private field sungguhan (dijaga oleh bahasa), berbeda dengan konvensi lama `_nama` yang hanya "kesepakatan".
- **`static`** untuk fungsi atau data yang berlaku untuk seluruh class.
- **getter/setter** membuat properti terlihat sederhana tetapi tetap punya logika (validasi, perhitungan).

### 5.4 Pewarisan dengan extends

```js
class Rekening2 {
  constructor(pemilik) {
    this.pemilik = pemilik;
  }
  deskripsi() {
    return `Rekening milik ${this.pemilik}`;
  }
}

class RekeningTabungan extends Rekening2 {
  constructor(pemilik, bunga) {
    super(pemilik);   // wajib dipanggil sebelum memakai this
    this.bunga = bunga;
  }
  deskripsi() {
    return `${super.deskripsi()} dengan bunga ${this.bunga}%`;
  }
}

const t = new RekeningTabungan("Budi", 3);
t.deskripsi();                    // "Rekening milik Budi dengan bunga 3%"
t instanceof RekeningTabungan;    // true
t instanceof Rekening2;           // true
```

### 5.5 Komposisi lebih disukai daripada pewarisan

Pewarisan yang dalam (A extends B extends C extends D) membuat kode kaku dan sulit dipahami. Praktik yang umum di backend adalah **komposisi**: class atau fungsi menerima dependensinya dari luar (disebut _dependency injection_).

```js
class LayananPesanan {
  #db;
  #notifikasi;

  constructor({ db, notifikasi }) {
    this.#db = db;
    this.#notifikasi = notifikasi;
  }

  async buat(pesanan) {
    const tersimpan = await this.#db.simpan(pesanan);
    await this.#notifikasi.kirim(`Pesanan ${tersimpan.id} dibuat`);
    return tersimpan;
  }
}

// Di produksi: db asli. Di pengujian: db palsu (mock) yang sederhana.
const layanan = new LayananPesanan({
  db: { simpan: async (p) => ({ id: 1, ...p }) },
  notifikasi: { kirim: async (pesan) => console.log(pesan) },
});
```

Keuntungannya: `LayananPesanan` tidak peduli database apa yang dipakai, dan sangat mudah diuji dengan objek tiruan.

### 5.6 Kapan pakai class, kapan cukup fungsi?

Di ekosistem JavaScript, keduanya sah. Pedoman sederhana:

- Pakai **class** jika Anda butuh banyak instance dengan _state_ internal dan beberapa method yang saling terkait (misalnya koneksi, layanan, error kustom).
- Pakai **fungsi biasa + objek** untuk logika tanpa state (validasi, formatter, helper).
- Jangan memaksakan class hanya karena terbiasa dari bahasa lain.

### Kesalahan umum

- Mengirim method sebagai callback tanpa `bind` atau arrow function (lihat 5.1).
- Lupa memanggil `super()` di constructor class turunan.
- Membuat hierarki pewarisan terlalu dalam.
- Memakai arrow function sebagai method objek yang memakai `this`.

## Bab 6. Modul ES dan Pengelolaan Paket

### Tujuan belajar

- memakai `import` dan `export` (ES Modules),
- membedakan ESM dan CommonJS, serta tahu cara keduanya berinteraksi,
- memakai _dynamic import_, _top-level await_, dan `import.meta`,
- mengelola dependensi dengan npm dan memahami _semantic versioning_.

### 6.1 Mengapa butuh modul?

Proyek backend berisi puluhan sampai ribuan file. **Modul** memecah kode menjadi file-file kecil dengan tanggung jawab jelas, dan hanya membagikan apa yang memang perlu dibagikan.

Ada dua sistem modul di Node.js:

|Aspek|ES Modules (ESM)|CommonJS (CJS)|
|---|---|---|
|Sintaks|`import` / `export`|`require()` / `module.exports`|
|Standar|Standar bahasa JavaScript|Khusus Node.js (lama)|
|Aktif jika|`"type": "module"` atau ekstensi `.mjs`|Default tanpa `type`, atau ekstensi `.cjs`|
|Top-level `await`|Bisa|Tidak bisa|
|Untuk proyek baru|Direkomendasikan|Hanya untuk kode lama|

Buku ini memakai **ESM**.

### 6.2 Export dan import

```js
// src/matematika.js

// Named export: bisa banyak per file
export const PI = 3.14159;
export function luasLingkaran(r) {
  return PI * r * r;
}

// Default export: maksimal satu per file
export default function keliling(r) {
  return 2 * PI * r;
}
```

```js
// src/index.js
import keliling, { PI, luasLingkaran } from "./matematika.js";
import { luasLingkaran as luas } from "./matematika.js"; // ganti nama
import * as mat from "./matematika.js";                  // ambil semuanya

console.log(luas(2));
console.log(mat.PI);
console.log(keliling(2));
```

Hal penting yang sering membuat pemula bingung:

1. **Path relatif wajib menyertakan ekstensi** `.js`: tulis `"./matematika.js"`, bukan `"./matematika"`.
2. Path yang diawali `./` atau `../` adalah file milik Anda. Nama tanpa awalan (misalnya `"express"`) berarti paket dari `node_modules`.
3. Modul bawaan Node.js sebaiknya ditulis dengan awalan `node:` agar jelas bukan paket luar: `import fs from "node:fs/promises"`.

**Saran gaya:** lebih baik pakai _named export_ daripada _default export_. Nama yang konsisten memudahkan pencarian dan _refactoring_.

**Re-export** berguna untuk membuat pintu masuk tunggal (sering dinamai `index.js`):

```js
// src/layanan/index.js
export { LayananPesanan } from "./pesanan.js";
export { LayananUser } from "./user.js";
```

### 6.3 Dynamic import dan top-level await

`import` statis harus ada di bagian atas file. Jika modul baru dimuat saat dibutuhkan, pakai **dynamic import** yang mengembalikan _promise_:

```js
if (process.env.MODE === "debug") {
  const { aktifkanDebug } = await import("./debug.js");
  aktifkanDebug();
}
```

Perhatikan kata `await` di luar fungsi apa pun: itulah **top-level await**, fitur yang hanya tersedia di ESM. Praktis untuk inisialisasi di awal aplikasi (misalnya membaca konfigurasi atau membuka koneksi).

### 6.4 import.meta dan file JSON

Di ESM tidak ada variabel `__dirname` dan `__filename` seperti di CommonJS. Gantinya:

```js
import path from "node:path";

console.log(import.meta.url);       // URL file ini: file:///.../index.js
console.log(import.meta.dirname);   // folder file ini
console.log(import.meta.filename);  // path lengkap file ini

// Membentuk path yang aman terhadap lokasi menjalankan program
const fileData = path.join(import.meta.dirname, "data", "produk.json");
```

Mengimpor file JSON langsung memakai _import attributes_:

```js
import konfigurasi from "./konfigurasi.json" with { type: "json" };
console.log(konfigurasi.namaAplikasi);
```

### 6.5 Interoperabilitas ESM dan CommonJS

Anda akan sering bertemu paket lama (CJS). Kabar baiknya:

- **ESM dapat mengimpor paket CJS** dengan `import`. Biasanya lancar.
- **CJS dapat me-`require` modul ESM** pada Node.js versi modern (fitur `require(esm)` sudah aktif tanpa flag sejak Node.js 22.12), selama modul ESM tersebut tidak memakai top-level `await`.

Jadi Anda tidak perlu khawatir memilih ESM untuk proyek baru.

### 6.6 Mengelola paket dengan npm

```bash
npm install express           # pasang paket, masuk ke "dependencies"
npm install -D eslint         # pasang khusus pengembangan ("devDependencies")
npm uninstall express         # hapus paket
npm update                    # perbarui sesuai aturan versi
npm outdated                  # lihat paket yang sudah punya versi baru
npm audit                     # periksa kerentanan keamanan yang diketahui
npm ci                        # pasang persis sesuai package-lock.json (untuk CI/produksi)
npx eslint .                  # jalankan alat dari paket tanpa memasang global
```

Beberapa konsep penting:

- **`dependencies`**: paket yang dibutuhkan aplikasi saat berjalan di produksi.
- **`devDependencies`**: paket hanya untuk pengembangan (pengujian, linter, formatter).
- **`package-lock.json`**: mengunci versi persis semua paket (termasuk dependensi dari dependensi). **Wajib di-commit ke Git** supaya semua orang dan server produksi memakai versi yang sama.
- **`node_modules/`**: tempat paket diunduh. **Jangan di-commit**; masukkan ke `.gitignore`.

**Semantic Versioning (semver)** memakai format `MAJOR.MINOR.PATCH`, misalnya `4.18.2`:

|Bagian|Naik jika|Contoh|
|---|---|---|
|MAJOR|Ada perubahan yang merusak kompatibilitas|4.x.x menjadi 5.0.0|
|MINOR|Ada fitur baru yang kompatibel|4.17.x menjadi 4.18.0|
|PATCH|Perbaikan bug yang kompatibel|4.18.1 menjadi 4.18.2|

Di `package.json`, tanda `^4.18.2` berarti "boleh naik ke versi minor/patch terbaru selama masih 4.x.x", sedangkan `~4.18.2` berarti "hanya patch terbaru dalam 4.18.x".

### 6.7 Memilih paket dengan bijak

Setiap paket yang Anda pasang adalah kode orang lain yang berjalan di server Anda. Sebelum memasang, periksa:

- apakah masih dirawat (rilis terakhir, isu terbuka),
- jumlah unduhan dan reputasi,
- ukuran dan jumlah dependensinya,
- apakah fitur itu sebenarnya sudah tersedia bawaan di Node.js (misalnya `fetch`, `node:test`, `--watch`, `crypto.randomUUID`).

Semakin sedikit dependensi, semakin kecil permukaan risiko keamanan dan semakin mudah perawatannya.

### Kesalahan umum

- Lupa ekstensi `.js` pada import relatif: `Cannot find module`.
- Mencampur `require` dan `import` dalam satu file ESM: `require is not defined`.
- Memakai `__dirname` di ESM: `__dirname is not defined`. Pakai `import.meta.dirname`.
- Membuat _circular dependency_ (A mengimpor B, B mengimpor A). Cara mengatasinya: pindahkan kode bersama ke modul ketiga.
- Tidak meng-commit `package-lock.json`.

## Bab 7. Pemrograman Asynchronous

### Tujuan belajar

- menjelaskan mengapa backend membutuhkan pemrograman asynchronous,
- memahami _event loop_, _call stack_, dan perbedaan _microtask_ dengan _macrotask_,
- memakai `Promise` dan `async`/`await` dengan benar,
- menjalankan tugas secara paralel dengan `Promise.all` dan kawan-kawannya,
- menangani _timeout_ dan pembatalan dengan `AbortController`.

Ini bab terpenting di buku ini. Hampir semua pekerjaan backend (membaca database, memanggil API lain, membaca file) bersifat asynchronous.

### 7.1 Masalahnya: menunggu itu lambat

Bayangkan sebuah kedai kopi dengan **satu kasir**.

- **Cara sinkron (blocking):** kasir menerima pesanan, lalu berdiri menunggu kopi selesai dibuat sebelum melayani pelanggan berikutnya. Antrean mengular.
- **Cara asinkron (non-blocking):** kasir menerima pesanan, menyerahkan ke barista, lalu langsung melayani pelanggan berikutnya. Saat kopi jadi, barista memanggil nama pelanggan.

Node.js bekerja seperti cara kedua. Ia menjalankan kode JavaScript Anda di **satu thread** (satu kasir), tetapi pekerjaan yang lambat (membaca file, query database, panggilan jaringan) diserahkan ke sistem operasi (barista), dan hasilnya diproses kemudian. Karena itu satu server Node.js dapat melayani ribuan koneksi bersamaan.

Konsekuensinya: **jangan pernah memblokir thread utama.** Satu perhitungan berat yang memakan 5 detik akan membuat _seluruh_ pengguna menunggu 5 detik.

### 7.2 Event loop

Komponen-komponennya:

1. **Call stack**: tumpukan fungsi yang sedang dieksekusi. Satu per satu.
2. **API asinkron (libuv/sistem operasi)**: mengerjakan tugas lambat di luar JavaScript.
3. **Antrean (queue)**: tempat _callback_ menunggu giliran.
4. **Event loop**: pengulang tak berujung yang memeriksa, "Apakah call stack kosong? Jika ya, ambil callback berikutnya dari antrean dan jalankan."

Ada dua jenis antrean utama:

|Antrean|Diisi oleh|Prioritas|
|---|---|---|
|**Microtask**|`Promise.then`, `await`, `queueMicrotask`|Tinggi: dikosongkan seluruhnya sebelum lanjut|
|**Macrotask**|`setTimeout`, `setInterval`, `setImmediate`, I/O|Lebih rendah: satu per giliran|

Buktikan sendiri:

```js
console.log("1. mulai");

setTimeout(() => console.log("4. setTimeout (macrotask)"), 0);

Promise.resolve().then(() => console.log("3. promise (microtask)"));

console.log("2. selesai");
```

Urutan keluaran: 1, 2, 3, 4. Meskipun `setTimeout` diberi jeda 0 ms, callback-nya tetap menunggu semua kode sinkron dan semua microtask selesai lebih dulu.

### 7.3 Callback dan masalahnya

Cara paling tua menangani hasil asinkron adalah **callback**. Konvensi Node.js: parameter pertama callback adalah error (_error-first callback_).

```js
import fs from "node:fs";

fs.readFile("data.txt", "utf8", (err, isi) => {
  if (err) {
    console.error("Gagal membaca:", err.message);
    return;
  }
  console.log(isi);
});
```

Jika beberapa langkah asinkron harus berurutan, callback bersarang semakin dalam (dijuluki _callback hell_ atau _pyramid of doom_):

```js
baca(a, (err, x) => {
  proses(x, (err, y) => {
    simpan(y, (err, z) => {
      // makin ke kanan, makin sulit dibaca dan sulit menangani error
    });
  });
});
```

Solusinya: **Promise**.

### 7.4 Promise

**Promise** adalah objek yang mewakili hasil operasi asinkron yang **akan selesai di masa depan**. Analogi: struk antrean kopi. Struk itu belum berisi kopi, tetapi menjanjikan kopi nanti, atau kabar bahwa pesanan gagal.

Sebuah promise berada di salah satu dari tiga keadaan:

- **pending**: belum selesai,
- **fulfilled**: berhasil, membawa nilai,
- **rejected**: gagal, membawa alasan (error).

```js
function tunggu(ms, nilai) {
  return new Promise((resolve, reject) => {
    if (ms < 0) return reject(new RangeError("ms tidak boleh negatif"));
    setTimeout(() => resolve(nilai), ms);
  });
}

tunggu(500, "selesai")
  .then((hasil) => {
    console.log(hasil);         // "selesai"
    return hasil.toUpperCase(); // nilai yang di-return dilempar ke then berikutnya
  })
  .then((huruf) => console.log(huruf)) // "SELESAI"
  .catch((err) => console.error("Gagal:", err.message))
  .finally(() => console.log("selalu dijalankan"));
```

Node.js sudah menyediakan versi promise untuk banyak modul bawaan, jadi Anda jarang perlu membuat `new Promise` sendiri:

```js
import fs from "node:fs/promises";
import { setTimeout as tidur } from "node:timers/promises";

const isi = await fs.readFile("data.txt", "utf8");
await tidur(1000); // menunggu 1 detik tanpa memblokir program
```

### 7.5 async dan await

`async`/`await` adalah cara menulis kode promise agar terlihat seperti kode sinkron biasa.

- Fungsi bertanda `async` **selalu mengembalikan Promise**.
- `await` menghentikan sementara _fungsi itu_ (bukan seluruh program) sampai promise selesai, lalu memberikan nilainya.
- `await` hanya boleh dipakai di dalam fungsi `async` atau di level atas modul ESM.

```js
async function ambilUser(id) {
  const res = await fetch(`https://api.example.com/users/${id}`);
  if (!res.ok) {
    throw new Error(`Permintaan gagal dengan status ${res.status}`);
  }
  return res.json();
}

async function main() {
  try {
    const user = await ambilUser(1);
    console.log(user.nama);
  } catch (err) {
    console.error("Terjadi masalah:", err.message);
  } finally {
    console.log("selesai");
  }
}

main();
```

Catatan penting tentang `fetch`: promise-nya **hanya gagal jika jaringan bermasalah**. Jika server membalas 404 atau 500, `fetch` tetap sukses. Karena itu selalu cek `res.ok`.

### 7.6 Berurutan versus paralel

Ini sumber masalah performa nomor satu bagi pemula.

```js
// LAMBAT: berurutan. Total waktu = 1 + 1 + 1 = 3 detik
const a = await ambilData("a"); // menunggu 1 detik
const b = await ambilData("b"); // menunggu 1 detik
const c = await ambilData("c"); // menunggu 1 detik

// CEPAT: paralel. Total waktu = sekitar 1 detik
const [a2, b2, c2] = await Promise.all([
  ambilData("a"),
  ambilData("b"),
  ambilData("c"),
]);
```

Gunakan cara berurutan **hanya jika** langkah berikutnya butuh hasil langkah sebelumnya. Jika tugasnya saling bebas, jalankan paralel.

**Kesalahan umum: `forEach` dengan `async`.** `forEach` tidak menunggu promise:

```js
// SALAH: forEach tidak menunggu, "selesai" tercetak lebih dulu
ids.forEach(async (id) => {
  await simpanKeDb(id);
});
console.log("selesai");

// BENAR (berurutan): pakai for...of
for (const id of ids) {
  await simpanKeDb(id);
}

// BENAR (paralel): map + Promise.all
await Promise.all(ids.map((id) => simpanKeDb(id)));
```

### 7.7 Kombinator promise

|Metode|Perilaku|Cocok untuk|
|---|---|---|
|`Promise.all([...])`|Menunggu semua berhasil; gagal cepat jika ada satu yang gagal|Semua hasil dibutuhkan|
|`Promise.allSettled([...])`|Menunggu semua selesai, berhasil atau gagal; tidak pernah reject|Ingin laporan per tugas|
|`Promise.race([...])`|Hasil dari promise yang selesai **pertama** (berhasil atau gagal)|Timeout manual|
|`Promise.any([...])`|Hasil dari yang **berhasil** pertama; reject jika semua gagal|Mencoba beberapa sumber cadangan|

```js
const hasil = await Promise.allSettled([
  ambilData("a"),
  Promise.reject(new Error("rusak")),
  ambilData("c"),
]);

for (const h of hasil) {
  if (h.status === "fulfilled") console.log("OK:", h.value);
  else console.log("Gagal:", h.reason.message);
}
```

Dua tambahan modern yang berguna:

```js
// Promise.withResolvers: membuat promise dengan resolve/reject di luar
const { promise, resolve, reject } = Promise.withResolvers();
setTimeout(() => resolve("siap"), 100);
console.log(await promise);

// Promise.try (Node 24 ke atas): menjalankan fungsi (sinkron atau async)
// dan membungkus error sinkronnya menjadi promise yang ditolak
const hasilTry = await Promise.try(() => JSON.parse('{"a":1}'));
```

### 7.8 Membatasi jumlah tugas paralel

`Promise.all` dengan 10.000 tugas sekaligus dapat membanjiri database atau API tujuan. Solusi sederhana: proses per kelompok (_batch_).

```js
async function prosesBerkelompok(items, ukuran, kerjakan) {
  const hasil = [];
  for (let i = 0; i < items.length; i += ukuran) {
    const kelompok = items.slice(i, i + ukuran);
    const hasilKelompok = await Promise.all(kelompok.map(kerjakan));
    hasil.push(...hasilKelompok);
  }
  return hasil;
}

// 100 tugas, tetapi hanya 10 berjalan bersamaan
await prosesBerkelompok(daftarId, 10, (id) => ambilUser(id));
```

Untuk kebutuhan yang lebih canggih, paket seperti `p-limit` dapat dipakai.

### 7.9 Timeout, pembatalan, dan retry

Panggilan ke layanan lain **bisa menggantung**. Server yang baik selalu memasang batas waktu.

```js
// Timeout sederhana untuk fetch
try {
  const res = await fetch("https://api.example.com/lambat", {
    signal: AbortSignal.timeout(3000), // batalkan setelah 3 detik
  });
  console.log(await res.json());
} catch (err) {
  if (err.name === "TimeoutError") console.error("Terlalu lama, dibatalkan");
  else throw err;
}
```

Pembatalan manual dengan `AbortController`:

```js
const kontrol = new AbortController();
const janji = fetch("https://api.example.com/data", { signal: kontrol.signal });

// misalnya pengguna menutup koneksi atau menekan "batal"
kontrol.abort();
// janji akan ditolak dengan AbortError
```

**Retry dengan exponential backoff**: mengulang percobaan dengan jeda yang makin lama, pola yang sangat umum untuk memanggil layanan eksternal:

```js
import { setTimeout as tidur } from "node:timers/promises";

async function coba(fn, { percobaan = 3, jedaAwal = 200 } = {}) {
  let errorTerakhir;
  for (let i = 0; i < percobaan; i++) {
    try {
      return await fn();
    } catch (err) {
      errorTerakhir = err;
      await tidur(jedaAwal * 2 ** i); // 200ms, 400ms, 800ms, ...
    }
  }
  throw new Error(`Gagal setelah ${percobaan} percobaan`, { cause: errorTerakhir });
}

const user = await coba(() => ambilUser(1));
```

### 7.10 Async iteration

Untuk data yang datang bertahap (halaman demi halaman, baris demi baris), pakai `for await...of`:

```js
import fs from "node:fs";
import readline from "node:readline";

const baris = readline.createInterface({
  input: fs.createReadStream("log-besar.txt"),
});

for await (const b of baris) {
  if (b.includes("ERROR")) console.log(b);
}
```

Dengan cara ini file berukuran gigabyte dapat diproses tanpa memuat semuanya ke memori. Konsep ini dibahas lebih lanjut di Bab 9 dan 10.

### 7.11 Jangan memblokir event loop

Kode berikut menghentikan seluruh server selama beberapa detik:

```js
function hitungBerat() {
  let total = 0;
  for (let i = 0; i < 5_000_000_000; i++) total += i;
  return total;
}
```

Selama loop ini berjalan, server tidak bisa merespons request apa pun. Solusi untuk pekerjaan berat CPU (kompresi, enkripsi berat, pemrosesan gambar) adalah memindahkannya ke **worker thread** atau proses terpisah (lihat Bab 13). Untuk pekerjaan I/O (database, file, jaringan), `async`/`await` sudah cukup.

### 7.12 Kesalahan umum

- Lupa `await` sehingga yang didapat adalah objek Promise, bukan nilainya (contoh: mencetak `Promise { <pending> }`).
- Memakai `await` berurutan pada tugas yang saling bebas.
- Memakai `forEach` dengan fungsi `async`.
- Tidak menangani penolakan promise (_unhandled rejection_). Pada Node.js modern, ini membuat proses **berhenti dengan error**.
- Membungkus fungsi yang sudah mengembalikan promise dengan `new Promise` lagi (dikenal sebagai _promise constructor anti-pattern_).
- Tidak memberi timeout pada panggilan jaringan.

### Latihan Bab 7

1. Tulis program yang mencetak `"A"` (kode sinkron), lalu mendaftarkan `setTimeout` 0 ms yang mencetak `"D"`, lalu `Promise.resolve().then` yang mencetak `"C"`, lalu mencetak `"B"` (kode sinkron). Prediksi urutan cetaknya sebelum menjalankannya, lalu jelaskan hasilnya.
2. Buat tiga fungsi async yang masing-masing menunggu 500 ms. Ukur waktu total jika dipanggil berurutan dan paralel dengan `console.time` dan `console.timeEnd`.
3. Perbaiki kode `forEach` + `async` di 7.6 dengan dua cara.

5. Tulis fungsi yang membaca 3 file secara paralel dengan `fs.readFile` dan `Promise.all`, dan tetap mengembalikan hasil file yang berhasil walau satu file tidak ada (petunjuk: `Promise.allSettled`).

## Bab 8. Penanganan Error

### Tujuan belajar

- memakai `try`/`catch`/`finally` dengan benar,
- membuat kelas error kustom dan memakai `cause`,
- membedakan _operational error_ dan _programmer error_,
- menangani error pada kode asinkron dan menutup aplikasi dengan rapi.

Di backend, error **pasti** terjadi: database mati, input pengguna salah, jaringan putus. Aplikasi yang baik bukan yang tidak pernah error, melainkan yang menanganinya dengan jelas dan aman.

### 8.1 Dasar try, catch, finally

```js
function bacaJson(teks) {
  try {
    return JSON.parse(teks);
  } catch (err) {
    console.error("JSON tidak valid:", err.message);
    return null;
  } finally {
    console.log("bagian ini selalu dijalankan, ada error ataupun tidak");
  }
}
```

Objek `Error` punya properti penting: `name`, `message`, `stack` (jejak pemanggilan, sangat berguna untuk debugging), dan `cause` (penyebab awal).

Jenis error bawaan yang umum:

|Error|Arti|
|---|---|
|`TypeError`|Tipe salah, misalnya memanggil sesuatu yang bukan fungsi, atau membaca properti dari `undefined`|
|`ReferenceError`|Memakai variabel yang tidak ada|
|`RangeError`|Nilai di luar jangkauan yang diizinkan|
|`SyntaxError`|Sintaks salah (termasuk `JSON.parse` pada teks tidak valid)|

**Selalu lempar objek `Error` (atau turunannya), bukan string.** `throw "gagal"` tidak membawa `stack` sehingga sulit dilacak.

### 8.2 Error kustom

Membuat kelas error sendiri membuat penanganan lebih terstruktur, misalnya untuk memetakan error ke kode status HTTP.

```js
export class AppError extends Error {
  constructor(message, { statusCode = 500, cause, detail } = {}) {
    super(message, { cause });
    this.name = this.constructor.name;
    this.statusCode = statusCode;
    this.detail = detail;
  }
}

export class NotFoundError extends AppError {
  constructor(sumber, id) {
    super(`${sumber} dengan id ${id} tidak ditemukan`, { statusCode: 404 });
  }
}

export class ValidationError extends AppError {
  constructor(message, detail) {
    super(message, { statusCode: 400, detail });
  }
}
```

Pemakaian:

```js
function cariProduk(id, daftar) {
  const p = daftar.find((x) => x.id === id);
  if (!p) throw new NotFoundError("Produk", id);
  return p;
}

try {
  cariProduk(99, []);
} catch (err) {
  if (err instanceof NotFoundError) {
    console.log(err.statusCode, err.message); // 404 Produk dengan id 99 tidak ditemukan
  } else {
    throw err; // error yang tidak dikenal: lempar ulang, jangan ditelan
  }
}
```

### 8.3 Error cause: mempertahankan konteks

Ketika menangkap error lalu melempar error baru yang lebih bermakna, sertakan error asli lewat `cause` agar jejak penyebab tidak hilang:

```js
async function ambilProfil(id) {
  try {
    return await db.query("SELECT * FROM users WHERE id = $1", [id]);
  } catch (err) {
    throw new AppError("Gagal mengambil profil pengguna", {
      statusCode: 500,
      cause: err, // error database asli tetap tersimpan
    });
  }
}
```

### 8.4 Dua jenis error

|Jenis|Contoh|Cara menangani|
|---|---|---|
|**Operational error** (diduga akan terjadi)|Input tidak valid, file tidak ada, timeout jaringan, database sementara mati|Tangani: beri respons yang sesuai, retry, atau laporkan ke pengguna|
|**Programmer error** (bug)|Membaca properti dari `undefined`, salah memanggil fungsi, salah ketik nama variabel|Jangan ditutupi. Perbaiki kodenya. Catat log dan biarkan proses dimulai ulang|

Ingat: jangan gunakan `catch` kosong yang "menelan" error.

```js
// BURUK: error hilang tanpa jejak
try { await proses(); } catch {}

// BAIK: minimal catat lognya
try {
  await proses();
} catch (err) {
  console.error("Proses gagal", err);
  throw err;
}
```

Hindari juga **log-lalu-lempar di setiap lapisan** karena akan menghasilkan log ganda untuk satu error. Cukup catat di satu tempat, biasanya di lapisan paling luar (penanganan error global).

### 8.5 Error pada kode asinkron

Dengan `async`/`await`, `try`/`catch` bekerja normal. Tanpa `await`, error tidak tertangkap:

```js
async function gagal() {
  throw new Error("boom");
}

async function salah() {
  try {
    gagal(); // tanpa await: promise yang ditolak lolos dari catch!
  } catch (err) {
    console.log("tidak pernah sampai sini");
  }
}

async function benar() {
  try {
    await gagal(); // dengan await: error tertangkap
  } catch (err) {
    console.log("tertangkap:", err.message);
  }
}
```

**AggregateError** muncul ketika beberapa error terjadi sekaligus, misalnya pada `Promise.any` jika semua gagal:

```js
try {
  await Promise.any([Promise.reject(new Error("a")), Promise.reject(new Error("b"))]);
} catch (err) {
  console.log(err instanceof AggregateError); // true
  console.log(err.errors.map((e) => e.message)); // ["a", "b"]
}
```

### 8.6 Penjaga terakhir dan graceful shutdown

Untuk error yang lolos dari semua penanganan, Node.js menyediakan _event_ proses:

```js
process.on("unhandledRejection", (alasan) => {
  console.error("Promise ditolak tanpa penanganan:", alasan);
  process.exit(1);
});

process.on("uncaughtException", (err) => {
  console.error("Exception tak tertangkap:", err);
  process.exit(1);
});
```

Setelah `uncaughtException`, kondisi aplikasi sudah tidak dapat dipercaya, sehingga praktik yang aman adalah **mencatat log lalu menghentikan proses**. Proses kemudian dihidupkan kembali oleh pengelola proses (Docker, systemd, Kubernetes, atau PM2).

**Graceful shutdown** adalah menutup server dengan rapi saat menerima sinyal berhenti (misalnya saat deploy), yaitu berhenti menerima request baru, menyelesaikan request yang sedang berjalan, menutup koneksi database, lalu keluar.

```js
function pasangShutdown(server, tutupResource) {
  const berhenti = async (sinyal) => {
    console.log(`Menerima ${sinyal}, menutup server...`);
    server.close(async () => {
      await tutupResource();
      process.exit(0);
    });
    // paksa keluar bila terlalu lama
    setTimeout(() => process.exit(1), 10_000).unref();
  };
  process.on("SIGTERM", () => berhenti("SIGTERM"));
  process.on("SIGINT", () => berhenti("SIGINT"));
}
```

### 8.7 Kesalahan umum

- `throw "teks"` alih-alih `throw new Error("teks")`.
- `catch` kosong yang menelan error.
- Lupa `await` di dalam `try` sehingga error lolos.
- Menampilkan pesan error internal (termasuk `stack` atau detail database) ke pengguna. Kirim pesan umum ke klien, simpan detail di log.
- Melanjutkan aplikasi setelah `uncaughtException`.

## Bab 9. Iterator dan Generator

### Tujuan belajar

- memahami protokol _iterable_ dan _iterator_,
- menulis generator dengan `function*` dan `yield`,
- memakai _iterator helpers_ modern (`map`, `filter`, `take`, dan lainnya),
- memakai _async generator_ untuk data bertahap.

### 9.1 Iterable dan iterator

Sesuatu disebut **iterable** jika bisa dipakai di `for...of`, di-_spread_ (`...`), atau di-_destructure_. Array, string, `Map`, dan `Set` adalah iterable.

```js
for (const huruf of "node") console.log(huruf); // n, o, d, e
const [satu, dua] = new Set(["a", "b", "c"]);
```

Secara teknis, iterable adalah objek yang punya method `[Symbol.iterator]()` yang mengembalikan **iterator**, yaitu objek dengan method `next()` yang mengembalikan `{ value, done }`.

```js
const rentang = {
  awal: 1,
  akhir: 3,
  [Symbol.iterator]() {
    let sekarang = this.awal;
    const akhir = this.akhir;
    return {
      next: () =>
        sekarang <= akhir
          ? { value: sekarang++, done: false }
          : { value: undefined, done: true },
    };
  },
};

console.log([...rentang]); // [1, 2, 3]
```

Menulis ini manual cukup merepotkan. Untuk itu ada generator.

### 9.2 Generator

**Generator** adalah fungsi yang bisa **berhenti sementara** di tengah jalan (`yield`) dan dilanjutkan kemudian. Ditulis dengan `function*`.

```js
function* hitungMundur(dari) {
  while (dari > 0) {
    yield dari; // berhenti di sini, kirim nilai, tunggu dipanggil lagi
    dari--;
  }
  return "selesai";
}

const gen = hitungMundur(3);
gen.next(); // { value: 3, done: false }
gen.next(); // { value: 2, done: false }
gen.next(); // { value: 1, done: false }
gen.next(); // { value: "selesai", done: true }

console.log([...hitungMundur(3)]); // [3, 2, 1]
```

Keunggulan utama: **lazy evaluation**. Nilai baru dihitung saat diminta. Ini memungkinkan urutan tak berhingga tanpa menghabiskan memori:

```js
function* idBerurutan(mulai = 1) {
  let id = mulai;
  while (true) yield id++;
}

const generator = idBerurutan(100);
generator.next().value; // 100
generator.next().value; // 101
```

### 9.3 Iterator helpers

Iterator modern punya method rantai seperti array, tetapi tetap _lazy_ dan tidak membuat array antara. Tersedia di Node.js 22 ke atas.

```js
function* angkaTakHingga() {
  let n = 1;
  while (true) yield n++;
}

const hasil = angkaTakHingga()
  .filter((n) => n % 2 === 0)  // genap saja
  .map((n) => n * n)           // kuadratkan
  .take(5)                     // ambil 5 pertama
  .toArray();                  // ubah menjadi array

console.log(hasil); // [4, 16, 36, 64, 100]
```

Method yang tersedia: `map`, `filter`, `take`, `drop`, `flatMap`, `reduce`, `toArray`, `forEach`, `some`, `every`, `find`. Untuk mengubah iterable apa saja menjadi iterator yang punya method ini, pakai `Iterator.from(iterable)`. Contoh: `new Set([1, 2, 3]).values().map(x => x * 2)`.

**(Node 26+)** `Iterator.concat()` menyambung beberapa iterable menjadi satu tanpa membuat array perantara:

```js
const gabungan = Iterator.concat([1, 2], new Set([3, 4])).toArray(); // [1, 2, 3, 4]
```

### 9.4 Async generator dan for await

Jika sumber datanya asinkron (misalnya API yang berhalaman-halaman), gunakan **async generator**: `async function*`.

```js
async function* ambilSemuaProduk(ambilHalaman) {
  let halaman = 1;
  while (true) {
    const data = await ambilHalaman(halaman);
    if (data.length === 0) return; // tidak ada data lagi, berhenti
    yield* data;                   // keluarkan item satu per satu
    halaman++;
  }
}

// Simulasi API dengan 3 halaman
const semuaData = [[1, 2], [3, 4], [5]];
const ambilHalaman = async (n) => semuaData[n - 1] ?? [];

for await (const produk of ambilSemuaProduk(ambilHalaman)) {
  console.log("proses produk", produk);
  if (produk === 3) break; // bisa berhenti kapan saja, halaman sisa tidak diambil
}
```

Keuntungannya: pemanggil menulis satu loop sederhana, sedangkan detail paginasi tersembunyi di dalam generator. Data juga hanya diambil saat dibutuhkan.

Untuk mengumpulkan hasil async iterable ke array, ada `Array.fromAsync`:

```js
const semua = await Array.fromAsync(ambilSemuaProduk(ambilHalaman)); // [1, 2, 3, 4, 5]
```

## Bab 10. Node.js Inti untuk Backend

### Tujuan belajar

### 10.1 Modul bawaan yang wajib dikenal

|Modul|Fungsi utama|

|`node:path`|Menyusun dan memecah path file lintas sistem operasi|

|`node:timers/promises`|`setTimeout` dan kawan-kawan versi promise|

### 10.2 Bekerja dengan file dan path

```js
import fs from "node:fs/promises";
import path from "node:path";

const folder = path.join(import.meta.dirname, "data");
const berkas = path.join(folder, "catatan.txt");

// Buat folder jika belum ada (recursive: tidak error bila sudah ada)
await fs.mkdir(folder, { recursive: true });

// Tulis dan baca
await fs.writeFile(berkas, "Baris pertama\n", "utf8");
await fs.appendFile(berkas, "Baris kedua\n", "utf8");
const isi = await fs.readFile(berkas, "utf8");
console.log(isi);

// Daftar isi folder dan informasi file
const daftar = await fs.readdir(folder);
const info = await fs.stat(berkas);
console.log(daftar, info.size, info.isFile());
```

**Selalu pakai `path.join` atau `path.resolve`**, jangan menyambung path dengan `+` atau `"/"`. Pemisah path berbeda antar sistem operasi (`/` di Linux/macOS, `\` di Windows).

Menangani file yang tidak ada:

```js
async function bacaJikaAda(berkas) {
  try {
    return await fs.readFile(berkas, "utf8");
  } catch (err) {
    if (err.code === "ENOENT") return null; // file tidak ditemukan
    throw err;                              // error lain tetap dilempar
  }
}
```

Kode error yang sering muncul: `ENOENT` (tidak ada), `EACCES` (tidak punya izin), `EEXIST` (sudah ada), `EADDRINUSE` (port sudah dipakai).

**Menulis file secara atomik.** Jika proses mati di tengah `writeFile`, file bisa rusak setengah jadi. Praktik aman: tulis ke file sementara, lalu ganti nama (operasi rename bersifat atomik):

```js
async function tulisAtomik(berkas, teks) {
  const sementara = `${berkas}.${process.pid}.tmp`;
  await fs.writeFile(sementara, teks, "utf8");
  await fs.rename(sementara, berkas);
}
```

### 10.3 Objek process

`process` menyediakan informasi dan kendali atas program yang sedang berjalan:

```js
process.argv;            // argumen baris perintah: [node, file, ...argumenAnda]
process.env.PORT;        // variabel lingkungan (selalu string)
process.cwd();           // folder kerja saat ini
process.pid;             // ID proses
process.uptime();        // lama proses berjalan (detik)
process.memoryUsage();   // pemakaian memori
process.exitCode = 1;    // kode keluar saat program selesai wajar
process.exit(1);         // keluar SEGERA (hati-hati, memotong pekerjaan yang tertunda)
```

Untuk membaca argumen baris perintah dengan rapi, pakai `parseArgs` bawaan:

```js
import { parseArgs } from "node:util";

const { values } = parseArgs({
  options: {
    port: { type: "string", short: "p", default: "3000" },
    verbose: { type: "boolean", short: "v" },
  },
});
// node app.js --port 8080 -v  ->  values = { port: "8080", verbose: true }
```

### 10.4 EventEmitter

Banyak objek di Node.js (server HTTP, stream, proses) bekerja dengan pola **event**: satu pihak "memancarkan" (_emit_) event, pihak lain "mendengarkan" (_listen_).

```js
import { EventEmitter } from "node:events";

class TokoOnline extends EventEmitter {
  buatPesanan(pesanan) {
    // ... simpan pesanan
    this.emit("pesananDibuat", pesanan);
  }
}

const toko = new TokoOnline();

toko.on("pesananDibuat", (p) => console.log("Kirim email untuk pesanan", p.id));
toko.on("pesananDibuat", (p) => console.log("Kurangi stok untuk pesanan", p.id));
toko.once("pesananDibuat", () => console.log("Hanya dijalankan sekali"));

toko.buatPesanan({ id: 101 });
```

Keuntungannya: kode yang membuat pesanan tidak perlu tahu siapa saja yang berkepentingan. Aturan penting: event bernama `"error"` bersifat khusus. Jika di-_emit_ tanpa ada pendengar, Node.js akan melempar error dan menghentikan proses. Selalu pasang `.on("error", ...)` pada emitter yang bisa gagal.

### 10.5 Buffer dan Stream

**Buffer** adalah potongan memori yang menyimpan data biner mentah (byte). Anda menemuinya saat berurusan dengan file, jaringan, atau enkripsi.

```js
const buf = Buffer.from("Halo", "utf8");
console.log(buf);                    // <Buffer 48 61 6c 6f>
console.log(buf.toString("hex"));    // "48616c6f"
console.log(buf.toString("base64")); // "SGFsbw=="
```

**Stream** adalah cara memproses data **sepotong demi sepotong**, tidak menunggu seluruh data terkumpul. Analogi: mengalirkan air lewat pipa dibandingkan mengangkut seluruh air dengan ember besar.

Mengapa penting? Membaca file 2 GB dengan `readFile` memuat 2 GB ke memori. Dengan stream, memori yang dipakai kecil dan konstan.

```js
import { createReadStream, createWriteStream } from "node:fs";
import { createGzip } from "node:zlib";
import { pipeline } from "node:stream/promises";

// Baca file besar -> kompres -> tulis ke file baru, tanpa memuat semuanya ke memori
await pipeline(
  createReadStream("log-besar.txt"),
  createGzip(),
  createWriteStream("log-besar.txt.gz")
);
```

Selalu pakai `pipeline` (bukan `.pipe()`) karena ia menangani error dan membersihkan resource dengan benar. Ada empat jenis stream: _Readable_ (sumber), _Writable_ (tujuan), _Duplex_ (dua arah), dan _Transform_ (mengubah data di tengah jalan, seperti `createGzip`).

### 10.6 Server HTTP pertama

```js
import http from "node:http";

const server = http.createServer((req, res) => {
  console.log(req.method, req.url);

  if (req.method === "GET" && req.url === "/halo") {
    res.writeHead(200, { "Content-Type": "application/json; charset=utf-8" });
    res.end(JSON.stringify({ pesan: "Halo dari Node.js" }));
    return;
  }

  res.writeHead(404, { "Content-Type": "application/json; charset=utf-8" });
  res.end(JSON.stringify({ error: "Tidak ditemukan" }));
});

const port = Number(process.env.PORT ?? 3000);
server.listen(port, () => console.log(`Server di http://localhost:${port}`));
```

Jalankan, lalu buka `http://localhost:3000/halo` di browser atau uji dengan `curl`.

Konsep HTTP yang harus Anda kuasai sebagai backend developer:

|Konsep|Penjelasan|
|---|---|
|**Method**|`GET` (baca), `POST` (buat), `PUT`/`PATCH` (ubah), `DELETE` (hapus)|
|**Status code**|`200` OK, `201` Created, `400` input salah, `401` belum login, `403` dilarang, `404` tidak ada, `409` konflik, `500` error server|
|**Header**|Metadata request/response, misalnya `Content-Type`, `Authorization`|
|**Body**|Isi data yang dikirim (biasanya JSON pada API modern)|
|**Query string**|Parameter di URL: `/produk?kategori=minuman&halaman=2`|

Membaca body JSON dari request (stream sederhana yang dikumpulkan):

```js
async function bacaBodyJson(req) {
  const potongan = [];
  for await (const p of req) potongan.push(p); // req adalah async iterable
  const teks = Buffer.concat(potongan).toString("utf8");
  return teks ? JSON.parse(teks) : {};
}
```

Pada praktiknya, kebanyakan tim memakai framework seperti **Express**, **Fastify**, atau **Hono** di atas `node:http`. Framework menghemat pekerjaan berulang, tetapi mengerti dasarnya seperti di atas membuat Anda tidak sekadar "menghafal framework". Kita akan membangun API lengkap tanpa framework di Bab 15.

### 10.7 Memanggil API lain dengan fetch


### 10.8 Modul crypto

```js
import { randomUUID, randomBytes, createHash } from "node:crypto";

randomUUID();                                   // "3b241101-e2bb-4255-8caf-4136c566a962"
randomBytes(32).toString("hex");                // token acak yang aman
createHash("sha256").update("halo").digest("hex"); // hash SHA-256
```

**Peringatan keras tentang password.** Jangan pernah menyimpan password apa adanya, dan jangan memakai hash cepat seperti MD5 atau SHA-256 polos untuk password. Gunakan algoritma yang **sengaja lambat** dan memakai _salt_ acak, misalnya `scrypt` (bawaan Node.js), `bcrypt`, atau `argon2`.

```js
import { scrypt, randomBytes, timingSafeEqual } from "node:crypto";
import { promisify } from "node:util";

const scryptAsync = promisify(scrypt);

export async function hashPassword(password) {
  const salt = randomBytes(16);
  const hash = await scryptAsync(password, salt, 64);
  return `${salt.toString("hex")}:${hash.toString("hex")}`;
}

export async function cekPassword(password, tersimpan) {
  const [saltHex, hashHex] = tersimpan.split(":");
  const hash = await scryptAsync(password, Buffer.from(saltHex, "hex"), 64);
  return timingSafeEqual(hash, Buffer.from(hashHex, "hex"));
}
```

`timingSafeEqual` membandingkan dalam waktu konstan sehingga tidak bocor informasi lewat selisih waktu respons.

- Lupa memasang listener `"error"` pada `EventEmitter` atau stream.
- Menyimpan password dengan hash cepat atau tanpa salt.
- Memakai `process.exit()` secara sembarangan sehingga log atau respons yang tertunda terpotong.

## Bab 11. Tanggal, Waktu, Angka, dan JSON

### Tujuan belajar

- menyadari jebakan objek `Date` dan mengenal **Temporal API** sebagai penggantinya,
- menangani angka desimal dan uang dengan benar,
- memakai `Intl` untuk format tanggal dan mata uang Indonesia,
- membaca, menulis, dan memvalidasi JSON dengan aman.

Empat hal ini (waktu, angka, format, JSON) adalah sumber bug yang paling sering muncul di aplikasi bisnis.

### 11.1 Objek Date dan jebakannya

```js
const sekarang = new Date();
sekarang.toISOString();    // "2026-09-29T03:15:00.000Z"  (selalu UTC)
sekarang.getTime();        // milidetik sejak 1 Januari 1970 UTC (timestamp)
Date.now();                // sama, tanpa membuat objek

new Date(2026, 0, 31);     // Bulan dihitung dari 0! Ini 31 JANUARI 2026
new Date(2026, 1, 31);     // Februari tidak punya tanggal 31 -> menjadi 3 Maret 2026
```

Jebakan `Date` yang sering menimbulkan bug:

- Bulan dimulai dari **0**, bukan 1.
- Objek `Date` **bisa diubah** (_mutable_): `tanggal.setDate(...)` mengubah objek aslinya.
- Zona waktu membingungkan: `new Date("2026-01-15")` dianggap UTC, tetapi `new Date("2026-01-15T00:00:00")` dianggap waktu lokal server.
- Tidak ada konsep "hanya tanggal" atau "hanya jam".

**Aturan emas backend: simpan dan kirim waktu dalam UTC dengan format ISO 8601** (contoh `2026-09-29T03:15:00Z`), lalu ubah ke zona waktu pengguna hanya saat ditampilkan. Jangan menyimpan "jam lokal" di database.

Menghitung tanggal dengan `Date` memang bisa, tetapi merepotkan:

```js
const tigaHariLagi = new Date(Date.now() + 3 * 24 * 60 * 60 * 1000);
// Salah jika ada pergantian jam musim panas, dan tidak jelas dibaca
```

### 11.2 Temporal API (Node 26+)

**Temporal** adalah API tanggal dan waktu modern yang dirancang untuk menggantikan `Date`. Sejak Node.js 26, Temporal aktif secara default (tanpa flag). Di Node.js 24 atau lebih lama, Anda dapat memakai paket _polyfill_ seperti `@js-temporal/polyfill`, dengan API yang sama.

Keunggulannya: **tidak bisa diubah** (setiap operasi mengembalikan nilai baru), zona waktu eksplisit, bulan dimulai dari 1, dan ada tipe terpisah untuk kebutuhan berbeda.

|Tipe|Untuk apa|Contoh|
|---|---|---|
|`Temporal.Instant`|Satu titik waktu absolut (seperti timestamp)|Waktu kejadian di log, `createdAt`|
|`Temporal.PlainDate`|Tanggal saja, tanpa jam dan zona|Tanggal lahir, jatuh tempo|
|`Temporal.PlainTime`|Jam saja|Jam buka toko|
|`Temporal.ZonedDateTime`|Tanggal dan jam di zona waktu tertentu|Jadwal rapat di Jakarta|
|`Temporal.Duration`|Selisih atau rentang waktu|2 jam 30 menit|

```js
// Titik waktu absolut saat ini
const sekarang = Temporal.Now.instant();
console.log(sekarang.toString()); // "2026-09-29T03:15:00.123456789Z"

// Tanggal saja
const jatuhTempo = Temporal.PlainDate.from("2026-01-31");
console.log(jatuhTempo.add({ months: 1 }).toString()); // "2026-02-28" (menyesuaikan akhir bulan)

// Waktu di zona tertentu
const rapat = Temporal.ZonedDateTime.from("2026-10-05T09:00[Asia/Jakarta]");
console.log(rapat.withTimeZone("UTC").toString());
// "2026-10-05T02:00:00+00:00[UTC]"

// Durasi
const lama = Temporal.Duration.from({ hours: 2, minutes: 30 });
console.log(lama.total({ unit: "minutes" })); // 150

// Selisih dua tanggal
const a = Temporal.PlainDate.from("2026-09-29");
const b = Temporal.PlainDate.from("2026-12-25");
console.log(a.until(b).days); // 87

// Membandingkan
Temporal.PlainDate.compare(a, b); // -1 (a lebih awal), 0 (sama), 1 (a lebih akhir)
```

Pola praktis di backend: simpan `Instant` (atau string ISO UTC) di database, dan pakai `ZonedDateTime` hanya saat perlu menampilkan atau menghitung dalam konteks zona waktu tertentu (misalnya "besok jam 9 pagi WIB").

### 11.3 Angka: jebakan floating point

Semua angka JavaScript adalah _floating point_ 64-bit, sehingga ada ketidaktepatan:

```js
0.1 + 0.2;                 // 0.30000000000000004
0.1 + 0.2 === 0.3;         // false
(0.1 + 0.2).toFixed(2);    // "0.30"  (hasilnya string!)
Number.MAX_SAFE_INTEGER;   // 9007199254740991, di atas ini angka tidak akurat lagi
```

**Untuk uang, jangan pakai desimal floating point.** Simpan dalam **satuan terkecil sebagai bilangan bulat** (misalnya sen), lalu hitung dengan bilangan bulat:

```js
// Rp19.990,50 disimpan sebagai 1999050 sen
const hargaSen = 1_999_050;
const jumlah = 3;
const totalSen = hargaSen * jumlah; // aman: bilangan bulat
```

Untuk rupiah yang praktis tanpa pecahan, simpan dalam rupiah bulat. Untuk sistem keuangan yang serius, pakai kolom `DECIMAL`/`NUMERIC` di database dan pustaka desimal seperti `decimal.js`, atau `BigInt`.

**BigInt** untuk bilangan bulat sangat besar (ID dari sistem lain, misalnya):

```js
const besar = 9007199254740993n;   // akhiran n
besar + 1n;                        // 9007199254740994n
// besar + 1                       // TypeError: tidak boleh dicampur dengan Number
BigInt("123456789012345678901234567890");
```

Catatan: `JSON.stringify` melempar error pada `BigInt`. Kirim sebagai string.

### 11.4 Format Indonesia dengan Intl

`Intl` adalah pustaka bawaan untuk format berbasis bahasa dan wilayah:

```js
const rupiah = new Intl.NumberFormat("id-ID", {
  style: "currency",
  currency: "IDR",
  maximumFractionDigits: 0,
});
rupiah.format(1250000);   // "Rp 1.250.000"

new Intl.NumberFormat("id-ID").format(1234567.89); // "1.234.567,89"

const tanggal = new Intl.DateTimeFormat("id-ID", {
  dateStyle: "full",
  timeStyle: "short",
  timeZone: "Asia/Jakarta",
});
tanggal.format(new Date("2026-09-29T03:15:00Z"));
// "Selasa, 29 September 2026 pukul 10.15"

new Intl.RelativeTimeFormat("id-ID", { numeric: "auto" }).format(-1, "day"); // "kemarin"
```

Format tampilan sebaiknya dilakukan sedekat mungkin dengan pengguna (di frontend atau saat membuat respons akhir). Data di database dan di antara layanan tetap dalam bentuk mentah (angka, ISO UTC).

### 11.5 JSON

JSON (_JavaScript Object Notation_) adalah format pertukaran data yang paling umum di API.

```js
const objek = { nama: "Sari", umur: 27, aktif: true, hobi: ["baca", "hiking"] };

const teks = JSON.stringify(objek);        // objek -> string JSON
const rapi = JSON.stringify(objek, null, 2); // dengan indentasi 2 spasi
const balik = JSON.parse(teks);            // string JSON -> objek
```

Aturan JSON yang ketat (lebih ketat dari objek JavaScript):

- kunci **harus** memakai tanda kutip ganda: `{"nama": "Sari"}`,
- tidak boleh ada koma di akhir (_trailing comma_),
- tidak boleh ada komentar,
- nilai hanya: string, angka, boolean, `null`, array, objek.

**Tidak semua tipe selamat melewati JSON:**

```js
JSON.stringify({
  a: undefined,            // dihilangkan
  b: () => {},             // dihilangkan
  c: new Date("2026-01-01T00:00:00Z"), // menjadi string ISO
  d: new Map([[1, 2]]),    // menjadi {}
  e: NaN,                  // menjadi null
});
// '{"c":"2026-01-01T00:00:00.000Z","d":{},"e":null}'
```

Mengendalikan hasil dengan `toJSON`, _replacer_, dan _reviver_:

```js
class User {
  constructor(nama, password) {
    this.nama = nama;
    this.password = password;
  }
  toJSON() {                       // dipanggil otomatis oleh JSON.stringify
    return { nama: this.nama };    // password tidak ikut terkirim
  }
}
JSON.stringify(new User("Sari", "rahasia")); // '{"nama":"Sari"}'

// Replacer berupa array: hanya properti tertentu yang diikutkan
JSON.stringify({ a: 1, b: 2, c: 3 }, ["a", "c"]); // '{"a":1,"c":3}'

// Reviver: mengubah nilai saat parse (misalnya string tanggal -> Date)
JSON.parse('{"dibuat":"2026-01-01T00:00:00.000Z"}', (kunci, nilai) =>
  kunci === "dibuat" ? new Date(nilai) : nilai
);
```

**Jangan pernah percaya data dari luar.** `JSON.parse` bisa gagal pada teks rusak, dan hasil yang sukses belum tentu berbentuk seperti yang Anda harapkan.

```js
function parseBodyAman(teks) {
  let data;
  try {
    data = JSON.parse(teks);
  } catch {
    throw new ValidationError("Body bukan JSON yang valid");
  }
  return data;
}

function validasiProdukBaru(data) {
  const masalah = [];
  if (typeof data?.nama !== "string" || data.nama.trim() === "") {
    masalah.push("nama wajib berupa teks tidak kosong");
  }
  if (!Number.isInteger(data?.harga) || data.harga < 0) {
    masalah.push("harga wajib berupa bilangan bulat tidak negatif");
  }
  if (masalah.length > 0) throw new ValidationError("Data tidak valid", masalah);
  return { nama: data.nama.trim(), harga: data.harga }; // hanya ambil field yang dikenal
}
```

Perhatikan baris terakhir: kita **membuat objek baru** dengan hanya field yang diizinkan. Ini mencegah pengguna menyelundupkan field tak terduga (misalnya `isAdmin: true`). Pada proyek nyata, biasanya dipakai pustaka validasi skema seperti **Zod**, **Valibot**, atau **Ajv** agar aturan validasi lebih ringkas dan terstandarisasi.

### Kesalahan umum

- Lupa bahwa bulan di `Date` dimulai dari 0.
- Menyimpan waktu lokal di database, bukan UTC.
- Menghitung uang dengan angka desimal: `0.1 + 0.2`.
- Menganggap `toFixed` mengembalikan angka (hasilnya string).
- Mengirim `BigInt` atau `Map` lewat `JSON.stringify` tanpa penanganan khusus.
- Memakai `JSON.parse` tanpa `try`/`catch` pada input pengguna.
- Langsung menyimpan seluruh isi body request ke database tanpa memilih field.

## Bab 12. Testing dan Kualitas Kode

### Tujuan belajar

- menulis pengujian otomatis dengan `node:test` dan `node:assert`,
- menguji fungsi sinkron, asinkron, dan error,
- memakai _mock_ untuk mengisolasi dependensi,
- menjaga kualitas kode dengan ESLint, Prettier, dan pengecekan tipe lewat JSDoc.

### 12.1 Mengapa menguji?

Pengujian otomatis adalah jaring pengaman. Tanpanya, setiap perubahan kecil berisiko merusak fitur lain tanpa Anda sadari, dan Anda harus mencoba semuanya secara manual setiap kali.

Jenis pengujian yang umum (sering digambarkan sebagai piramida):

|Jenis|Yang diuji|Kecepatan|Jumlah|
|---|---|---|---|
|**Unit test**|Satu fungsi atau class secara terpisah|Sangat cepat|Paling banyak|
|**Integration test**|Beberapa bagian bekerja bersama (misalnya endpoint + database uji)|Sedang|Sedang|
|**End-to-end test**|Alur lengkap dari sudut pandang pengguna|Lambat|Paling sedikit|

### 12.2 Pengujian pertama dengan node:test

Node.js punya test runner bawaan, tanpa perlu Jest atau Mocha untuk kebutuhan dasar.

Buat `src/diskon.js`:

```js
export function hitungDiskon(total, kodePromo) {
  if (total < 0) throw new RangeError("Total tidak boleh negatif");
  if (kodePromo === "HEMAT10") return Math.round(total * 0.1);
  return 0;
}
```

Buat `test/diskon.test.js`:

```js
import { describe, it } from "node:test";
import assert from "node:assert/strict";
import { hitungDiskon } from "../src/diskon.js";

describe("hitungDiskon", () => {
  it("memberi diskon 10 persen untuk kode HEMAT10", () => {
    assert.equal(hitungDiskon(100_000, "HEMAT10"), 10_000);
  });

  it("tidak memberi diskon untuk kode tidak dikenal", () => {
    assert.equal(hitungDiskon(100_000, "XYZ"), 0);
  });

  it("melempar error jika total negatif", () => {
    assert.throws(() => hitungDiskon(-1, "HEMAT10"), RangeError);
  });
});
```

Jalankan:

```bash
node --test
```

Node.js otomatis mencari file bernama `*.test.js` dan file di folder `test`. Anda juga bisa memakai `npm test` karena sudah diatur di Bab 1.

Fungsi `assert` yang sering dipakai (impor dari `node:assert/strict` agar perbandingan selalu ketat):

```js
assert.equal(a, b);              // a === b
assert.deepEqual(obj1, obj2);    // isi objek/array sama (perbandingan mendalam)
assert.ok(nilai);                // truthy
assert.throws(fn, RangeError);   // fn harus melempar error tertentu
await assert.rejects(promise, { message: "..." }); // promise harus ditolak
```

### 12.3 Menguji kode asinkron dan error

```js
import { test } from "node:test";
import assert from "node:assert/strict";

async function ambilUser(id, db) {
  const user = await db.cari(id);
  if (!user) throw new Error("User tidak ditemukan");
  return user;
}

test("mengembalikan user jika ada", async () => {
  const db = { cari: async () => ({ id: 1, nama: "Sari" }) };
  const user = await ambilUser(1, db);
  assert.deepEqual(user, { id: 1, nama: "Sari" });
});

test("melempar error jika user tidak ada", async () => {
  const db = { cari: async () => null };
  await assert.rejects(ambilUser(99, db), { message: "User tidak ditemukan" });
});
```

Perhatikan bahwa `db` adalah objek tiruan sederhana. Inilah keuntungan menerima dependensi dari luar (Bab 5.5): kita bisa mengujinya tanpa database sungguhan.

### 12.4 Mock

_Mock_ adalah fungsi tiruan yang mencatat bagaimana ia dipanggil.

```js
import { test, mock } from "node:test";
import assert from "node:assert/strict";
import { LayananPesanan } from "../src/layanan-pesanan.js"; // class dari Bab 5.5

test("mengirim notifikasi setelah pesanan disimpan", async () => {
  const kirim = mock.fn(async () => {});
  const layanan = new LayananPesanan({
    db: { simpan: async (p) => ({ id: 1, ...p }) },
    notifikasi: { kirim },
  });

  await layanan.buat({ produkId: 7 });

  assert.equal(kirim.mock.callCount(), 1);
  assert.deepEqual(kirim.mock.calls[0].arguments, ["Pesanan 1 dibuat"]);
});
```

Pedoman menulis test yang baik:

- Satu test menguji **satu perilaku**, dengan nama yang menjelaskannya.
- Pola **Arrange-Act-Assert**: siapkan data, jalankan fungsi, periksa hasil.
- Test harus **independen**: urutan eksekusi tidak boleh mempengaruhi hasil.
- Uji juga **kasus tepi dan kasus gagal** (input kosong, nol, negatif, `null`), bukan hanya kasus normal.
- Jangan menguji detail implementasi internal; uji perilaku yang terlihat dari luar.

Opsi seperti _coverage_ (persentase kode yang tersentuh test) dan mode `--watch` untuk test tersedia di test runner Node.js. Nama opsinya dapat berbeda antar versi, jadi periksa `node --help` atau dokumentasi versi Anda.

### 12.5 Linter dan formatter

- **ESLint** menganalisis kode dan menemukan bug potensial (variabel tidak terpakai, lupa `await`, dan sebagainya).
- **Prettier** memformat kode secara otomatis sehingga gaya seragam, dan mengakhiri debat soal titik koma dan spasi.

```bash
npm install -D eslint @eslint/js globals prettier
```

`eslint.config.js`:

```js
import js from "@eslint/js";
import globals from "globals";

export default [
  js.configs.recommended,
  {
    languageOptions: { globals: globals.node },
    rules: {
      "no-unused-vars": "warn",
      eqeqeq: "error",          // wajib === dan !==
    },
  },
];
```

Tambahkan ke `package.json`:

```json
"scripts": {
  "lint": "eslint .",
  "format": "prettier --write ."
}
```

Catatan: aturan untuk mendeteksi promise yang lupa di-`await` (`no-floating-promises`) baru tersedia jika Anda memakai TypeScript bersama `typescript-eslint`. Itu salah satu alasan TypeScript populer di proyek backend.

### 12.6 Pengecekan tipe dengan JSDoc dan pengenalan TypeScript

JavaScript tidak punya tipe statis, sehingga kesalahan seperti memanggil fungsi dengan argumen keliru baru ketahuan saat program berjalan. Ada dua cara mendapatkan pengecekan tipe:

**1. JSDoc + `@ts-check`** (tetap menulis JavaScript murni):

```js
// @ts-check

/**
 * Menghitung total harga.
 * @param {number} harga
 * @param {number} jumlah
 * @returns {number}
 */
export function total(harga, jumlah) {
  return harga * jumlah;
}

total("10", 2); // editor menandai error: string tidak cocok dengan number
```

**2. TypeScript**: superset JavaScript dengan sistem tipe penuh. Node.js versi modern dapat menjalankan file `.ts` sederhana secara langsung dengan membuang anotasi tipenya (_type stripping_), meski pengecekan tipe tetap dilakukan oleh compiler `tsc` atau editor. Di dunia kerja, TypeScript sudah sangat umum untuk backend Node.js. Setelah Anda nyaman dengan JavaScript menengah di buku ini, mempelajari TypeScript adalah langkah lanjutan yang paling bernilai.

### 12.7 Kebiasaan kode bersih

- **Nama yang jelas**: `hitungTotalPesanan` lebih baik dari `hitung` atau `proses`.
- **Fungsi kecil, satu tugas**. Jika butuh kata "dan" untuk menjelaskan fungsi Anda, pecah menjadi dua.
- **Early return** untuk mengurangi nesting:

```js
// Bersarang dalam, sulit dibaca
function proses(user) {
  if (user) {
    if (user.aktif) {
      return kerjakan(user);
    }
  }
  return null;
}

// Early return: lebih rata dan jelas
function prosesRapi(user) {
  if (!user) return null;
  if (!user.aktif) return null;
  return kerjakan(user);
}
```

- **Hindari "angka ajaib"**: pakai konstanta bernama (`const MAKS_PERCOBAAN = 3`).
- **Komentar menjelaskan "mengapa", bukan "apa"**. Kode sudah menjelaskan apa yang terjadi; komentar untuk alasan di baliknya.
- **Commit kecil dan sering** di Git dengan pesan yang bermakna.

## Bab 13. Debugging dan Performa

### Tujuan belajar

- menemukan penyebab bug secara sistematis,
- memakai `console`, `debugger`, dan `--inspect`,
- membuat _logging_ terstruktur yang berguna di produksi,
- mengukur performa, mengenali _memory leak_, dan memindahkan kerja berat ke _worker thread_.

### 13.1 Cara berpikir saat debugging

Debugging adalah pekerjaan ilmiah, bukan menebak-nebak. Urutannya:

1. **Reproduksi**: temukan langkah pasti yang memunculkan bug. Bug yang tidak bisa direproduksi tidak bisa diperbaiki dengan yakin.
2. **Isolasi**: persempit lokasi masalah. Matikan bagian yang tidak terkait, atau bagi kode menjadi dua dan periksa di sisi mana masalahnya (_binary search_).
3. **Hipotesis**: "Saya kira `user` bernilai `undefined` di baris ini karena ..."
4. **Uji hipotesis**: cetak nilai, pasang _breakpoint_, atau tulis test yang gagal.
5. **Perbaiki dan pastikan**: setelah diperbaiki, tambahkan test agar bug yang sama tidak kembali.

**Membaca stack trace.** Saat error muncul, Node.js mencetak jejak pemanggilan:

```
TypeError: Cannot read properties of undefined (reading 'nama')
    at formatUser (file:///proyek/src/format.js:12:20)
    at prosesPesanan (file:///proyek/src/layanan.js:34:15)
    at file:///proyek/src/index.js:8:1
```

Baca dari **atas**: baris pertama adalah tempat error terjadi (`format.js` baris 12), baris di bawahnya adalah siapa yang memanggil. Cari baris pertama yang merupakan file milik Anda (bukan `node_modules` atau `node:internal`).

### 13.2 Alat debugging

**Method console yang berguna:**

```js
console.log("biasa");
console.error("ke stderr, untuk error");
console.table([{ id: 1, nama: "Kopi" }, { id: 2, nama: "Teh" }]); // tampil sebagai tabel
console.dir(objekBersarang, { depth: null });  // tampilkan seluruh kedalaman objek
console.time("query"); await jalankanQuery(); console.timeEnd("query"); // ukur durasi
console.trace("siapa yang memanggil ini?");
```

**Debugger sungguhan** jauh lebih efektif daripada puluhan `console.log`. Anda bisa berhenti di baris tertentu, memeriksa semua variabel, dan menelusuri kode langkah demi langkah.

Cara termudah di VS Code: buka terminal khusus debug (_JavaScript Debug Terminal_), lalu jalankan `node src/index.js`, dan klik di samping nomor baris untuk memasang breakpoint. Alternatifnya dari terminal biasa:

```bash
node --inspect-brk src/index.js
```

Lalu buka `chrome://inspect` di Chrome dan klik _inspect_. Anda bisa juga menulis kata kunci `debugger;` di kode: eksekusi akan berhenti di baris itu saat debugger terhubung.

Perintah dasar debugger: _continue_ (lanjut sampai breakpoint berikutnya), _step over_ (jalankan baris ini), _step into_ (masuk ke dalam fungsi), _step out_ (keluar dari fungsi), serta panel _watch_ untuk memantau ekspresi dan _call stack_ untuk melihat rantai pemanggilan.

### 13.3 Logging yang baik

Di produksi Anda tidak bisa memasang debugger. **Log adalah mata Anda.** Praktik yang baik:

- **Level log**: `debug` (detail pengembangan), `info` (kejadian normal penting), `warn` (mencurigakan tapi tidak gagal), `error` (gagal).
- **Log terstruktur (JSON)**: satu baris per kejadian berformat JSON, sehingga mudah dicari dan dianalisis oleh alat seperti Loki, Elasticsearch, atau Datadog.
- **Sertakan konteks**: ID request, ID pengguna, durasi, kode status.
- **Jangan pernah mencatat data sensitif**: password, token, nomor kartu, data pribadi.

```js
export function buatLogger(namaLayanan) {
  const tulis = (level, pesan, data = {}) => {
    console.log(
      JSON.stringify({
        waktu: new Date().toISOString(),
        level,
        layanan: namaLayanan,
        pesan,
        ...data,
      })
    );
  };

  return {
    info: (pesan, data) => tulis("info", pesan, data),
    warn: (pesan, data) => tulis("warn", pesan, data),
    error: (pesan, err, data) =>
      tulis("error", pesan, {
        ...data,
        error: { nama: err?.name, pesan: err?.message, stack: err?.stack },
      }),
  };
}

const log = buatLogger("katalog-api");
log.info("Server dimulai", { port: 3000 });
log.error("Query gagal", new Error("koneksi terputus"), { requestId: "abc123" });
```

Pada proyek nyata, pustaka seperti **pino** lebih dipilih karena cepat dan kaya fitur, tetapi konsepnya sama dengan contoh di atas.

### 13.4 Mengukur performa

Aturan pertama optimasi: **ukur dulu, jangan menebak.** Kode yang Anda kira lambat sering bukan penyebab sebenarnya.

```js
import { performance } from "node:perf_hooks";

const mulai = performance.now();
await kerjakanSesuatu();
console.log(`Selesai dalam ${(performance.now() - mulai).toFixed(1)} ms`);
```

**Memantau kesehatan event loop.** Jika event loop terlambat berputar, artinya ada kode yang memblokir:

```js
import { monitorEventLoopDelay } from "node:perf_hooks";

const histogram = monitorEventLoopDelay({ resolution: 20 });
histogram.enable();

setInterval(() => {
  const p99 = histogram.percentile(99) / 1e6; // nanodetik ke milidetik
  console.log(`Keterlambatan event loop (p99): ${p99.toFixed(1)} ms`);
  histogram.reset();
}, 5000).unref();
```

Nilai yang terus tinggi (misalnya di atas 100 ms) adalah tanda bahaya.

**Profiling CPU**: untuk mengetahui fungsi mana yang paling banyak memakan waktu, jalankan `node --cpu-prof src/index.js`. Node.js menghasilkan file `.cpuprofile` yang dapat dibuka di tab _Performance_ pada Chrome DevTools atau di VS Code.

### 13.5 Memory leak

**Memory leak** terjadi ketika memori yang tidak lagi dibutuhkan tetap tertahan sehingga pemakaian memori naik terus sampai proses mati (_out of memory_). Penyebab umum di aplikasi backend:

|Penyebab|Contoh|
|---|---|
|Cache tanpa batas|`Map` global yang terus bertambah (lihat memoize di Bab 3)|
|Listener yang tidak dilepas|`emitter.on(...)` dipanggil di setiap request tanpa `off`|
|Array atau objek global yang terus diisi|Menyimpan riwayat request di variabel global|
|Timer yang tidak dibersihkan|`setInterval` tanpa `clearInterval`|
|Closure yang menahan data besar|Callback yang merujuk objek besar yang seharusnya sudah bebas|

Cara mendeteksi: pantau `process.memoryUsage().heapUsed` dari waktu ke waktu. Jika naik terus dan tidak turun setelah _garbage collection_, curigai leak. Untuk mencari pelakunya, ambil _heap snapshot_ lewat Chrome DevTools (tab _Memory_) setelah `--inspect`, lalu bandingkan dua snapshot.

Perbaikan paling umum adalah **membatasi ukuran cache**. Contoh cache LRU sederhana (_Least Recently Used_: yang paling lama tidak dipakai dibuang lebih dulu) memanfaatkan fakta bahwa `Map` mengingat urutan sisipan:

```js
export class CacheLRU {
  #maks;
  #data = new Map();

  constructor(maks = 100) {
    this.#maks = maks;
  }

  get(kunci) {
    if (!this.#data.has(kunci)) return undefined;
    const nilai = this.#data.get(kunci);
    this.#data.delete(kunci);       // pindahkan ke posisi paling baru
    this.#data.set(kunci, nilai);
    return nilai;
  }

  set(kunci, nilai) {
    this.#data.delete(kunci);
    this.#data.set(kunci, nilai);
    if (this.#data.size > this.#maks) {
      const tertua = this.#data.keys().next().value; // kunci pertama = paling lama
      this.#data.delete(tertua);
    }
  }
}
```

### 13.6 Worker thread untuk pekerjaan berat CPU

Di Bab 7 kita tahu bahwa perhitungan berat memblokir event loop. Solusinya: pindahkan ke **worker thread**, yaitu thread terpisah yang memiliki JavaScript engine sendiri dan berkomunikasi lewat pesan.

```js
// hitung.js
import { Worker, isMainThread, parentPort, workerData } from "node:worker_threads";

function fib(n) {
  return n < 2 ? n : fib(n - 1) + fib(n - 2); // sengaja lambat
}

if (isMainThread) {
  // Kode di blok ini berjalan di thread utama
  function hitungDiWorker(n) {
    return new Promise((resolve, reject) => {
      const worker = new Worker(import.meta.filename, { workerData: n });
      worker.once("message", resolve);
      worker.once("error", reject);
    });
  }

  console.log("hasil:", await hitungDiWorker(40));
} else {
  // Kode di blok ini berjalan di thread worker
  parentPort.postMessage(fib(workerData));
}
```

Selama worker menghitung, thread utama tetap bebas melayani request. Untuk pemakaian sungguhan, buat sekumpulan worker yang dipakai ulang (_worker pool_), misalnya dengan paket `piscina`, karena membuat worker baru untuk setiap tugas cukup mahal.

Ingat: worker thread untuk pekerjaan **CPU**. Untuk pekerjaan I/O (database, jaringan, file), `async`/`await` sudah tepat.

### 13.7 Kebiasaan performa di backend

Sebagian besar masalah performa backend bukan di JavaScript-nya, melainkan pada cara memakai sumber daya lain:

- **Query database yang buruk**: hindari masalah _N+1_ (satu query untuk daftar, lalu satu query per item). Ambil data terkait dalam satu query atau `JOIN`. Pasang **index** pada kolom yang sering dicari.
- **Paginasi**: jangan pernah mengembalikan seluruh tabel. Selalu batasi jumlah data per respons.
- **Caching**: simpan hasil yang mahal dan jarang berubah (di memori dengan batas ukuran, atau di Redis).
- **Streaming**: kirim file atau data besar sebagai stream.
- **Connection pool**: pakai ulang koneksi database, jangan membuka koneksi baru setiap request.
- **API sinkron** seperti `fs.readFileSync` boleh dipakai saat aplikasi start, tetapi **jangan** di dalam handler request.
- **Skalakan horizontal**: jalankan beberapa instance proses di belakang _load balancer_ untuk memanfaatkan banyak core CPU dan meningkatkan ketersediaan.

## Bab 14. Keamanan Dasar

### Tujuan belajar

- memahami prinsip dasar keamanan aplikasi backend,
- mengenali dan mencegah serangan umum: injeksi SQL, injeksi perintah, _path traversal_, _prototype pollution_, dan ReDoS,
- mengelola rahasia dan dependensi dengan aman.

Keamanan bukan fitur tambahan yang dipasang di akhir. Ia adalah kebiasaan yang harus ada sejak baris kode pertama. Satu celah dapat membocorkan data ribuan pengguna. Bab ini memberi fondasi; untuk mendalami, pelajari **OWASP Top 10** (daftar risiko keamanan aplikasi web paling umum dari organisasi OWASP).

### 14.1 Prinsip utama

1. **Jangan percaya input apa pun dari luar.** Body, query string, header, cookie, nama file, bahkan data dari layanan lain: semuanya harus divalidasi.
2. **Hak akses minimum (_least privilege_).** Beri akun database, token API, dan proses server hanya izin yang benar-benar dibutuhkan.
3. **Pertahanan berlapis.** Jangan bergantung pada satu perlindungan saja.
4. **Gagal dengan aman.** Jika ragu, tolak.
5. **Jangan membuat kriptografi sendiri.** Pakai pustaka dan algoritma standar yang sudah teruji.

### 14.2 Injeksi SQL

Terjadi ketika input pengguna disambung langsung ke dalam string query sehingga penyerang bisa menyisipkan perintah SQL.

```js
// BERBAHAYA: input disambung ke dalam query
const email = "' OR '1'='1";
const query = `SELECT * FROM users WHERE email = '${email}'`;
// Menjadi: SELECT * FROM users WHERE email = '' OR '1'='1'  -> mengembalikan SEMUA user

// AMAN: parameterized query (nilai dikirim terpisah dari perintah SQL)
const hasil = await db.query("SELECT * FROM users WHERE email = $1", [email]);
```

Aturan sederhana: **jangan pernah menyambung string untuk membuat query.** Selalu pakai _parameterized query_ atau _prepared statement_. ORM dan query builder yang baik melakukannya secara otomatis, tetapi tetap waspada saat menulis query mentah.

### 14.3 Injeksi perintah (command injection)

```js
import { exec, execFile } from "node:child_process";

const namaFolder = "dokumen; rm -rf /"; // input dari pengguna

// BERBAHAYA: string dijalankan oleh shell, sehingga karakter ; dijalankan sebagai perintah baru
exec(`ls -l ${namaFolder}`);

// LEBIH AMAN: tanpa shell, argumen dikirim sebagai daftar terpisah
execFile("ls", ["-l", namaFolder], (err, stdout) => {
  // "dokumen; rm -rf /" hanya dianggap nama folder, bukan perintah
});
```

Lebih baik lagi: hindari menjalankan program eksternal berdasarkan input pengguna. Jika terpaksa, validasi input dengan daftar yang diizinkan (_allowlist_).

### 14.4 Path traversal

Penyerang mengirim nama file seperti `../../etc/passwd` untuk membaca file di luar folder yang seharusnya.

```js
import path from "node:path";

const FOLDER_UPLOAD = path.resolve("uploads");

function pathAman(namaBerkas) {
  const target = path.resolve(FOLDER_UPLOAD, namaBerkas);
  // pastikan hasil akhirnya benar-benar masih di dalam folder yang diizinkan
  if (!target.startsWith(FOLDER_UPLOAD + path.sep)) {
    throw new Error("Path tidak valid");
  }
  return target;
}

pathAman("foto/a.png");          // OK
pathAman("../../etc/passwd");    // melempar error
```

### 14.5 Prototype pollution

Karena semua objek JavaScript mewarisi dari `Object.prototype` (Bab 5), penyerang yang bisa menyisipkan properti `__proto__` lewat JSON dapat mengubah perilaku **seluruh aplikasi**.

```js
// Fungsi penggabung objek yang rentan
function gabung(target, sumber) {
  for (const kunci in sumber) {
    if (typeof sumber[kunci] === "object" && sumber[kunci] !== null) {
      target[kunci] ??= {};
      gabung(target[kunci], sumber[kunci]);
    } else {
      target[kunci] = sumber[kunci];
    }
  }
  return target;
}

gabung({}, JSON.parse('{"__proto__": {"isAdmin": true}}'));
console.log({}.isAdmin); // true  <- SEMUA objek baru sekarang punya isAdmin!
```

Pencegahan:

- Jangan menulis fungsi _deep merge_ sendiri; pakai pustaka yang terawat dan selalu perbarui.
- Tolak kunci `__proto__`, `constructor`, dan `prototype` dari input.
- Gunakan `Map` atau `Object.create(null)` untuk kamus dengan kunci dari pengguna.
- Validasi input dengan skema sehingga hanya field yang dikenal yang diterima (seperti di `validasiProdukBaru`).

### 14.6 ReDoS: regex yang menghentikan server

Ekspresi reguler (_regex_) tertentu memiliki waktu eksekusi yang meledak secara eksponensial pada input yang dirancang khusus. Karena Node.js single-thread, satu regex bermasalah dapat membekukan seluruh server (_Regular expression Denial of Service_).

```js
// Pola dengan pengulangan bersarang seperti ini berbahaya
const rentan = /^(a+)+$/;
// rentan.test("aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaab"); // bisa memakan waktu sangat lama
```

Pencegahan: hindari kuantifier bersarang (`(a+)+`, `(a*)*`), batasi panjang input sebelum diuji, dan untuk validasi standar seperti email atau URL gunakan pustaka validasi yang teruji.

### 14.7 Rahasia dan konfigurasi

- Simpan rahasia (password database, kunci API, kunci penandatangan token) di **environment variable** atau layanan pengelola rahasia, bukan di kode.
- **Jangan commit `.env`** ke Git. Jika rahasia pernah ter-commit, anggap sudah bocor: **putar (rotate) rahasianya**, jangan hanya menghapus commit.
- Bedakan rahasia untuk setiap lingkungan (lokal, staging, produksi).
- Jangan menulis rahasia ke log.

### 14.8 Autentikasi dan otorisasi

Dua hal yang sering tertukar:

- **Autentikasi**: memastikan **siapa** Anda (login).
- **Otorisasi**: memastikan **apa yang boleh** Anda lakukan (izin).

Prinsip dasar:

- Simpan password dengan hash lambat dan bergaram (`scrypt`, `bcrypt`, `argon2`; lihat Bab 10.8).
- Beri pesan error yang sama untuk "email tidak ditemukan" dan "password salah" agar penyerang tidak bisa menebak email yang terdaftar.
- Selalu periksa otorisasi **di server** untuk setiap request. Menyembunyikan tombol di frontend bukan keamanan.
- Pakai mekanisme yang mapan (sesi dengan cookie `HttpOnly` dan `Secure`, atau token seperti JWT dengan masa berlaku singkat) melalui pustaka teruji, bukan implementasi sendiri.
- Batasi percobaan login (_rate limiting_) untuk menahan tebak-tebakan password.

### 14.9 Lapisan HTTP

- **HTTPS wajib** di produksi. Biasanya dipasang di _reverse proxy_ seperti Nginx, Caddy, atau layanan cloud.
- **CORS** (_Cross-Origin Resource Sharing_) adalah aturan browser tentang situs mana yang boleh memanggil API Anda. Izinkan hanya _origin_ yang dipercaya, jangan asal `*` untuk API yang memakai kredensial.
- **Security headers** seperti `Strict-Transport-Security` dan `X-Content-Type-Options`. Di framework, paket seperti `helmet` menambahkannya otomatis.
- **Batasi ukuran body** (seperti di proyek akhir) agar tidak dibanjiri data besar.
- **Rate limiting** untuk membatasi jumlah request per klien.
- **Jangan bocorkan detail internal**: kirim pesan error umum ke klien, simpan detail lengkap di log.

### 14.10 Keamanan dependensi

Aplikasi Node.js biasanya memakai ratusan paket, sehingga _supply chain_ (rantai pasok kode) adalah risiko nyata.

- Jalankan `npm audit` secara rutin, dan perbarui paket yang rentan.
- Commit `package-lock.json` dan pakai `npm ci` di server build.
- Kurangi jumlah dependensi. Setiap paket tambahan adalah permukaan serangan tambahan.
- Waspadai paket dengan nama mirip paket populer (_typosquatting_).
- Jangan memakai `eval()` atau `new Function()` pada string dari luar.
- Node.js juga memiliki **Permission Model** (opsi `--permission`) yang membatasi akses proses ke file, jaringan, dan proses anak. Cek dokumentasi versi Anda untuk cara pemakaian terbaru.

### Daftar periksa keamanan singkat

- Semua input divalidasi dengan skema, dan field yang tidak dikenal ditolak.
- Query database memakai parameter.
- Tidak ada rahasia di kode maupun di Git.
- Password di-hash dengan algoritma lambat dan bergaram.
- Otorisasi diperiksa di server untuk setiap aksi.
- HTTPS aktif, CORS dibatasi, ukuran body dibatasi, ada rate limiting.
- Error ke klien bersifat umum, detail hanya di log.
- Dependensi diaudit dan dikunci.

### Tujuan belajar

### 15.1 Apa itu REST API?

**REST** adalah gaya merancang API di atas HTTP. Ide intinya: aplikasi memiliki **resource** (sumber daya, misalnya `produk`), setiap resource punya alamat (URL), dan operasi ditentukan oleh **method HTTP**.

|Method|Path|Fungsi|Status sukses|
|---|---|---|---|
|`GET`|`/kesehatan`|Cek server hidup (_health check_)|200|
|`GET`|`/produk`|Daftar produk (dengan filter dan paginasi)|200|
|`POST`|`/produk`|Membuat produk baru|201|
|`GET`|`/produk/:id`|Detail satu produk|200|
|`PATCH`|`/produk/:id`|Mengubah sebagian field produk|200|
|`DELETE`|`/produk/:id`|Menghapus produk|204 (tanpa isi)|

Parameter query untuk `GET /produk`: `kategori`, `q` (cari nama), `halaman` (default 1), `ukuran` (default 10, maksimum 100).

Status code error yang dipakai: `400` (input tidak valid), `404` (tidak ditemukan), `405` (method tidak diizinkan), `413` (body terlalu besar), `415` (Content-Type salah), dan `500` (bug di server).

### 15.5 validasi.js

Prinsip dari Bab 11 dan 14: jangan percaya input. Perhatikan tiga keputusan desain:

1. **Semua masalah dikumpulkan** lalu dilaporkan sekaligus, sehingga klien tidak perlu memperbaiki satu per satu.
2. **Field tak dikenal ditolak**, sehingga penyerang tidak bisa menyelundupkan field seperti `isAdmin`.
3. **Objek baru dibuat** dari field yang dikenal (`bersihkan`), bukan menyimpan langsung objek dari luar.

```js
// src/validasi.js
import { ValidationError } from "./errors.js";

const FIELD_DIIZINKAN = ["nama", "harga", "kategori", "stok"];

// Memeriksa satu field. Mengembalikan pesan masalah, atau null jika valid.
function periksaField(kunci, nilai) {
  switch (kunci) {
    case "nama":
      if (typeof nilai !== "string" || nilai.trim() === "" || nilai.length > 100) {
        return "nama wajib berupa teks 1 sampai 100 karakter";
      }
      return null;
    case "harga":
      if (!Number.isInteger(nilai) || nilai < 0) {
        return "harga wajib berupa bilangan bulat tidak negatif";
      }
      return null;
    case "kategori":
      if (typeof nilai !== "string" || nilai.trim() === "") {
        return "kategori wajib berupa teks tidak kosong";
      }
      return null;
    case "stok":
      if (!Number.isInteger(nilai) || nilai < 0) {
        return "stok wajib berupa bilangan bulat tidak negatif";
      }
      return null;
    default:
      return `field "${kunci}" tidak dikenal`;
  }
}

function pastikanObjek(data) {
  if (typeof data !== "object" || data === null || Array.isArray(data)) {
    throw new ValidationError("Body harus berupa objek JSON");
  }
}

function bersihkan(data) {
  const hasil = {};
  if ("nama" in data) hasil.nama = data.nama.trim();
  if ("harga" in data) hasil.harga = data.harga;
  if ("kategori" in data) hasil.kategori = data.kategori.trim();
  if ("stok" in data) hasil.stok = data.stok;
  return hasil;
}

export function validasiProdukBaru(data) {
  pastikanObjek(data);
  const masalah = [];

  for (const kunci of Object.keys(data)) {
    if (!FIELD_DIIZINKAN.includes(kunci)) masalah.push(`field "${kunci}" tidak dikenal`);
  }
  for (const wajib of ["nama", "harga"]) {
    if (!(wajib in data)) masalah.push(`${wajib} wajib diisi`);
  }
  for (const kunci of FIELD_DIIZINKAN) {
    if (kunci in data) {
      const pesan = periksaField(kunci, data[kunci]);
      if (pesan) masalah.push(pesan);
    }
  }

  if (masalah.length > 0) throw new ValidationError("Data tidak valid", masalah);
  return { kategori: "umum", stok: 0, ...bersihkan(data) };
}

export function validasiPerubahan(data) {
  pastikanObjek(data);
  const kunciData = Object.keys(data);
  if (kunciData.length === 0) {
    throw new ValidationError("Tidak ada field yang diubah");
  }

  const masalah = [];
  for (const kunci of kunciData) {
    const pesan = periksaField(kunci, data[kunci]);
    if (pesan) masalah.push(pesan);
  }
  if (masalah.length > 0) throw new ValidationError("Data tidak valid", masalah);
  return bersihkan(data);
}
```

### 15.6 repositori.js

Ini bagian yang paling menarik secara teknis. Perhatikan beberapa hal:

- **Class dengan private field** (`#berkas`, `#pemuatan`, `#antrean`) dari Bab 5.
- **Pemuatan malas (_lazy load_)**: file dibaca sekali saat pertama dibutuhkan, dan yang disimpan adalah _promise_-nya sehingga pembacaan tidak berulang meski diminta bersamaan.
- **Antrean penulisan (`#serial`)**: karena banyak request bisa masuk bersamaan, dua operasi tulis yang berjalan paralel dapat saling menimpa dan menghasilkan ID ganda. Dengan merantai setiap operasi pada promise sebelumnya, penulisan dijalankan **satu per satu**. Ini contoh nyata penerapan promise dari Bab 7.
- **Penulisan atomik** dengan file sementara lalu `rename` (Bab 10.2), sehingga file tidak rusak jika proses mati di tengah menulis.
- **`structuredClone`** saat mengembalikan data agar pemanggil tidak bisa mengubah data internal tanpa sengaja (Bab 4).
- **Tidak memodifikasi data lama**: `with()`, `filter()`, dan spread membuat array atau objek baru.

```js
// src/repositori.js
import fs from "node:fs/promises";
import path from "node:path";

// Repositori: satu-satunya bagian yang tahu CARA data disimpan.
// Sekarang memakai file JSON. Nanti bisa diganti database tanpa mengubah layanan.
export class RepositoriProduk {
  #berkas;
  #pemuatan = null;
  #antrean = Promise.resolve();

  constructor(berkas) {
    this.#berkas = berkas;
  }

  // Data dimuat sekali dan disimpan sebagai promise agar pemuatan tidak berulang
  #muat() {
    this.#pemuatan ??= this.#bacaFile();
    return this.#pemuatan;
  }

  async #bacaFile() {
    try {
      return JSON.parse(await fs.readFile(this.#berkas, "utf8"));
    } catch (err) {
      if (err.code === "ENOENT") return { terakhirId: 0, produk: [] };
      throw err;
    }
  }

  // Penulisan atomik: tulis ke file sementara lalu rename
  async #simpan(data) {
    await fs.mkdir(path.dirname(this.#berkas), { recursive: true });
    const sementara = `${this.#berkas}.${process.pid}.tmp`;
    await fs.writeFile(sementara, JSON.stringify(data, null, 2), "utf8");
    await fs.rename(sementara, this.#berkas);
  }

  // Operasi tulis dijalankan satu per satu agar tidak saling menimpa
  #serial(operasi) {
    const hasil = this.#antrean.then(operasi);
    this.#antrean = hasil.catch(() => {}); // kegagalan satu operasi tidak menghentikan antrean
    return hasil;
  }

  async semua() {
    const data = await this.#muat();
    return structuredClone(data.produk);
  }

  async cari(id) {
    const data = await this.#muat();
    const produk = data.produk.find((p) => p.id === id);
    return produk ? structuredClone(produk) : null;
  }

  tambah(dataBaru) {
    return this.#serial(async () => {
      const data = await this.#muat();
      const sekarang = new Date().toISOString();
      const produk = {
        id: data.terakhirId + 1,
        ...dataBaru,
        dibuatPada: sekarang,
        diubahPada: sekarang,
      };
      const berikutnya = {
        terakhirId: produk.id,
        produk: [...data.produk, produk],
      };
      await this.#simpan(berikutnya);
      this.#pemuatan = Promise.resolve(berikutnya);
      return structuredClone(produk);
    });
  }

  ubah(id, perubahan) {
    return this.#serial(async () => {
      const data = await this.#muat();
      const indeks = data.produk.findIndex((p) => p.id === id);
      if (indeks === -1) return null;

      const diperbarui = {
        ...data.produk[indeks],
        ...perubahan,
        diubahPada: new Date().toISOString(),
      };
      const berikutnya = { ...data, produk: data.produk.with(indeks, diperbarui) };
      await this.#simpan(berikutnya);
      this.#pemuatan = Promise.resolve(berikutnya);
      return structuredClone(diperbarui);
    });
  }

  hapus(id) {
    return this.#serial(async () => {
      const data = await this.#muat();
      if (!data.produk.some((p) => p.id === id)) return false;

      const berikutnya = { ...data, produk: data.produk.filter((p) => p.id !== id) };
      await this.#simpan(berikutnya);
      this.#pemuatan = Promise.resolve(berikutnya);
      return true;
    });
  }
}
```

### 15.7 layanan.js

Lapisan bisnis ini tidak mengenal HTTP (`req`, `res`) maupun file. Ia hanya menerima data biasa dan bekerja lewat `repo` yang diberikan dari luar (_dependency injection_). Karena itu mudah diuji, seperti terlihat di `test/layanan.test.js`.

```js
// src/layanan.js
import { NotFoundError } from "./errors.js";
import { validasiProdukBaru, validasiPerubahan } from "./validasi.js";

// Layanan: berisi logika bisnis. Tidak tahu tentang HTTP maupun cara penyimpanan.
export class LayananProduk {
  #repo;

  constructor({ repo }) {
    this.#repo = repo;
  }

  async daftar({ kategori, q, halaman = 1, ukuran = 10 } = {}) {
    let hasil = await this.#repo.semua();

    if (kategori) hasil = hasil.filter((p) => p.kategori === kategori);
    if (q) {
      const kata = q.toLowerCase();
      hasil = hasil.filter((p) => p.nama.toLowerCase().includes(kata));
    }

    const total = hasil.length;
    const mulai = (halaman - 1) * ukuran;

    return {
      data: hasil.slice(mulai, mulai + ukuran),
      meta: { halaman, ukuran, total, totalHalaman: Math.ceil(total / ukuran) },
    };
  }

  async ambil(id) {
    const produk = await this.#repo.cari(id);
    if (!produk) throw new NotFoundError("Produk", id);
    return produk;
  }

  async buat(data) {
    return this.#repo.tambah(validasiProdukBaru(data));
  }

  async ubah(id, data) {
    const produk = await this.#repo.ubah(id, validasiPerubahan(data));
    if (!produk) throw new NotFoundError("Produk", id);
    return produk;
  }

  async hapus(id) {
    const berhasil = await this.#repo.hapus(id);
    if (!berhasil) throw new NotFoundError("Produk", id);
  }
}
```

### 15.8 server.js

Lapisan HTTP. Poin yang perlu diperhatikan:

- **Tabel rute** berisi method, pola path (regex), dan handler. Ini versi mini dari apa yang dilakukan framework routing.
- **Pembedaan 404 dan 405**: jika path dikenal tetapi method-nya salah, hasilnya 405, bukan 404.
- **`bacaBodyJson`** membatasi ukuran body (1 MB), memeriksa `Content-Type`, dan menerjemahkan JSON rusak menjadi `ValidationError`.
- **Parameter query divalidasi** (`angkaPositif`) dan dibatasi maksimumnya. Parameter `ukuran=1000000` tidak akan lolos.
- **Penanganan error terpusat** di satu tempat: `AppError` diterjemahkan ke respons sesuai `statusCode`; error lain dianggap bug, dicatat lengkap ke log, dan klien hanya menerima pesan umum (Bab 8 dan 14).
- **`logger` bisa disuntikkan** sehingga test dapat membungkam log.
- Blok `finally` mencatat satu baris log terstruktur untuk setiap request.

```js
// src/server.js
import http from "node:http";
import { AppError, ValidationError } from "./errors.js";

const BATAS_BODY = 1_000_000; // 1 MB

// Mengubah nilai query string menjadi bilangan bulat positif yang aman
function angkaPositif(nilai, bawaan, maks = Infinity) {
  if (nilai === null || nilai === undefined) return bawaan;
  const angka = Number(nilai);
  if (!Number.isInteger(angka) || angka < 1) {
    throw new ValidationError(`Parameter harus bilangan bulat positif, diterima: "${nilai}"`);
  }
  return Math.min(angka, maks);
}

async function bacaBodyJson(req) {
  const jenis = req.headers["content-type"] ?? "";
  if (!jenis.includes("application/json")) {
    throw new AppError("Content-Type harus application/json", { statusCode: 415 });
  }

  let ukuran = 0;
  const potongan = [];
  for await (const p of req) {
    ukuran += p.length;
    if (ukuran > BATAS_BODY) {
      throw new AppError("Body terlalu besar", { statusCode: 413 });
    }
    potongan.push(p);
  }

  try {
    return JSON.parse(Buffer.concat(potongan).toString("utf8"));
  } catch {
    throw new ValidationError("Body bukan JSON yang valid");
  }
}

function kirimJson(res, status, data) {
  if (data === undefined) {
    res.writeHead(status).end();
    return;
  }
  res.writeHead(status, { "Content-Type": "application/json; charset=utf-8" });
  res.end(JSON.stringify(data));
}

export function buatServer(layanan, { logger = console } = {}) {
  // Tabel rute: [method, pola path, handler]
  // Handler menerima { url, params, req } dan mengembalikan { status, data }
  const rute = [
    ["GET", /^\/kesehatan$/, async () => ({ status: 200, data: { status: "ok" } })],

    ["GET", /^\/produk$/, async ({ url }) => {
      const q = url.searchParams;
      const hasil = await layanan.daftar({
        kategori: q.get("kategori") ?? undefined,
        q: q.get("q") ?? undefined,
        halaman: angkaPositif(q.get("halaman"), 1),
        ukuran: angkaPositif(q.get("ukuran"), 10, 100),
      });
      return { status: 200, data: hasil };
    }],

    ["POST", /^\/produk$/, async ({ req }) => {
      const produk = await layanan.buat(await bacaBodyJson(req));
      return { status: 201, data: produk };
    }],

    ["GET", /^\/produk\/(\d+)$/, async ({ params }) => ({
      status: 200,
      data: await layanan.ambil(Number(params[0])),
    })],

    ["PATCH", /^\/produk\/(\d+)$/, async ({ req, params }) => ({
      status: 200,
      data: await layanan.ubah(Number(params[0]), await bacaBodyJson(req)),
    })],

    ["DELETE", /^\/produk\/(\d+)$/, async ({ params }) => {
      await layanan.hapus(Number(params[0]));
      return { status: 204 };
    }],
  ];

  async function tangani(req, res) {
    const url = new URL(req.url, `http://${req.headers.host ?? "localhost"}`);

    const cocok = rute
      .map(([method, pola, handler]) => ({ method, hasil: pola.exec(url.pathname), handler }))
      .filter((r) => r.hasil !== null);

    if (cocok.length === 0) {
      throw new AppError("Rute tidak ditemukan", { statusCode: 404 });
    }
    const dipilih = cocok.find((r) => r.method === req.method);
    if (!dipilih) {
      throw new AppError("Method tidak diizinkan", { statusCode: 405 });
    }

    const { status, data } = await dipilih.handler({
      req,
      url,
      params: dipilih.hasil.slice(1),
    });
    kirimJson(res, status, data);
    return status;
  }

  return http.createServer(async (req, res) => {
    const mulai = performance.now();
    let status = 500;

    try {
      status = await tangani(req, res);
    } catch (err) {
      if (err instanceof AppError) {
        status = err.statusCode;
        kirimJson(res, status, { error: { pesan: err.message, detail: err.detail } });
      } else {
        // Error tak terduga (bug): catat lengkap di log, kirim pesan umum ke klien
        logger.error("Error tak terduga:", err);
        kirimJson(res, 500, { error: { pesan: "Terjadi kesalahan pada server" } });
      }
    } finally {
      logger.log(
        JSON.stringify({
          method: req.method,
          path: req.url,
          status,
          ms: Math.round(performance.now() - mulai),
        })
      );
    }
  });
}
```

### 15.9 index.js

Titik awal yang "merakit" semua bagian (sering disebut _composition root_): membuat repositori, memasukkannya ke layanan, memasukkan layanan ke server, lalu menyalakan server. Juga memasang penjaga terakhir untuk error dan _graceful shutdown_ dari Bab 8.

```js
// src/index.js
import path from "node:path";
import { RepositoriProduk } from "./repositori.js";
import { LayananProduk } from "./layanan.js";
import { buatServer } from "./server.js";

const port = Number(process.env.PORT ?? 3000);
const berkasData = process.env.DATA_FILE ?? path.join(import.meta.dirname, "..", "data", "produk.json");

  console.log(`Katalog API berjalan di http://localhost:${port}`);
});

// Penjaga terakhir untuk error yang lolos
process.on("unhandledRejection", (alasan) => {
  console.error("Promise ditolak tanpa penanganan:", alasan);
  process.exit(1);
});
process.on("uncaughtException", (err) => {
  console.error("Exception tak tertangkap:", err);
  process.exit(1);
});

// Graceful shutdown
function berhenti(sinyal) {
  console.log(`Menerima ${sinyal}, menutup server...`);
  server.close(() => process.exit(0));
  setTimeout(() => process.exit(1), 10_000).unref(); // paksa keluar jika terlalu lama
}
process.on("SIGTERM", () => berhenti("SIGTERM"));
process.on("SIGINT", () => berhenti("SIGINT"));
```

Proyek ini sengaja sederhana. Untuk produksi, Anda perlu menggantinya atau menambahkannya:

|Keterbatasan|Solusi di dunia nyata|
|---|---|
|Data di satu file JSON, muat semua ke memori|Database sungguhan (PostgreSQL, MySQL, MongoDB)|
|Hanya aman untuk satu proses|Database mendukung banyak proses dan banyak server|
|Tanpa autentikasi dan otorisasi|Login, token/sesi, dan pengecekan izin (Bab 14.8)|
|Routing dengan regex manual|Framework seperti Fastify, Express, atau Hono|
|Log ke `console`|Logger terstruktur seperti pino, dikirim ke sistem log terpusat|
|Tanpa rate limiting dan CORS|Middleware atau konfigurasi reverse proxy|
|Tanpa dokumentasi API|Spesifikasi OpenAPI/Swagger|

### Tantangan pengembangan

Kerjakan berurutan, dari yang paling mudah:

1. Tambahkan parameter `urut` (misalnya `urut=harga` atau `urut=-harga` untuk menurun) pada `GET /produk`.
2. Tambahkan filter `hargaMin` dan `hargaMaks`.
3. Tambahkan endpoint `POST /produk/:id/stok` yang menambah atau mengurangi stok, dan menolak jika stok akan menjadi negatif (respons `409`).
4. Ganti `console` dengan logger terstruktur dari Bab 13.3, lengkap dengan ID request unik (`randomUUID`).
5. Tambahkan pembatasan request sederhana: maksimum 60 request per menit per alamat IP, dengan respons `429` jika terlampaui.
6. Ganti `RepositoriProduk` dengan versi yang memakai database SQLite (Node.js memiliki modul `node:sqlite` bawaan; periksa statusnya di dokumentasi versi Anda) atau PostgreSQL, **tanpa mengubah `layanan.js`**. Jika pengujian layanan tetap lulus, desain berlapis Anda berhasil.
7. Tulis ulang `server.js` memakai Fastify atau Hono, dengan `layanan.js` yang sama. Rasakan apa yang dilakukan framework untuk Anda.

### 16.2 Peta jalan Backend Developer

Urutan berikut adalah rekomendasi umum. Tidak harus kaku; kuasai satu tahap sambil membuat proyek nyata, baru lanjut.

**Tahap 1: Memperkuat bahasa**

- Kenali basis data dokumen seperti **MongoDB** dan pahami kapan cocok dipakai.

**Tahap 4: Autentikasi dan keamanan**

- Sesi dan cookie, JWT, OAuth 2.0 dan OpenID Connect ("Login dengan Google").

**Tahap 5: Desain API dan arsitektur**

- REST yang baik, versioning, paginasi, idempotensi. Kenali **GraphQL** dan **gRPC**.
- Dokumentasi API dengan **OpenAPI**.
- Konsep arsitektur: _layered architecture_, _clean architecture_, monolit versus microservices, dan pola desain (_design pattern_) dasar.

**Tahap 6: Infrastruktur dan operasi (DevOps dasar)**

- **Git** tingkat lanjut dan alur kerja tim (branch, pull request, code review).
- **Docker** untuk membungkus aplikasi.
- **CI/CD** (misalnya GitHub Actions) untuk menjalankan test dan deploy otomatis.
- Deploy ke VPS atau platform cloud, konfigurasi **Nginx** atau Caddy, HTTPS.
- _Observability_: log, metrik, dan tracing (misalnya OpenTelemetry).

**Tahap 7: Topik lanjutan**

- Antrean pesan dan _background job_ (BullMQ, RabbitMQ, Kafka).
- WebSocket dan _server-sent events_ untuk fitur waktu nyata.
- Pengujian tingkat lanjut (kontrak, beban/_load testing_).
- Performa dan skalabilitas.
