## Tentang Buku Ini

Buku ini adalah bagian dari perjalanan belajar menjadi **Backend Developer**, tepatnya pada langkah **"Learn a Language"** (belajar satu bahasa pemrograman). Bahasa yang dipilih adalah **JavaScript**, dijalankan di sisi server menggunakan **Node.js**.

Buku ini ditulis dengan prinsip berikut:

- **Teknis tetapi ramah pemula.** Istilah teknis tetap dipakai supaya Anda terbiasa dengan bahasa dunia kerja, tetapi setiap istilah dijelaskan dengan bahasa sehari-hari dan analogi.
- **Belajar sambil mengetik.** Setiap konsep disertai contoh kode yang bisa Anda salin, jalankan, lalu ubah sendiri.
- **Fokus pada kebutuhan backend.** Materi dipilih dengan mempertimbangkan apa yang akan Anda pakai saat membuat API, mengolah data, dan berinteraksi dengan file atau jaringan.
- **Relevan untuk tahun 2026.** Contoh kode menggunakan sintaks modern (ES Modules, `async/await`, `fetch` bawaan, dan sebagainya) dan dijalankan di Node.js versi LTS.

### Untuk Siapa Buku Ini

Buku ini cocok untuk Anda yang:

- belum pernah memprogram sama sekali, atau baru sedikit mencoba;
- ingin menjadi backend developer;
- ingin belajar JavaScript secara terstruktur dari nol hingga siap membuat server sederhana.

### Yang Perlu Disiapkan

- Sebuah komputer atau laptop (Windows, macOS, atau Linux) dengan koneksi internet.
- Kemauan untuk mengetik kode sendiri (jangan hanya membaca).
- Waktu belajar rutin. Disarankan 1 sampai 2 jam per hari.

Anda **tidak** perlu jago matematika atau memiliki latar belakang IT.

### Cara Memakai Buku Ini

1. Baca satu bab secara berurutan. Jangan melompat, karena bab-bab saling membangun.
2. Ketik ulang setiap contoh kode, jalankan, dan amati hasilnya.
3. Ubah kode contoh (misalnya ganti angka atau teks) untuk melihat apa yang berubah.
4. Kerjakan **Latihan** di akhir bab **sebelum** melihat kunci jawaban di Lampiran A.
5. Jika buntu lebih dari 20 menit, baca pesan error dengan teliti, lalu cari di dokumentasi. Kemampuan mencari solusi adalah keahlian inti seorang developer.

### Konvensi Penulisan

- Kode ditulis dalam blok seperti ini:

```js
console.log("Halo, dunia!");
```

- Baris yang diawali `//` di dalam kode adalah **komentar**, yaitu catatan untuk manusia yang diabaikan oleh komputer. Dalam buku ini, komentar sering dipakai untuk menunjukkan hasil (output) dari suatu baris kode.
- Kotak kutipan (diawali tanda `>`) berisi **catatan**, **tips**, atau **peringatan** penting.

## Bab 1: Pendahuluan

### Tujuan Bab Ini

Setelah membaca bab ini, Anda akan memahami:

- apa itu backend developer dan apa saja pekerjaannya;
- di mana posisi "belajar bahasa pemrograman" dalam peta belajar backend;
- mengapa JavaScript dan Node.js adalah pilihan yang masuk akal;
- perbedaan antara JavaScript, ECMAScript, dan Node.js;
- rencana belajar yang akan Anda jalani.

### 1.1 Apa Itu Backend Developer

Bayangkan sebuah **restoran**:

- **Ruang makan** (meja, menu, dekorasi) adalah **frontend**. Ini bagian yang dilihat dan disentuh pelanggan.
- **Dapur, gudang bahan, dan kasir** adalah **backend**. Pelanggan tidak melihatnya, tetapi tanpa bagian ini restoran tidak bisa berjalan.

Dalam dunia aplikasi web atau mobile, backend developer bertanggung jawab atas hal-hal yang berjalan di **server**, misalnya:

|Tanggung jawab|Contoh nyata|
|---|---|
|Membuat **API** (Application Programming Interface)|Aplikasi mobile meminta daftar produk, server mengirimkannya|
|Mengelola **database**|Menyimpan data pengguna, pesanan, dan transaksi|
|**Autentikasi** dan **otorisasi**|Login, logout, menentukan siapa boleh mengakses apa|
|Menjalankan **logika bisnis**|Menghitung total belanja, diskon, dan pajak|
|Menjaga **keamanan**|Mencegah data bocor atau disalahgunakan|
|Menjaga **performa** dan **skalabilitas**|Aplikasi tetap cepat saat penggunanya bertambah|
|**Deployment** dan operasional|Menaruh aplikasi di server agar bisa diakses publik|

Alur sederhananya:

```text
Pengguna  ->  Frontend (browser/aplikasi)  ->  Backend (server)  ->  Database
                                              <-  respons (data)  <-
```

### 1.2 Peta Belajar Backend Developer

Belajar backend itu seperti membangun rumah. Bahasa pemrograman adalah salah satu pondasinya. Berikut urutan umum yang dianjurkan:

1. Dasar internet: HTTP, DNS, hosting, browser.
2. **Learn a Language** (buku ini): JavaScript, Python, Go, Java, PHP, C#, dan lainnya.
3. Version control: Git dan GitHub.
4. Database: SQL (misalnya PostgreSQL, MySQL) dan NoSQL (misalnya MongoDB).
5. Membuat API: REST, lalu mungkin GraphQL atau gRPC.
6. Autentikasi: session, token (JWT), OAuth.
7. Caching, antrean pesan (message queue), dan pencarian.
8. Testing: unit test dan integration test.
9. Deployment: Linux dasar, Docker, CI/CD, cloud.
10. Observabilitas: logging, monitoring, dan penanganan insiden.

Buku ini fokus pada langkah nomor 2.

> **Catatan:** Tidak ada bahasa yang paling benar. Konsep yang Anda pelajari (variabel, fungsi, struktur data, asynchronous, dan lain-lain) akan berguna di bahasa apa pun. Memilih satu bahasa dan mendalaminya jauh lebih baik daripada berpindah-pindah.

### 1.3 Mengapa JavaScript untuk Backend

**Kelebihan:**

- **Satu bahasa untuk frontend dan backend.** Jika suatu hari Anda ingin memahami sisi frontend, Anda tidak perlu belajar bahasa baru.
- **Ekosistem sangat besar.** Registry paket **npm** menyimpan jutaan paket siap pakai.
- **Cocok untuk pekerjaan I/O** (input/output), yaitu aplikasi yang banyak menunggu database, file, atau jaringan. Ini adalah kasus umum di backend web.
- **Komunitas dan lowongan kerja luas.**
- **Mudah dimulai.** Cukup instal Node.js, tanpa konfigurasi rumit.

**Kekurangan (yang perlu Anda sadari sejak awal):**

- **Dynamically typed.** Tipe data variabel ditentukan saat program berjalan, sehingga beberapa kesalahan baru ketahuan belakangan. Solusinya adalah **TypeScript** (dibahas singkat di Bab 19).
- **Ada beberapa keanehan historis** (misalnya `typeof null` menghasilkan `"object"`). Buku ini akan menunjukkan jebakan-jebakannya.
- **Kurang ideal untuk komputasi berat** (CPU-bound) seperti pemrosesan video, karena JavaScript pada dasarnya berjalan dengan satu thread utama. Ada solusi seperti Worker Threads, tetapi itu topik lanjutan.

### 1.4 JavaScript, ECMAScript, dan Node.js

Tiga istilah ini sering membingungkan pemula:

|Istilah|Penjelasan|Analogi|
|---|---|---|
|**ECMAScript** (ES)|**Standar/spesifikasi** bahasa yang ditulis oleh badan bernama Ecma International. Setiap tahun ada versi baru (ES2015, ES2016, dan seterusnya).|Buku aturan tata bahasa|
|**JavaScript**|**Bahasa pemrograman** yang mengikuti standar ECMAScript.|Bahasa Indonesia yang dipakai sehari-hari|
|**Node.js**|**Runtime**, yaitu program yang memungkinkan JavaScript berjalan **di luar browser** (misalnya di server). Dibangun di atas mesin V8 milik Chrome.|Penerjemah yang membuat bahasa itu bisa dipakai di banyak tempat|

Selain Node.js ada runtime lain seperti **Deno** dan **Bun**. Semuanya menjalankan JavaScript yang sama. Buku ini memakai Node.js karena paling luas digunakan dan dokumentasinya paling lengkap.

### 1.5 Bagaimana JavaScript Dijalankan

Komputer tidak langsung mengerti teks kode yang Anda tulis. Di dalam Node.js ada **mesin JavaScript (engine) bernama V8**. Tugasnya membaca kode Anda, menerjemahkannya ke instruksi mesin, dan menjalankannya. Anda cukup menulis kode dan menjalankan perintah `node`, sisanya diurus oleh runtime.

Ada satu hal penting yang perlu diingat sejak awal: **JavaScript menjalankan kode Anda satu per satu pada satu jalur utama (single-threaded)**. Nanti di Bab 13 Anda akan belajar bagaimana Node.js tetap bisa melayani banyak permintaan sekaligus dengan pola asynchronous.

## Bab 2: Menyiapkan Lingkungan Belajar

### Tujuan Bab Ini

- Menginstal Node.js dan editor kode.
- Mengenal terminal dan perintah dasarnya.
- Menjalankan program JavaScript pertama.

### 2.1 Menginstal Node.js

Node.js memiliki dua jenis rilis:

- **LTS (Long Term Support):** stabil, didukung lama, **direkomendasikan untuk belajar dan produksi**.
- **Current:** membawa fitur terbaru, tetapi masa dukungannya lebih pendek.

Untuk belajar, **selalu pilih versi LTS terbaru**. Pada saat buku ini ditulis (akhir September 2026), Node.js 24 adalah versi LTS aktif, sedangkan Node.js 26 dirilis pada Mei 2026 dan dijadwalkan menjadi LTS pada Oktober 2026. Semua contoh dalam buku ini berjalan di Node.js 22 ke atas.

**Langkah instalasi:**

1. Buka situs resmi: `https://nodejs.org`.
2. Unduh installer versi **LTS** sesuai sistem operasi Anda, lalu jalankan.
3. Setelah selesai, buka **terminal** (lihat bagian 2.3) dan ketik:

```bash
node --version
npm --version
```

Jika muncul nomor versi (misalnya `v24.x.x`), instalasi berhasil.

> **Tips:** Jika nanti Anda perlu berpindah-pindah versi Node.js antar proyek, gunakan **version manager** seperti `nvm`, `fnm`, atau `Volta`. Untuk pemula, installer biasa sudah cukup.

### 2.2 Menginstal Code Editor

Anda dapat memakai editor teks apa saja, tetapi **Visual Studio Code (VS Code)** sangat populer, gratis, dan dilengkapi fitur untuk pemrograman.

Ekstensi yang berguna (opsional, bisa dipasang nanti):

- **ESLint:** memeriksa kualitas dan kesalahan kode.
- **Prettier:** merapikan format kode secara otomatis.

### 2.3 Mengenal Terminal

**Terminal** (atau command line) adalah jendela tempat Anda mengetik perintah teks untuk mengendalikan komputer. Seorang backend developer akan sangat sering memakainya.

- Windows: **PowerShell** atau **Windows Terminal**.
- macOS: aplikasi **Terminal**.
- Linux: **Terminal** bawaan distribusi Anda.
- VS Code juga memiliki terminal bawaan (menu **Terminal > New Terminal**).

Perintah dasar yang perlu dikuasai:

|Tujuan|macOS / Linux|Windows (PowerShell)|
|---|---|---|
|Melihat lokasi folder saat ini|`pwd`|`pwd`|
|Melihat isi folder|`ls`|`ls` atau `dir`|
|Pindah ke folder|`cd nama-folder`|`cd nama-folder`|
|Naik satu level folder|`cd ..`|`cd ..`|
|Membuat folder|`mkdir nama-folder`|`mkdir nama-folder`|
|Menghapus file|`rm nama-file`|`del nama-file`|
|Membersihkan layar|`clear`|`cls`|

### 2.4 Membuat Folder Belajar

Buat folder khusus untuk semua latihan Anda:

```bash
mkdir belajar-js
cd belajar-js
npm init -y
```

Perintah `npm init -y` membuat file **`package.json`**, yaitu "kartu identitas" proyek Node.js Anda. Buka file tersebut dan tambahkan baris `"type": "module"` seperti berikut:

```json
{
  "name": "belajar-js",
  "version": "1.0.0",
  "type": "module"
}
```

Baris `"type": "module"` memberi tahu Node.js bahwa proyek ini memakai **ES Modules** (`import` dan `export`), yaitu cara modern untuk membagi kode ke banyak file. Penjelasan lengkapnya ada di Bab 14.

### 2.5 Program Pertama

Buat file bernama `halo.js` di dalam folder `belajar-js`, isi dengan:

```js
console.log("Halo, dunia!");
```

Jalankan dari terminal:

```bash
node halo.js
```

Hasilnya:

```text
Halo, dunia!
```

Selamat, Anda baru saja menjalankan program JavaScript di sisi server.

**Penjelasan:**

- `console` adalah objek bawaan untuk menampilkan informasi ke terminal.
- `.log(...)` adalah **method** (fungsi milik objek) untuk mencetak nilai.
- `"Halo, dunia!"` adalah **string** (teks) yang dicetak.
- `;` menandai akhir sebuah pernyataan.

### 2.6 Mode Interaktif (REPL)

Jika Anda mengetik `node` saja tanpa nama file, Anda masuk ke **REPL** (Read-Eval-Print Loop), yaitu tempat mencoba kode baris per baris:

```text
$ node
> 2 + 3
5
> "halo".toUpperCase()
'HALO'
> .exit
```

REPL sangat berguna untuk bereksperimen cepat. Ketik `.exit` atau tekan `Ctrl + C` dua kali untuk keluar.

### 2.7 Menjalankan Ulang Otomatis

Agar tidak mengetik `node namafile.js` setiap kali mengubah kode, gunakan mode **watch** bawaan Node.js:

```bash
node --watch halo.js
```

Setiap kali Anda menyimpan file, program akan dijalankan ulang otomatis.

### 2.8 Struktur Folder yang Disarankan

Agar rapi, buat subfolder per bab:

```text
belajar-js/
  package.json
  bab03/
    variabel.js
  bab04/
    tipe-data.js
  ...
```

Jalankan dengan menyebutkan path-nya, misalnya `node bab03/variabel.js`.

### 2.9 Kesalahan Umum Saat Memulai

|Gejala|Kemungkinan penyebab|Solusi|
|---|---|---|
|`node: command not found` atau `'node' is not recognized`|Node.js belum terpasang atau terminal belum dibuka ulang|Instal ulang, lalu tutup dan buka kembali terminal|
|`Cannot find module '...'`|Anda menjalankan perintah dari folder yang salah atau salah menulis nama file|Cek `pwd` dan `ls`, pastikan nama file benar|
|`SyntaxError: Cannot use import statement outside a module`|Belum menambahkan `"type": "module"` di `package.json`|Tambahkan seperti pada bagian 2.4|

## Bab 3: Sintaks Dasar, Variabel, dan Konstanta

### Tujuan Bab Ini

- Memahami aturan penulisan dasar JavaScript.
- Menggunakan `let` dan `const` untuk menyimpan data.
- Memahami scope dan hoisting secara ringkas.

### 3.1 Statement, Ekspresi, dan Komentar

- **Statement (pernyataan)** adalah satu instruksi lengkap, misalnya `console.log("hai");`.
- **Ekspresi (expression)** adalah potongan kode yang **menghasilkan nilai**, misalnya `2 + 3` yang menghasilkan `5`.

```js
// Ini komentar satu baris

/*
  Ini komentar
  beberapa baris
*/

console.log(2 + 3); // 5
```

Aturan dasar:

- JavaScript **case-sensitive**: `nama` dan `Nama` adalah dua hal yang berbeda.
- Titik koma (`;`) di akhir statement **bersifat opsional** karena JavaScript bisa menyisipkannya otomatis, tetapi otomatis ini kadang menimbulkan kejutan. **Pilih satu gaya dan konsisten.** Buku ini selalu memakai titik koma.
- Spasi dan baris kosong tidak memengaruhi hasil, tetapi sangat memengaruhi keterbacaan.

### 3.2 Menampilkan Output dengan console

```js
console.log("Pesan biasa");
console.error("Pesan error (ke stderr)");
console.warn("Peringatan");
console.table([
  { nama: "Sari", umur: 25 },
  { nama: "Budi", umur: 30 },
]);
```

`console.log` bisa menerima banyak argumen sekaligus:

```js
console.log("Umur saya:", 25, "tahun"); // Umur saya: 25 tahun
```

### 3.3 Variabel

**Variabel** adalah "kotak bernama" untuk menyimpan data. Anda membuat kotak, memberinya nama, lalu mengisinya.

```js
let nama = "Sari";
console.log(nama); // Sari

nama = "Budi"; // isi kotak diganti
console.log(nama); // Budi
```

Alur di atas:

1. `let nama` : **deklarasi**, yaitu membuat kotak bernama `nama`.
2. `= "Sari"` : **inisialisasi/assignment**, yaitu mengisi kotak dengan nilai.
3. `nama = "Budi"` : **assignment ulang**, isi kotak diganti.

### 3.4 `let`, `const`, dan `var`

JavaScript punya tiga kata kunci untuk mendeklarasikan variabel:

|Kata kunci|Bisa diisi ulang?|Scope|Dipakai di era modern?|
|---|---|---|---|
|`const`|Tidak|Block|Ya, **pilihan utama**|
|`let`|Ya|Block|Ya, jika nilainya memang berubah|
|`var`|Ya|Function|Hindari, ini gaya lama|

```js
const PI = 3.14159;
// PI = 3; // TypeError: Assignment to constant variable.

let skor = 0;
skor = skor + 10;
console.log(skor); // 10
```

**Aturan praktis:**

1. Mulai dengan `const` untuk semua variabel.
2. Ubah menjadi `let` **hanya jika** Anda memang perlu mengisi ulang variabel tersebut.
3. Jangan gunakan `var` pada kode baru.

> **Peringatan (kesalahpahaman yang sangat umum):** `const` **bukan berarti isinya tidak bisa berubah**. `const` hanya melarang **mengganti kotaknya dengan nilai lain**. Jika isinya adalah array atau object, isi di dalamnya masih bisa dimodifikasi.

```js
const buah = ["apel", "jeruk"];
buah.push("mangga"); // boleh, isi array diubah
console.log(buah); // [ 'apel', 'jeruk', 'mangga' ]

// buah = ["pisang"]; // TypeError, kotaknya tidak boleh diganti
```

### 3.5 Aturan dan Konvensi Penamaan

**Aturan wajib (kalau dilanggar, error):**

- Boleh berisi huruf, angka, garis bawah `_`, dan tanda dolar `$`.
- **Tidak boleh diawali angka.**
- **Tidak boleh memakai kata kunci** bahasa (misalnya `class`, `return`, `if`).
- Tidak boleh mengandung spasi atau tanda hubung.

**Konvensi (tidak wajib, tetapi dipakai hampir semua developer):**

|Gaya|Contoh|Dipakai untuk|
|---|---|---|
|`camelCase`|`namaLengkap`, `hitungTotal`|Variabel dan fungsi|
|`PascalCase`|`UserService`, `Produk`|Class|
|`UPPER_SNAKE_CASE`|`MAX_RETRY`, `API_URL`|Konstanta bernilai tetap|

Gunakan nama yang **menjelaskan isi**. Bandingkan:

```js
// Buruk
const x = 17;
const d = 3;

// Baik
const umurPengguna = 17;
const jumlahPercobaan = 3;
```

### 3.6 Scope (Ruang Lingkup)

**Scope** menentukan di mana sebuah variabel bisa diakses.

```js
const globalNama = "bisa dilihat di mana saja di file ini";

if (true) {
  const dalamBlok = "hanya hidup di dalam kurung kurawal ini";
  console.log(dalamBlok); // berhasil
  console.log(globalNama); // berhasil
}

// console.log(dalamBlok); // ReferenceError: dalamBlok is not defined
```

Aturan sederhananya: variabel `let` dan `const` **hanya hidup di dalam pasangan kurung kurawal `{ }`** tempat ia dibuat. Kode di dalam blok bisa melihat ke luar, tetapi kode di luar tidak bisa melihat ke dalam.

### 3.7 Hoisting dan Temporal Dead Zone (Ringkas)

**Hoisting** adalah perilaku JavaScript yang "mengangkat" deklarasi ke atas scope sebelum kode dijalankan. Efeknya berbeda antara `var` dan `let`/`const`:

```js
console.log(a); // undefined (var "terangkat", tetapi belum diisi)
var a = 5;

// console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 5;
```

Pada `let` dan `const`, ada masa antara awal scope hingga baris deklarasi yang disebut **Temporal Dead Zone (TDZ)**. Mengakses variabel pada masa itu menghasilkan error. Ini **lebih baik** daripada perilaku `var` yang diam-diam menghasilkan `undefined`, karena kesalahan Anda langsung ketahuan.

> **Kesimpulan praktis:** deklarasikan variabel di **atas** sebelum dipakai, gunakan `const`/`let`, dan hindari `var`.

## Bab 4: Tipe Data

### Tujuan Bab Ini

- Mengenal tipe data primitif dan non-primitif.
- Memakai `typeof` untuk memeriksa tipe.
- Memahami konsep truthy/falsy dan konversi tipe.
- Mengenali jebakan umum: `NaN`, `null`, dan ketidaktelitian angka desimal.

### 4.1 Apa Itu Tipe Data

Setiap nilai di JavaScript memiliki **tipe**. Tipe menentukan apa yang bisa dilakukan dengan nilai tersebut. Anda bisa menjumlahkan dua angka, tetapi menjumlahkan dua nama tidak berarti apa-apa (hasilnya digabung, bukan dijumlahkan).

JavaScript memiliki dua kelompok tipe:

**Tipe primitif** (nilai sederhana, tidak bisa diubah isinya, hanya bisa diganti):

|Tipe|Contoh|Keterangan|
|---|---|---|
|`string`|`"halo"`, `'dunia'`|Teks|
|`number`|`42`, `3.14`, `-7`|Angka bulat maupun desimal|
|`bigint`|`9007199254740993n`|Angka bulat sangat besar|
|`boolean`|`true`, `false`|Benar atau salah|
|`undefined`|`undefined`|Variabel ada, tetapi belum diisi|
|`null`|`null`|"Kosong" yang disengaja|
|`symbol`|`Symbol("id")`|Pengenal unik (jarang dipakai pemula)|

**Tipe non-primitif** (referensi): `object`, termasuk **array**, **function**, `Date`, `Map`, `Set`, dan lainnya. Ini dibahas di bab-bab berikutnya.

JavaScript adalah bahasa **dynamically typed**: Anda tidak menuliskan tipe saat membuat variabel, dan tipe nilai di dalam variabel bisa berubah.

```js
let sesuatu = 10; // number
sesuatu = "sepuluh"; // sekarang string, JavaScript tidak protes
```

Fleksibel, tetapi juga rawan salah. Karena itu Anda perlu disiplin.

### 4.2 Memeriksa Tipe dengan `typeof`

```js
console.log(typeof "halo"); // "string"
console.log(typeof 42); // "number"
console.log(typeof true); // "boolean"
console.log(typeof undefined); // "undefined"
console.log(typeof 10n); // "bigint"
console.log(typeof Symbol("x")); // "symbol"
console.log(typeof {}); // "object"
console.log(typeof []); // "object"  (array juga object)
console.log(typeof function () {}); // "function"
console.log(typeof null); // "object"  (bug historis!)
```

> **Peringatan:** `typeof null` menghasilkan `"object"`. Ini adalah **bug lama** yang tidak diperbaiki demi kompatibilitas. Untuk memeriksa `null`, gunakan `nilai === null`. Untuk memeriksa array, gunakan `Array.isArray(nilai)`.

### 4.3 String

String adalah teks. Boleh memakai tanda kutip ganda `" "`, tunggal `' '`, atau **backtick** `` ` ` ``.

```js
const a = "Halo";
const b = 'Dunia';
const c = `Backtick`;
```

**Template literal** (memakai backtick) adalah cara paling nyaman untuk menyisipkan nilai ke dalam teks memakai `${ }`:

```js
const nama = "Sari";
const umur = 25;

// Cara lama: digabung dengan +
console.log("Nama: " + nama + ", umur: " + umur);

// Cara modern: template literal
console.log(`Nama: ${nama}, umur: ${umur}`);
console.log(`Tahun depan umur saya ${umur + 1}`); // ekspresi boleh di dalam ${}
```

Template literal juga mendukung teks beberapa baris:

```js
const pesan = `Baris pertama
Baris kedua
Baris ketiga`;
console.log(pesan);
```

Karakter spesial (escape sequence):

|Penulisan|Arti|
|---|---|
|`\n`|Baris baru|
|`\t`|Tab|
|`\"`|Tanda kutip ganda|
|`\\`|Garis miring terbalik|

### 4.4 Number

JavaScript hanya memiliki satu tipe angka biasa (`number`) untuk bilangan bulat maupun desimal.

```js
const bulat = 42;
const desimal = 3.14;
const negatif = -10;
const ilmiah = 1.5e3; // 1500
```

Nilai khusus:

```js
console.log(1 / 0); // Infinity
console.log(-1 / 0); // -Infinity
console.log("abc" * 2); // NaN  (Not a Number)
console.log(typeof NaN); // "number" (aneh, tetapi benar)
console.log(NaN === NaN); // false  (NaN tidak sama dengan dirinya sendiri)
console.log(Number.isNaN(NaN)); // true  (cara yang benar untuk memeriksa NaN)
```

**Jebakan desimal.** Komputer menyimpan angka dalam biner, sehingga sebagian desimal tidak persis:

```js
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false
```

Ini terjadi di hampir semua bahasa pemrograman, bukan kekurangan JavaScript saja. Untuk **uang**, jangan simpan dalam desimal. Simpan dalam **satuan terkecil** berupa bilangan bulat (misalnya rupiah utuh, atau sen), dan konversi hanya saat ditampilkan.

```js
const hargaDalamSen = 1999; // 19,99 disimpan sebagai 1999
```

Aman atau tidaknya bilangan bulat:

```js
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991
```

Di atas angka itu, ketelitian hilang. Untuk angka bulat yang lebih besar, gunakan `bigint`.

Fungsi yang sering dipakai:

```js
console.log(Number.isInteger(5)); // true
console.log(Number("42")); // 42
console.log(parseInt("42px")); // 42 (membaca angka di awal teks)
console.log(parseFloat("3.14abc")); // 3.14
console.log((3.14159).toFixed(2)); // "3.14" (hasilnya string!)
```

### 4.5 BigInt

Diberi akhiran `n`. Dipakai untuk bilangan bulat yang sangat besar (misalnya ID dari sistem tertentu).

```js
const besar = 9007199254740993n;
console.log(besar + 1n); // 9007199254740994n
// console.log(besar + 1); // TypeError: tidak boleh dicampur dengan number biasa
```

### 4.6 Boolean, Truthy, dan Falsy

`boolean` hanya punya dua nilai: `true` dan `false`.

Yang menarik: pada kondisi (misalnya `if`), **setiap nilai** akan dianggap sebagai benar atau salah.

**Nilai falsy** (dianggap salah). Hafalkan daftar ini, jumlahnya hanya delapan:

```text
false, 0, -0, 0n, "" (string kosong), null, undefined, NaN
```

**Semua nilai selain itu adalah truthy** (dianggap benar), termasuk `"0"`, `"false"`, `[]` (array kosong), dan `{}` (object kosong).

```js
console.log(Boolean(0)); // false
console.log(Boolean("")); // false
console.log(Boolean("halo")); // true
console.log(Boolean([])); // true  (array kosong tetap truthy!)
console.log(Boolean({})); // true
```

### 4.7 `undefined` dan `null`

Keduanya berarti "tidak ada nilai", tetapi maknanya berbeda:

||`undefined`|`null`|
|---|---|---|
|Arti|"Belum diberi nilai"|"Sengaja dikosongkan"|
|Siapa yang menghasilkan|JavaScript otomatis|Programmer sendiri|

```js
let belumDiisi;
console.log(belumDiisi); // undefined

const dikosongkan = null;
console.log(dikosongkan); // null

const orang = { nama: "Sari" };
console.log(orang.umur); // undefined (properti tidak ada)
```

Sebagai kebiasaan baik, gunakan `null` jika Anda ingin menyatakan "sengaja kosong", dan biarkan `undefined` muncul secara alami.

### 4.8 Konversi Tipe

**Konversi eksplisit** (Anda yang meminta):

```js
console.log(Number("123")); // 123
console.log(Number("abc")); // NaN
console.log(Number("")); // 0  (hati-hati)
console.log(String(123)); // "123"
console.log(Boolean("halo")); // true
console.log(parseInt("101", 2)); // 5 (membaca sebagai biner)
```

**Konversi implisit / type coercion** (JavaScript melakukannya otomatis, sering mengejutkan):

```js
console.log("5" + 3); // "53"  (angka diubah jadi string lalu digabung)
console.log("5" - 3); // 2     (string diubah jadi angka)
console.log("5" * "2"); // 10
console.log(true + 1); // 2
console.log([] + []); // ""
```

Aturan yang harus diingat: operator `+` **memprioritaskan penggabungan string** jika salah satu sisinya string. Operator `-`, `*`, `/` selalu mencoba mengubah ke angka.

> **Praktik baik:** Jangan mengandalkan konversi implisit. Ubah tipe secara **eksplisit** agar maksud kode jelas. Data dari luar (input pengguna, query string, isi file) hampir selalu berupa string, jadi biasakan mengubahnya dulu.

## Bab 5: Operator

### Tujuan Bab Ini

- Menggunakan operator aritmatika, assignment, perbandingan, dan logika.
- Memahami perbedaan `==` dan `===`.
- Memakai operator modern: `??`, `?.`, dan ternary.

### 5.1 Operator Aritmatika

|Operator|Nama|Contoh|Hasil|
|---|---|---|---|
|`+`|Tambah|`7 + 2`|`9`|
|`-`|Kurang|`7 - 2`|`5`|
|`*`|Kali|`7 * 2`|`14`|
|`/`|Bagi|`7 / 2`|`3.5`|
|`%`|Sisa bagi (modulo)|`7 % 2`|`1`|
|`**`|Pangkat|`7 ** 2`|`49`|

Modulo sangat berguna. Contoh: memeriksa bilangan genap/ganjil, atau membuat siklus.

```js
console.log(10 % 2); // 0 -> genap
console.log(11 % 2); // 1 -> ganjil
```

Increment dan decrement:

```js
let n = 5;
n++; // sama dengan n = n + 1
console.log(n); // 6
n--; // sama dengan n = n - 1
console.log(n); // 5
```

### 5.2 Operator Assignment

|Operator|Arti|
|---|---|
|`=`|Isi nilai|
|`+=`|`x = x + y`|
|`-=`|`x = x - y`|
|`*=`|`x = x * y`|
|`/=`|`x = x / y`|

```js
let saldo = 100;
saldo += 50; // 150
saldo -= 30; // 120
saldo *= 2; // 240
console.log(saldo); // 240
```

### 5.3 Operator Perbandingan

Hasilnya selalu `boolean`.

|Operator|Arti|
|---|---|
|`===`|Sama **nilai dan tipe** (strict equality)|
|`!==`|Tidak sama nilai atau tipe (strict)|
|`>` `<` `>=` `<=`|Lebih besar, lebih kecil, dan seterusnya|
|`==`|Sama nilai setelah konversi tipe (loose), **hindari**|
|`!=`|Kebalikannya, **hindari**|

```js
console.log(5 === 5); // true
console.log(5 === "5"); // false (tipe beda)
console.log(5 == "5"); // true  (loose, karena dikonversi)
console.log(0 == false); // true  (membingungkan)
console.log(null == undefined); // true
console.log(null === undefined); // false
```

> **Aturan emas:** Selalu gunakan `===` dan `!==`. Operator `==` menjalankan aturan konversi rumit yang sering menghasilkan kejutan, sehingga bug-nya sulit dilacak.

### 5.4 Operator Logika

|Operator|Nama|Arti|
|---|---|---|
|`&&`|AND|Benar jika **keduanya** benar|
|`\|`|OR|Benar jika **salah satu** benar|
|`!`|NOT|Membalik nilai|

```js
const umur = 20;
const punyaKTP = true;

console.log(umur >= 17 && punyaKTP); // true
console.log(umur < 17 || punyaKTP); // true
console.log(!punyaKTP); // false
```

**Short-circuit evaluation.** `&&` dan `||` sebenarnya tidak mengembalikan `true`/`false`, melainkan **salah satu operandnya**, dan berhenti membaca begitu hasilnya pasti:

```js
console.log("halo" || "cadangan"); // "halo"      (kiri truthy, langsung dipakai)
console.log("" || "cadangan"); // "cadangan" (kiri falsy, pakai kanan)
console.log("halo" && "dunia"); // "dunia"    (kiri truthy, hasil = kanan)
console.log(0 && "dunia"); // 0          (kiri falsy, berhenti di sini)
```

Ini sering dipakai untuk **nilai cadangan (default)**:

```js
const namaPengguna = "" || "Tamu";
console.log(namaPengguna); // "Tamu"
```

### 5.5 Nullish Coalescing `??`

Masalah dengan `||`: ia menganggap `0` dan `""` sebagai "kosong", padahal bisa jadi itu nilai yang sah.

```js
const jumlah = 0;
console.log(jumlah || 10); // 10  (salah! 0 dianggap kosong)
console.log(jumlah ?? 10); // 0   (benar)
```

Operator `??` hanya memakai nilai cadangan jika sisi kiri adalah **`null` atau `undefined`**. Untuk nilai default, `??` biasanya pilihan yang lebih aman.

### 5.6 Optional Chaining `?.`

Mengakses properti dari `undefined` atau `null` menyebabkan error. Operator `?.` membuatnya aman:

```js
const pengguna = { nama: "Sari" };

// console.log(pengguna.alamat.kota); // TypeError: Cannot read properties of undefined
console.log(pengguna.alamat?.kota); // undefined (tidak error)
console.log(pengguna.alamat?.kota ?? "Tidak diketahui"); // "Tidak diketahui"
```

Kombinasi `?.` dan `??` sangat umum ketika memproses data JSON dari luar yang strukturnya belum pasti.

### 5.7 Operator Logical Assignment

Singkatan untuk pola "isi jika kosong":

```js
let konfig = { port: null };

konfig.port ??= 3000; // isi hanya jika null/undefined
console.log(konfig.port); // 3000
```

Ada juga `||=` (isi jika falsy) dan `&&=` (isi jika truthy).

### 5.8 Operator Ternary

Bentuk singkat dari if-else yang menghasilkan nilai:

```js
kondisi ? nilaiJikaBenar : nilaiJikaSalah
```

```js
const umur = 16;
const status = umur >= 17 ? "boleh" : "belum boleh";
console.log(status); // "belum boleh"
```

Gunakan untuk kasus sederhana. Jika kondisinya bersarang (ternary di dalam ternary), gunakan `if` agar mudah dibaca.

### 5.9 Urutan Prioritas Operator

Seperti matematika, ada urutan prioritas (`*` lebih dulu daripada `+`). Anda tidak perlu menghafal semuanya. **Gunakan tanda kurung** untuk memperjelas:

```js
console.log(2 + 3 * 4); // 14
console.log((2 + 3) * 4); // 20
```

## Bab 6: Percabangan (Kontrol Alur)

### Tujuan Bab Ini

- Membuat program yang mengambil keputusan dengan `if`, `else if`, `else`.
- Memakai `switch` untuk banyak pilihan.
- Menerapkan pola guard clause agar kode lebih bersih.

### 6.1 Mengapa Butuh Percabangan

Program yang hanya berjalan lurus dari atas ke bawah sangat terbatas. Aplikasi nyata harus **mengambil keputusan**: jika password salah, tolak login; jika stok habis, tampilkan pesan. Itulah gunanya percabangan.

### 6.2 `if`, `else if`, `else`

```js
const nilai = 78;

if (nilai >= 90) {
  console.log("Grade A");
} else if (nilai >= 75) {
  console.log("Grade B");
} else if (nilai >= 60) {
  console.log("Grade C");
} else {
  console.log("Grade D");
}
// Output: Grade B
```

Cara kerja: JavaScript memeriksa kondisi dari atas. **Begitu ada yang benar**, blok itu dijalankan dan sisanya **dilewati**. Bagian `else` dijalankan jika semua kondisi di atasnya salah.

Kondisi di dalam tanda kurung akan dikonversi menjadi truthy/falsy, sehingga ini valid:

```js
const daftarPesan = [];

if (daftarPesan.length) {
  console.log("Ada pesan");
} else {
  console.log("Tidak ada pesan"); // dijalankan, karena length = 0 (falsy)
}
```

> **Peringatan:** Jangan salah menulis `=` (assignment) sebagai `===` (perbandingan) di dalam kondisi. `if (x = 5)` mengisi `x` dengan 5, bukan membandingkannya.

### 6.3 Menggabungkan Kondisi

```js
const umur = 25;
const punyaSIM = true;

if (umur >= 17 && punyaSIM) {
  console.log("Boleh mengemudi");
}

const hari = "sabtu";
if (hari === "sabtu" || hari === "minggu") {
  console.log("Akhir pekan");
}
```

### 6.4 `switch`

Cocok ketika satu nilai dibandingkan dengan banyak kemungkinan yang pasti.

```js
const hari = "selasa";

switch (hari) {
  case "senin":
    console.log("Awal pekan");
    break;
  case "selasa":
  case "rabu":
    console.log("Tengah pekan");
    break;
  case "sabtu":
  case "minggu":
    console.log("Akhir pekan");
    break;
  default:
    console.log("Hari lainnya");
}
// Output: Tengah pekan
```

Poin penting:

- `break` menghentikan `switch`. **Jika lupa `break`**, eksekusi "jatuh" ke case berikutnya (fall-through).
- `default` berjalan jika tidak ada case yang cocok (seperti `else`).
- `switch` memakai perbandingan **strict** (`===`).

### 6.5 Guard Clause (Early Return)

Kode dengan `if` bersarang dalam-dalam sulit dibaca. Pola **guard clause** memeriksa kondisi buruk **lebih dulu** lalu keluar, sehingga sisanya lurus dan rapi. (Anda akan mengenal `return` lebih dalam di Bab 8.)

Sebelum:

```js
function prosesPesanan(pesanan) {
  if (pesanan) {
    if (pesanan.items.length > 0) {
      if (pesanan.stokTersedia) {
        return "Pesanan diproses";
      } else {
        return "Stok habis";
      }
    } else {
      return "Keranjang kosong";
    }
  } else {
    return "Pesanan tidak valid";
  }
}
```

Sesudah (guard clause):

```js
function prosesPesanan(pesanan) {
  if (!pesanan) return "Pesanan tidak valid";
  if (pesanan.items.length === 0) return "Keranjang kosong";
  if (!pesanan.stokTersedia) return "Stok habis";

  return "Pesanan diproses";
}
```

Versi kedua lebih pendek dan alurnya lebih mudah diikuti. Pola ini akan sangat sering Anda pakai untuk validasi input di backend.

### 6.6 Contoh Nyata: Validasi Pendaftaran

```js
const email = "sari@contoh.com";
const password = "rahasia123";

if (!email.includes("@")) {
  console.log("Email tidak valid");
} else if (password.length < 8) {
  console.log("Password minimal 8 karakter");
} else {
  console.log("Pendaftaran berhasil");
}
// Output: Pendaftaran berhasil
```

Validasi seperti ini akan menjadi dasar dari endpoint pendaftaran pengguna di backend.

## Bab 7: Perulangan

### Tujuan Bab Ini

- Menjalankan kode berulang dengan `for`, `while`, dan `do...while`.
- Memakai `for...of` dan `for...in`.
- Mengendalikan perulangan dengan `break` dan `continue`.

### 7.1 Mengapa Butuh Perulangan

Bayangkan mencetak angka 1 sampai 1000. Menulis `console.log` seribu kali tentu tidak masuk akal. **Perulangan (loop)** memungkinkan satu blok kode dijalankan berkali-kali.

Di backend, perulangan dipakai untuk memproses daftar data: setiap pengguna, setiap pesanan, setiap baris file.

### 7.2 Perulangan `for`

Bentuk umum:

```js
for (inisialisasi; kondisi; langkah) {
  // kode yang diulang
}
```

```js
for (let i = 1; i <= 5; i++) {
  console.log(`Perulangan ke-${i}`);
}
```

Cara membacanya:

1. `let i = 1` dijalankan **sekali** di awal.
2. `i <= 5` diperiksa sebelum setiap putaran. Jika benar, blok dijalankan.
3. `i++` dijalankan setelah setiap putaran.
4. Kembali ke langkah 2 sampai kondisi salah.

Contoh menjumlahkan angka 1 sampai 100:

```js
let total = 0;
for (let i = 1; i <= 100; i++) {
  total += i;
}
console.log(total); // 5050
```

### 7.3 Perulangan `while`

Dipakai ketika **jumlah putaran tidak diketahui di awal**, hanya tahu kapan harus berhenti.

```js
let angka = 1;
while (angka <= 3) {
  console.log(angka);
  angka++;
}
```

> **Peringatan (infinite loop):** Jika kondisi tidak pernah menjadi salah (misalnya lupa `angka++`), program berputar selamanya dan terminal seperti membeku. Tekan `Ctrl + C` untuk menghentikannya.

### 7.4 Perulangan `do...while`

Blok dijalankan **minimal satu kali**, baru kemudian kondisi diperiksa.

```js
let percobaan = 0;
do {
  console.log(`Percobaan ke-${percobaan + 1}`);
  percobaan++;
} while (percobaan < 3);
```

### 7.5 `break` dan `continue`

- `break` : keluar dari perulangan seketika.
- `continue` : lewati sisa putaran saat ini, lanjut ke putaran berikutnya.

```js
for (let i = 1; i <= 10; i++) {
  if (i === 3) continue; // lewati 3
  if (i === 6) break; // berhenti di 6
  console.log(i);
}
// Output: 1, 2, 4, 5
```

### 7.6 `for...of`: Menelusuri Nilai

Cara paling nyaman menelusuri isi array (dan string, `Map`, `Set`):

```js
const buah = ["apel", "jeruk", "mangga"];

for (const item of buah) {
  console.log(item);
}
```

Jika butuh nomor indeks juga, gunakan `entries()`:

```js
for (const [indeks, item] of buah.entries()) {
  console.log(`${indeks}: ${item}`);
}
// 0: apel
// 1: jeruk
// 2: mangga
```

Sintaks `[indeks, item]` disebut **destructuring**, yang akan dibahas di Bab 9.

### 7.7 `for...in`: Menelusuri Kunci Object

Dipakai untuk menelusuri **nama properti** dari sebuah object:

```js
const pengguna = { nama: "Sari", umur: 25, kota: "Bandung" };

for (const kunci in pengguna) {
  console.log(`${kunci} = ${pengguna[kunci]}`);
}
// nama = Sari
// umur = 25
// kota = Bandung
```

> **Peringatan:** Jangan pakai `for...in` untuk array. Ia menelusuri indeks sebagai string dan bisa ikut menyertakan properti tambahan. Untuk array gunakan `for...of`. Untuk object, sering kali `Object.entries()` (Bab 10) lebih baik.

### 7.8 Perulangan Bersarang

Perulangan di dalam perulangan. Contoh tabel perkalian:

```js
for (let baris = 1; baris <= 3; baris++) {
  let teks = "";
  for (let kolom = 1; kolom <= 3; kolom++) {
    teks += `${baris * kolom}\t`;
  }
  console.log(teks);
}
// 1  2  3
// 2  4  6
// 3  6  9
```

### 7.9 Contoh Klasik: FizzBuzz

Soal wawancara populer. Cetak 1 sampai 15, tetapi ganti kelipatan 3 dengan `Fizz`, kelipatan 5 dengan `Buzz`, dan kelipatan keduanya dengan `FizzBuzz`.

```js
for (let i = 1; i <= 15; i++) {
  if (i % 15 === 0) {
    console.log("FizzBuzz");
  } else if (i % 3 === 0) {
    console.log("Fizz");
  } else if (i % 5 === 0) {
    console.log("Buzz");
  } else {
    console.log(i);
  }
}
```

Perhatikan bahwa kondisi kelipatan 15 harus diperiksa **paling awal**. Jika tidak, angka 15 akan tertangkap oleh kondisi kelipatan 3 dan tidak pernah menjadi `FizzBuzz`.

### Latihan Bab 7

**7.1** Cetak semua bilangan genap dari 2 sampai 20 menggunakan `for`.

**7.2** Hitung faktorial dari 6 (`6 * 5 * 4 * 3 * 2 * 1`) menggunakan perulangan.

**7.3** Diketahui `const angka = [4, 9, 2, 15, 7];`. Cari angka terbesar menggunakan `for...of` (tanpa `Math.max`).

## Bab 8: Fungsi

### Tujuan Bab Ini

- Membuat dan memanggil fungsi dengan tiga gaya penulisan.
- Memahami parameter, argumen, nilai default, dan `return`.
- Memahami scope, closure, callback, dan higher-order function.

### 8.1 Apa Itu Fungsi

**Fungsi** adalah blok kode yang diberi nama dan bisa dipakai berulang kali. Analoginya **resep masakan**: Anda menuliskan resep sekali, lalu bisa memasaknya kapan saja dengan bahan yang berbeda.

Manfaat fungsi:

- **Menghindari pengulangan kode** (prinsip DRY: Don't Repeat Yourself).
- **Memecah masalah besar** menjadi bagian kecil yang mudah dipahami dan diuji.
- **Memberi nama** pada sebuah tindakan sehingga kode lebih mudah dibaca.

### 8.2 Function Declaration

```js
function sapa(nama) {
  return `Halo, ${nama}!`;
}

console.log(sapa("Sari")); // Halo, Sari!
console.log(sapa("Budi")); // Halo, Budi!
```

Istilah penting:

- **Parameter**: nama variabel di dalam definisi fungsi (`nama` di atas).
- **Argumen**: nilai nyata yang diberikan saat memanggil fungsi (`"Sari"`).
- **`return`**: mengirim nilai keluar dari fungsi dan **menghentikan** eksekusi fungsi seketika.

Jika fungsi tidak memiliki `return` (atau `return` kosong), hasilnya adalah `undefined`.

```js
function cetakSaja(x) {
  console.log(x);
}
const hasil = cetakSaja(5);
console.log(hasil); // undefined
```

### 8.3 Function Expression

Fungsi disimpan ke dalam variabel:

```js
const kali = function (a, b) {
  return a * b;
};
console.log(kali(3, 4)); // 12
```

Perbedaan dengan declaration: function declaration ter-**hoist** sehingga bisa dipanggil sebelum ditulis, sedangkan function expression tidak (mengikuti aturan variabel `const`/`let`).

```js
console.log(tambah(1, 2)); // 3 (berhasil, karena hoisting)
function tambah(a, b) {
  return a + b;
}

// console.log(bagi(4, 2)); // ReferenceError
const bagi = function (a, b) {
  return a / b;
};
```

### 8.4 Arrow Function

Sintaks yang lebih ringkas, diperkenalkan pada ES2015 dan sangat populer:

```js
const kuadrat = (x) => {
  return x * x;
};

// Jika isinya satu ekspresi, kurung kurawal dan return boleh dibuang
const kuadratSingkat = (x) => x * x;

// Satu parameter: kurung boleh dibuang (tetapi banyak tim tetap memakainya)
const dua = (x) => x * 2;

// Tanpa parameter: kurung wajib
const acak = () => Math.random();

// Mengembalikan object literal: bungkus dengan tanda kurung
const buatUser = (nama) => ({ nama, aktif: true });

console.log(kuadratSingkat(5)); // 25
console.log(buatUser("Sari")); // { nama: 'Sari', aktif: true }
```

Arrow function sangat cocok untuk fungsi pendek dan **callback**. Ada perbedaan dalam perilaku `this` yang dibahas di Bab 15.

### 8.5 Parameter Default dan Rest Parameter

**Nilai default** dipakai jika argumen tidak diberikan:

```js
function sapaDenganSalam(nama, salam = "Halo") {
  return `${salam}, ${nama}!`;
}

console.log(sapaDenganSalam("Sari")); // Halo, Sari!
console.log(sapaDenganSalam("Sari", "Selamat pagi")); // Selamat pagi, Sari!
```

**Rest parameter** (`...`) menampung sisa argumen menjadi array:

```js
function jumlahkan(...angka) {
  let total = 0;
  for (const n of angka) {
    total += n;
  }
  return total;
}

console.log(jumlahkan(1, 2, 3)); // 6
console.log(jumlahkan(10, 20, 30, 40)); // 100
```

### 8.6 Scope Fungsi dan Closure

Variabel yang dibuat di dalam fungsi **hanya hidup di dalam fungsi itu**:

```js
function hitung() {
  const rahasia = 42;
  return rahasia;
}
hitung();
// console.log(rahasia); // ReferenceError
```

Sebaliknya, fungsi dapat **mengingat** variabel dari tempat ia dibuat, meskipun fungsi luarnya sudah selesai. Kemampuan ini disebut **closure**.

```js
function buatPenghitung() {
  let hitungan = 0; // variabel "tersembunyi"

  return function () {
    hitungan++;
    return hitungan;
  };
}

const penghitungA = buatPenghitung();
console.log(penghitungA()); // 1
console.log(penghitungA()); // 2
console.log(penghitungA()); // 3

const penghitungB = buatPenghitung(); // penghitung baru dengan hitungan sendiri
console.log(penghitungB()); // 1
```

Variabel `hitungan` tidak bisa diakses dari luar, tetapi fungsi yang dikembalikan tetap bisa mengubahnya. Closure adalah dasar dari banyak pola di JavaScript, termasuk cara kerja banyak library.

### 8.7 Fungsi sebagai Nilai (First-Class Function)

Di JavaScript, fungsi adalah **nilai biasa**. Ia bisa disimpan di variabel, dikirim sebagai argumen, dan dikembalikan dari fungsi lain.

```js
function jalankanDuaKali(fungsi) {
  fungsi();
  fungsi();
}

jalankanDuaKali(() => console.log("Halo!"));
// Halo!
// Halo!
```

- Fungsi yang dikirim ke fungsi lain disebut **callback**.
- Fungsi yang menerima atau mengembalikan fungsi disebut **higher-order function**.

Contoh yang lebih praktis:

```js
function ubahSemua(daftar, aturan) {
  const hasil = [];
  for (const item of daftar) {
    hasil.push(aturan(item));
  }
  return hasil;
}

console.log(ubahSemua([1, 2, 3], (x) => x * 10)); // [10, 20, 30]
console.log(ubahSemua(["a", "b"], (x) => x.toUpperCase())); // ['A', 'B']
```

Anda baru saja membuat versi sederhana dari `map()` yang akan dipelajari di Bab 9.

### 8.8 Rekursi (Pengenalan)

**Rekursi** adalah fungsi yang memanggil dirinya sendiri. Wajib ada **kondisi berhenti (base case)** agar tidak berjalan selamanya.

```js
function faktorial(n) {
  if (n <= 1) return 1; // base case
  return n * faktorial(n - 1);
}

console.log(faktorial(5)); // 120
```

Untuk saat ini, cukup pahami idenya. Rekursi berguna untuk struktur bersarang seperti folder atau data tree.

### 8.9 Prinsip Fungsi yang Baik

1. **Satu fungsi, satu tugas.** Jika nama fungsi memerlukan kata "dan" (misalnya `validasiDanSimpan`), pertimbangkan memecahnya.
2. **Beri nama berupa kata kerja**: `hitungTotal`, `ambilPengguna`, `validasiEmail`.
3. **Jaga fungsi tetap pendek**, ideal beberapa belas baris.
4. **Utamakan pure function** bila memungkinkan, yaitu fungsi yang hasilnya hanya bergantung pada argumennya dan tidak mengubah apa pun di luar dirinya. Pure function mudah diuji dan diprediksi.

```js
// Pure: input sama, output selalu sama, tanpa efek samping
const tambahPajak = (harga) => harga * 1.1;

// Tidak pure: bergantung dan mengubah variabel di luar
let totalGlobal = 0;
function tambahKeTotal(x) {
  totalGlobal += x;
}
```

**8.2** Buat fungsi `hitungDiskon(harga, persen = 10)` yang mengembalikan harga setelah diskon. Panggil dengan dan tanpa argumen kedua.

**8.3** Buat fungsi `buatPenyapa(salam)` yang mengembalikan fungsi lain. Fungsi yang dikembalikan menerima `nama` dan mengembalikan `"<salam>, <nama>!"`. Contoh pemakaian: `buatPenyapa("Selamat malam")("Sari")`.

## Bab 9: Array

### Tujuan Bab Ini

- Membuat dan mengakses array.
- Memodifikasi array dengan method mutasi maupun non-mutasi.
- Menguasai `map`, `filter`, `reduce`, `find`, `some`, `every`.
- Memakai spread dan destructuring.

### 9.1 Apa Itu Array

**Array** adalah daftar berurutan yang menyimpan banyak nilai dalam satu variabel. Analoginya **rak buku**: tiap buku punya posisi nomor.

```js
const buah = ["apel", "jeruk", "mangga"];
console.log(buah[0]); // "apel"   (indeks dimulai dari 0!)
console.log(buah[2]); // "mangga"
console.log(buah[5]); // undefined (tidak ada)
console.log(buah.length); // 3
console.log(buah.at(-1)); // "mangga" (at(-1) = elemen terakhir)
```

> **Penting:** Indeks array dimulai dari **0**, bukan 1. Elemen terakhir ada di indeks `length - 1`.

Array boleh berisi tipe campuran, tetapi dalam praktik biasanya berisi tipe yang seragam:

```js
const campur = [1, "dua", true, null, { a: 1 }, [1, 2]];
```

### 9.2 Method yang Mengubah Array Asli (Mutasi)

```js
const daftar = ["a", "b", "c"];

daftar.push("d"); // tambah di akhir      -> ['a','b','c','d']
daftar.pop(); // hapus dari akhir       -> ['a','b','c']
daftar.unshift("z"); // tambah di awal      -> ['z','a','b','c']
daftar.shift(); // hapus dari awal        -> ['a','b','c']

daftar.splice(1, 1); // hapus 1 elemen mulai indeks 1 -> ['a','c']
daftar.splice(1, 0, "x", "y"); // sisip di indeks 1 -> ['a','x','y','c']
console.log(daftar);
```

Method `sort()` dan `reverse()` juga **mengubah array asli**.

### 9.3 Method yang Tidak Mengubah Array Asli

```js
const angka = [1, 2, 3, 4, 5];

console.log(angka.slice(1, 3)); // [2, 3]   (indeks 1 sampai sebelum 3)
console.log(angka.concat([6, 7])); // [1, 2, 3, 4, 5, 6, 7]
console.log(angka); // array asli tidak berubah

// Versi "non-mutasi" dari sort/reverse/splice (tersedia di Node.js modern)
const terurut = [3, 1, 2].toSorted((a, b) => a - b); // [1, 2, 3]
const terbalik = [1, 2, 3].toReversed(); // [3, 2, 1]
```

Memahami mana method yang mengubah data asli dan mana yang tidak adalah sumber bug yang sangat umum. Jika ragu, cek dokumentasi di MDN.

### 9.4 Pencarian dan Pemeriksaan

```js
const angka = [10, 20, 30, 20];

console.log(angka.includes(20)); // true
console.log(angka.indexOf(20)); // 1  (indeks pertama, -1 jika tidak ada)
console.log(angka.lastIndexOf(20)); // 3

console.log(angka.find((n) => n > 15)); // 20  (elemen pertama yang cocok)
console.log(angka.findIndex((n) => n > 15)); // 1
console.log(angka.findLast((n) => n > 15)); // 20 (dari belakang)

console.log(angka.some((n) => n > 25)); // true  (minimal satu cocok)
console.log(angka.every((n) => n > 5)); // true  (semua cocok)
```

### 9.5 Tiga Method Terpenting: `map`, `filter`, `reduce`

Ketiganya tidak mengubah array asli, tetapi menghasilkan **array/nilai baru**. Keterampilan ini akan Anda pakai setiap hari.

**`map`: mengubah setiap elemen (jumlah elemen sama).**

```js
const harga = [10000, 25000, 5000];
const hargaPlusPajak = harga.map((h) => h * 1.1);
console.log(hargaPlusPajak); // [ 11000, 27500, 5500 ]
```

**`filter`: menyaring elemen yang memenuhi syarat.**

```js
const angka = [1, 2, 3, 4, 5, 6];
const genap = angka.filter((n) => n % 2 === 0);
console.log(genap); // [2, 4, 6]
```

**`reduce`: meringkas array menjadi satu nilai.**

```js
const angka = [1, 2, 3, 4];
const total = angka.reduce((akumulator, n) => akumulator + n, 0);
console.log(total); // 10
```

Cara kerja `reduce` pada contoh di atas (nilai awal `0`):

|Langkah|akumulator|n|hasil|
|---|---|---|---|
|1|0|1|1|
|2|1|2|3|
|3|3|3|6|
|4|6|4|10|

**Chaining (rantai method):**

```js
const pesanan = [
  { nama: "Kopi", harga: 20000, jumlah: 2 },
  { nama: "Teh", harga: 15000, jumlah: 0 },
  { nama: "Roti", harga: 12000, jumlah: 3 },
];

const totalBayar = pesanan
  .filter((p) => p.jumlah > 0) // buang yang jumlahnya 0
  .map((p) => p.harga * p.jumlah) // hitung subtotal
  .reduce((a, b) => a + b, 0); // jumlahkan semua

console.log(totalBayar); // 76000
```

Membaca kode ini seperti membaca kalimat: "saring pesanan yang jumlahnya lebih dari nol, ubah jadi subtotal, lalu jumlahkan."

### 9.6 `forEach`

Menjalankan fungsi untuk setiap elemen. **Tidak mengembalikan apa pun** (hasilnya `undefined`), jadi dipakai untuk efek samping seperti mencetak:

```js
["a", "b", "c"].forEach((huruf, indeks) => {
  console.log(indeks, huruf);
});
```

Aturan praktis: butuh hasil baru? Pakai `map`/`filter`/`reduce`. Hanya ingin melakukan sesuatu untuk tiap elemen? `forEach` atau `for...of`.

### 9.7 Mengurutkan (`sort`) dan Jebakannya

Secara default `sort()` mengurutkan sebagai **string**, bukan angka:

```js
console.log([10, 9, 1, 100].sort()); // [ 1, 10, 100, 9 ]  (salah untuk angka!)
```

Selalu berikan **fungsi pembanding** untuk angka:

```js
console.log([10, 9, 1, 100].sort((a, b) => a - b)); // [ 1, 9, 10, 100 ] naik
console.log([10, 9, 1, 100].sort((a, b) => b - a)); // [ 100, 10, 9, 1 ] turun
```

Mengurutkan array of object berdasarkan properti:

```js
const orang = [
  { nama: "Budi", umur: 30 },
  { nama: "Sari", umur: 25 },
];
orang.sort((a, b) => a.umur - b.umur);
console.log(orang); // Sari (25) lalu Budi (30)

// Untuk teks, gunakan localeCompare
const nama = ["Sari", "Andi", "Budi"];
nama.sort((a, b) => a.localeCompare(b));
console.log(nama); // [ 'Andi', 'Budi', 'Sari' ]
```

### 9.8 Method Lain yang Berguna

```js
console.log([1, 2, 3].join("-")); // "1-2-3"
console.log([1, [2, [3]]].flat(Infinity)); // [1, 2, 3]
console.log(Array.from({ length: 3 }, (_, i) => i * 2)); // [0, 2, 4]
console.log(Array.isArray([])); // true
console.log([..."abc"]); // ['a', 'b', 'c']
```

### 9.9 Spread Operator `...`

Menyebarkan isi array. Berguna untuk menyalin dan menggabungkan **tanpa mengubah aslinya**:

```js
const a = [1, 2];
const b = [3, 4];

const gabung = [...a, ...b, 5]; // [1, 2, 3, 4, 5]
const salinan = [...a]; // salinan dangkal (shallow copy)
```

### 9.10 Destructuring Array

Mengambil elemen array ke variabel terpisah dalam satu baris:

```js
const koordinat = [10, 20, 30];
const [x, y, z] = koordinat;
console.log(x, y, z); // 10 20 30

const [pertama, , ketiga] = koordinat; // lewati elemen kedua
console.log(pertama, ketiga); // 10 30

const [a = 1, b = 2] = [9]; // nilai default
console.log(a, b); // 9 2

// Menukar nilai tanpa variabel bantu
let p = 1;
let q = 2;
[p, q] = [q, p];
console.log(p, q); // 2 1
```

### 9.11 Array of Object: Bentuk Data Paling Umum di Backend

Hasil dari database dan isi respons API hampir selalu berupa **array yang berisi object**:

```js
const pengguna = [
  { id: 1, nama: "Sari", aktif: true },
  { id: 2, nama: "Budi", aktif: false },
  { id: 3, nama: "Citra", aktif: true },
];

// Mengambil satu pengguna berdasarkan id
const p2 = pengguna.find((u) => u.id === 2);

// Nama semua pengguna aktif
const namaAktif = pengguna.filter((u) => u.aktif).map((u) => u.nama);
console.log(namaAktif); // [ 'Sari', 'Citra' ]

// Mengelompokkan menjadi dua kelompok dengan reduce
const dikelompokkan = pengguna.reduce((hasil, u) => {
  const kunci = u.aktif ? "aktif" : "nonaktif";
  hasil[kunci] = hasil[kunci] ?? [];
  hasil[kunci].push(u.nama);
  return hasil;
}, {});
console.log(dikelompokkan); // { aktif: [ 'Sari', 'Citra' ], nonaktif: [ 'Budi' ] }
```

### Latihan Bab 9

**9.1** Diketahui `const angka = [3, 8, 15, 22, 7];`. Buat array baru berisi kuadrat dari angka yang lebih besar dari 5.

**9.2** Diketahui daftar produk berikut. Hitung **total stok** semua produk dengan `reduce`, dan cari produk yang stoknya 0 dengan `find`.

```js

  { nama: "Pensil", stok: 10 },
  { nama: "Buku", stok: 0 },
  { nama: "Penghapus", stok: 5 },

```

## Bab 10: Object, JSON, Map, dan Set

### Tujuan Bab Ini

- Membuat dan memodifikasi object.
- Memahami destructuring, spread, dan method `Object`.
- Membedakan salinan dangkal dan dalam, serta nilai vs referensi.
- Memakai JSON untuk pertukaran data.
- Mengenal `Map` dan `Set`.

### 10.1 Apa Itu Object

**Object** menyimpan data dalam pasangan **kunci: nilai** (key-value). Analoginya **kartu identitas** yang punya kolom nama, umur, dan alamat.

```js
const pengguna = {
  nama: "Sari",
  umur: 25,
  aktif: true,
  hobi: ["membaca", "bersepeda"],
  alamat: {
    kota: "Bandung",
    kodePos: "40111",
  },
};
```

Mengakses data:

```js
console.log(pengguna.nama); // notasi titik
console.log(pengguna["umur"]); // notasi kurung siku
console.log(pengguna.alamat.kota); // "Bandung"
console.log(pengguna.hobi[0]); // "membaca"

const kunci = "nama";
console.log(pengguna[kunci]); // kunci dinamis hanya bisa dengan kurung siku
```

Mengubah, menambah, dan menghapus:

```js
pengguna.umur = 26; // ubah
pengguna.email = "sari@contoh.com"; // tambah
delete pengguna.aktif; // hapus
console.log("nama" in pengguna); // true (apakah kunci ada?)
```

### 10.2 Shorthand dan Computed Property

```js
const nama = "Budi";
const umur = 30;

// Shorthand: jika nama variabel sama dengan nama kunci
const orang = { nama, umur }; // sama dengan { nama: nama, umur: umur }

// Computed property: kunci dari ekspresi
const bidang = "kota";
const alamat = { [bidang]: "Jakarta" }; // { kota: 'Jakarta' }
```

### 10.3 Method dan `this`

Fungsi yang menjadi properti object disebut **method**.

```js
const kalkulator = {
  nilai: 10,
  tambah(n) {
    this.nilai += n; // this = object yang memanggil method
    return this;
  },
};

kalkulator.tambah(5);
console.log(kalkulator.nilai); // 15
```

`this` merujuk pada **object yang memanggil method tersebut**. Aturan lengkap `this` cukup rumit. Dalam praktik modern, Anda akan menemuinya terutama pada class (Bab 15).

### 10.4 Destructuring Object

Mengambil properti ke variabel terpisah:

```js
const pengguna = { nama: "Sari", umur: 25, kota: "Bandung" };

const { nama, umur } = pengguna;
console.log(nama, umur); // Sari 25

// Mengganti nama variabel
const { nama: namaLengkap } = pengguna;
console.log(namaLengkap); // Sari

// Nilai default
const { negara = "Indonesia" } = pengguna;
console.log(negara); // Indonesia

// Bersarang
const data = { profil: { email: "a@b.com" } };
const {
  profil: { email },
} = data;
console.log(email); // a@b.com
```

Destructuring pada parameter fungsi sangat umum:

```js
function tampilkan({ nama, umur = 18 }) {
  console.log(`${nama} (${umur})`);
}
tampilkan({ nama: "Sari" }); // Sari (18)
```

### 10.5 Spread dan Rest pada Object

```js
const dasar = { a: 1, b: 2 };

const gabung = { ...dasar, b: 20, c: 3 };
console.log(gabung); // { a: 1, b: 20, c: 3 } (kunci belakangan menimpa)

// Rest: mengambil sisa properti
const { a, ...sisa } = gabung;
console.log(sisa); // { b: 20, c: 3 }
```

Pola "salin object lalu ubah sebagian" (`{ ...lama, kunci: baru }`) akan sering Anda pakai untuk memperbarui data tanpa mengubah aslinya.

### 10.6 Method Bawaan `Object`

```js
const stok = { apel: 10, jeruk: 5, mangga: 0 };

console.log(Object.keys(stok)); // [ 'apel', 'jeruk', 'mangga' ]
console.log(Object.values(stok)); // [ 10, 5, 0 ]
console.log(Object.entries(stok)); // [ ['apel', 10], ['jeruk', 5], ['mangga', 0] ]

// Menelusuri key dan value sekaligus
for (const [buah, jumlah] of Object.entries(stok)) {
  console.log(`${buah}: ${jumlah}`);
}

// Kebalikan entries: dari pasangan menjadi object
const hanyaAda = Object.fromEntries(
  Object.entries(stok).filter(([, jumlah]) => jumlah > 0)
);
console.log(hanyaAda); // { apel: 10, jeruk: 5 }

console.log(Object.hasOwn(stok, "apel")); // true
```

`Object.freeze()` membuat object tidak bisa diubah (secara dangkal):

```js
const konfig = Object.freeze({ mode: "produksi" });

try {
  konfig.mode = "debug";
} catch (error) {
  // Pada ES Modules (strict mode), perubahan ini melempar TypeError.
  // Pada mode non-strict, perubahan diabaikan diam-diam.
  console.log(error.name); // "TypeError"
}

console.log(konfig.mode); // "produksi"
```

### 10.7 Nilai vs Referensi (Konsep Krusial)

Ini adalah salah satu konsep yang paling sering menjebak pemula.

- **Tipe primitif** disalin **nilainya**.
- **Object dan array** disalin **alamat/referensinya**, bukan isinya.

```js
// Primitif: dua kotak terpisah
let a = 5;
let b = a;
b = 10;
console.log(a); // 5 (tidak terpengaruh)

// Object: dua nama menunjuk ke SATU object yang sama
const asli = { nilai: 1 };
const alias = asli;
alias.nilai = 99;
console.log(asli.nilai); // 99 (ikut berubah!)
```

Analoginya: object itu seperti **dokumen bersama di cloud**. Menyalin "referensi" sama dengan membagikan tautannya. Siapa pun yang mengedit lewat tautan itu mengubah dokumen yang sama.

**Salinan dangkal (shallow copy)** memakai spread:

```js
const a1 = { nama: "Sari", alamat: { kota: "Bandung" } };
const a2 = { ...a1 };

a2.nama = "Budi";
console.log(a1.nama); // "Sari" (aman, level pertama tersalin)

a2.alamat.kota = "Jakarta";
console.log(a1.alamat.kota); // "Jakarta" (ikut berubah! level dalam masih dibagi)
```

**Salinan dalam (deep copy)** memakai `structuredClone`:

```js
const b1 = { nama: "Sari", alamat: { kota: "Bandung" } };
const b2 = structuredClone(b1);

b2.alamat.kota = "Jakarta";
console.log(b1.alamat.kota); // "Bandung" (aman)
```

**Perbandingan object** memakai referensi, bukan isi:

```js
console.log({ a: 1 } === { a: 1 }); // false (dua object berbeda)
const x = { a: 1 };
const y = x;
console.log(x === y); // true (referensi sama)
```

### 10.8 JSON

**JSON (JavaScript Object Notation)** adalah format **teks** untuk bertukar data, dan menjadi format standar hampir semua API web. Bentuknya mirip object JavaScript, tetapi dengan aturan lebih ketat:

- Kunci **wajib** memakai tanda kutip ganda.
- String memakai kutip ganda saja.
- Tidak boleh ada komentar, fungsi, `undefined`, atau koma di akhir.

```json
{
  "nama": "Sari",
  "umur": 25,
  "hobi": ["membaca", "bersepeda"],
  "alamat": null
}
```

Dua fungsi utama:

```js
const obj = { nama: "Sari", umur: 25 };

// Object -> teks JSON (serialisasi)
const teks = JSON.stringify(obj);
console.log(teks); // '{"nama":"Sari","umur":25}'
console.log(JSON.stringify(obj, null, 2)); // versi rapi dengan indentasi 2 spasi

// Teks JSON -> object (parsing)
const kembali = JSON.parse(teks);
console.log(kembali.nama); // "Sari"
```

`JSON.parse` akan **melempar error** jika teksnya tidak valid, jadi bungkus dengan `try...catch` saat memproses data dari luar (lihat Bab 12):

```js
try {
  JSON.parse("{nama: 'Sari'}"); // tidak valid: kunci tanpa kutip
} catch (error) {
  console.log("JSON tidak valid:", error.message);
}
```

### 10.9 `Map`

`Map` mirip object, tetapi dirancang khusus sebagai kamus (dictionary) data:

- kunci boleh bertipe **apa saja** (bukan hanya string);
- **urutan penyisipan terjaga**;
- punya properti `size`;
- performa baik untuk sering tambah/hapus.

```js
const skor = new Map();
skor.set("Sari", 90);
skor.set("Budi", 75);

console.log(skor.get("Sari")); // 90
console.log(skor.has("Andi")); // false
console.log(skor.size); // 2
skor.delete("Budi");

for (const [nama, nilai] of skor) {
  console.log(nama, nilai);
}
```

Gunakan object untuk data berstruktur tetap (misalnya `{ nama, umur }`). Gunakan `Map` untuk kumpulan pasangan yang kuncinya dinamis, misalnya cache atau penghitung.

### 10.10 `Set`

`Set` menyimpan kumpulan nilai **unik** (tanpa duplikat).

```js
const tag = new Set(["js", "node", "js", "api"]);
console.log(tag); // Set(3) { 'js', 'node', 'api' }
console.log(tag.has("node")); // true
tag.add("db");
tag.delete("api");
console.log(tag.size); // 3

// Trik populer: menghapus duplikat dari array
const angka = [1, 2, 2, 3, 3, 3];
const unik = [...new Set(angka)];
console.log(unik); // [1, 2, 3]
```

### 10.11 Mengelompokkan Data dengan `Object.groupBy`

Pada Node.js modern tersedia `Object.groupBy` untuk mengelompokkan data tanpa `reduce` manual:

```js
const pengguna = [
  { nama: "Sari", aktif: true },
  { nama: "Budi", aktif: false },
  { nama: "Citra", aktif: true },
];

const grup = Object.groupBy(pengguna, (u) => (u.aktif ? "aktif" : "nonaktif"));
console.log(grup.aktif.map((u) => u.nama)); // [ 'Sari', 'Citra' ]
```

## Bab 11: String, Angka, dan Tanggal

### Tujuan Bab Ini

- Menguasai method string yang paling sering dipakai.
- Memakai `Math` dan memformat angka (termasuk Rupiah).
- Bekerja dengan tanggal secara aman.

### 11.1 Method String

String bersifat **immutable** (tidak bisa diubah). Setiap method mengembalikan **string baru**, sedangkan string asli tetap.

```js
const teks = "  Belajar JavaScript  ";

console.log(teks.length); // 22
console.log(teks.trim()); // "Belajar JavaScript"
console.log(teks.toUpperCase()); // "  BELAJAR JAVASCRIPT  "
console.log(teks.toLowerCase()); // "  belajar javascript  "

const s = "Belajar JavaScript";
console.log(s.includes("Java")); // true
console.log(s.startsWith("Bel")); // true
console.log(s.endsWith("Script")); // true
console.log(s.indexOf("a")); // 3 (indeks pertama, -1 jika tidak ada)
console.log(s.at(0)); // "B"
console.log(s[0]); // "B"

console.log(s.slice(0, 7)); // "Belajar"
console.log(s.slice(-6)); // "Script"
console.log(s.split(" ")); // [ 'Belajar', 'JavaScript' ]
console.log(s.replace("a", "@")); // "Bel@jar JavaScript" (hanya yang pertama)
console.log(s.replaceAll("a", "@")); // "Bel@j@r J@v@Script" (semua)

console.log("7".padStart(3, "0")); // "007"
console.log("ha".repeat(3)); // "hahaha"
```

Contoh nyata membuat **slug** untuk URL artikel:

```js
const judul = "  Belajar Backend Itu Menyenangkan  ";
const slug = judul.trim().toLowerCase().replaceAll(" ", "-");
console.log(slug); // "belajar-backend-itu-menyenangkan"
```

### 11.2 Regular Expression (Pengenalan Singkat)

**Regex** adalah pola untuk mencocokkan teks. Topiknya luas, tetapi berikut contoh dasar:

```js
const pola = /^[^\s@]+@[^\s@]+\.[^\s@]+$/; // pola email sederhana

console.log(pola.test("sari@contoh.com")); // true
console.log(pola.test("bukan-email")); // false

console.log("Tel: 0812-3456".replace(/\D/g, "")); // "08123456" (buang non-digit)
```

> **Catatan:** Validasi email dengan regex tidak pernah sempurna. Untuk keperluan serius, gunakan library validasi dan verifikasi lewat pengiriman email konfirmasi.

### 11.3 Objek `Math`

```js
console.log(Math.round(4.6)); // 5
console.log(Math.floor(4.9)); // 4 (bulatkan ke bawah)
console.log(Math.ceil(4.1)); // 5 (bulatkan ke atas)
console.log(Math.trunc(-4.9)); // -4 (buang desimal)
console.log(Math.abs(-7)); // 7
console.log(Math.max(1, 5, 3)); // 5
console.log(Math.min(1, 5, 3)); // 1
console.log(Math.sqrt(16)); // 4
console.log(Math.pow(2, 3)); // 8 (sama dengan 2 ** 3)
console.log(Math.PI); // 3.141592653589793

// Angka acak antara 0 (termasuk) dan 1 (tidak termasuk)
console.log(Math.random());

// Bilangan bulat acak dari min sampai max (termasuk keduanya)
const acak = (min, max) => Math.floor(Math.random() * (max - min + 1)) + min;
console.log(acak(1, 6)); // simulasi dadu
```

> **Peringatan keamanan:** `Math.random()` **tidak aman** untuk membuat token, password, atau kode verifikasi. Untuk kebutuhan tersebut gunakan modul `crypto` bawaan Node.js (misalnya `crypto.randomUUID()` atau `crypto.randomInt()`).

### 11.4 Memformat Angka dengan `Intl`

`Intl` adalah API bawaan untuk format angka, mata uang, dan tanggal sesuai bahasa/negara.

```js
const harga = 1500000;

console.log(new Intl.NumberFormat("id-ID").format(harga));
// "1.500.000"

const rupiah = new Intl.NumberFormat("id-ID", {
  style: "currency",
  currency: "IDR",
  maximumFractionDigits: 0,
});
console.log(rupiah.format(harga)); // "Rp 1.500.000" (bisa berbeda tipis spasinya)
```

Ingat prinsip dari Bab 4: **simpan** nilai uang sebagai angka murni (bilangan bulat), lalu **format** hanya ketika ditampilkan.

### 11.5 Tanggal dengan `Date`

```js
const sekarang = new Date();
console.log(sekarang); // objek Date saat ini
console.log(sekarang.getFullYear()); // misalnya 2026
console.log(sekarang.getMonth()); // 0-11 (0 = Januari!)
console.log(sekarang.getDate()); // tanggal 1-31
console.log(sekarang.getDay()); // hari 0-6 (0 = Minggu)

console.log(Date.now()); // milidetik sejak 1 Januari 1970 UTC (timestamp)
console.log(sekarang.toISOString()); // "2026-09-28T10:30:00.000Z"
```

Membuat tanggal tertentu:

```js
const a = new Date("2026-12-25T08:00:00Z"); // format ISO 8601 (disarankan)
const b = new Date(2026, 11, 25); // tahun, bulan (0-11), tanggal, zona waktu lokal
```

> **Jebakan:** Bulan pada `Date` dimulai dari **0** (Januari = 0, Desember = 11).

Menghitung selisih:

```js
const mulai = new Date("2026-09-01T00:00:00Z");
const selesai = new Date("2026-09-28T00:00:00Z");
const selisihHari = (selesai - mulai) / (1000 * 60 * 60 * 24);
console.log(selisihHari); // 27
```

Memformat tanggal untuk tampilan:

```js
const tgl = new Date("2026-09-28T03:00:00Z");
console.log(
  new Intl.DateTimeFormat("id-ID", {
    dateStyle: "full",
    timeZone: "Asia/Jakarta",
  }).format(tgl)
); // "Senin, 28 September 2026"
```

**Aturan penting untuk backend:**

1. **Simpan dan kirim waktu dalam UTC** menggunakan format ISO 8601 (`toISOString()`).
2. **Ubah ke zona waktu lokal hanya saat menampilkan** ke pengguna.
3. Jangan menyimpan tanggal sebagai teks bebas seperti `"28/9/26"`, karena ambigu.

> **Catatan:** Ada API tanggal baru bernama **Temporal** yang dirancang untuk mengatasi kelemahan `Date`. Periksa status dukungannya di versi Node.js Anda melalui dokumentasi resmi sebelum memakainya. Untuk saat ini, `Date` dan `Intl` sudah cukup untuk kebutuhan dasar.

## Bab 12: Penanganan Error

### Tujuan Bab Ini

- Mengenali jenis error yang umum.
- Menangani error dengan `try`, `catch`, `finally`.
- Melempar error sendiri dan membuat error khusus.
- Memahami prinsip dasar penanganan error di backend.

### 12.1 Mengapa Error Harus Ditangani

Di aplikasi nyata, banyak hal bisa salah: file tidak ditemukan, database mati, pengguna mengirim data aneh, jaringan terputus. Jika error tidak ditangani, **seluruh program bisa berhenti mendadak**. Untuk server yang melayani ribuan pengguna, itu tidak boleh terjadi.

Tujuan penanganan error bukan menyembunyikan masalah, tetapi:

1. mencegah program crash tanpa kontrol,
2. memberi respons yang jelas kepada pengguna,
3. mencatat penyebab masalah agar bisa diperbaiki.

### 12.2 Jenis Error Bawaan

|Jenis|Penyebab|Contoh|
|---|---|---|
|`SyntaxError`|Kode atau data salah tata bahasa|`JSON.parse("{rusak")`|
|`ReferenceError`|Memakai variabel yang belum ada|`console.log(tidakAda)`|
|`TypeError`|Operasi pada tipe yang salah|`null.nama`, memanggil sesuatu yang bukan fungsi|
|`RangeError`|Nilai di luar rentang yang diizinkan|`new Array(-1)`, rekursi tak berujung|

### 12.3 `try`, `catch`, `finally`

```js
try {
  // kode yang berpotensi error
  const data = JSON.parse("{rusak");
  console.log(data); // tidak dijalankan, karena error di baris sebelumnya
} catch (error) {
  // dijalankan hanya jika terjadi error di blok try
  console.log("Terjadi error:");
  console.log(error.name); // "SyntaxError"
  console.log(error.message); // penjelasan error
} finally {
  // SELALU dijalankan, ada error atau tidak
  console.log("Selesai memproses");
}
```

Alurnya:

1. Kode di `try` dijalankan.
2. Jika terjadi error, eksekusi **langsung lompat** ke `catch`, sisa kode di `try` dilewati.
3. `finally` (opsional) selalu dijalankan, cocok untuk membersihkan sumber daya seperti menutup koneksi atau file.

### 12.4 Melempar Error dengan `throw`

Anda bisa melempar error sendiri saat menemukan kondisi yang tidak valid:

```js
function bagi(a, b) {
  if (b === 0) {
    throw new Error("Pembagi tidak boleh nol");
  }
  return a / b;
}

try {
  console.log(bagi(10, 2)); // 5
  console.log(bagi(10, 0)); // melempar error
} catch (error) {
  console.log("Gagal:", error.message);
}
```

> **Selalu lempar objek `Error`** (atau turunannya), jangan lempar string mentah seperti `throw "salah"`. Objek `Error` membawa **stack trace** yang sangat membantu saat mencari sumber masalah.

### 12.5 Error Khusus (Custom Error)

Membuat jenis error sendiri membuat kode lebih ekspresif. Di backend, ini dipakai untuk membedakan "data pengguna salah" dari "server bermasalah".

```js
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

class NotFoundError extends Error {
  constructor(message) {
    super(message);
    this.name = "NotFoundError";
  }
}

function validasiUmur(umur) {
  if (typeof umur !== "number" || Number.isNaN(umur)) {
    throw new ValidationError("Umur harus berupa angka", "umur");
  }
  if (umur < 0) {
    throw new ValidationError("Umur tidak boleh negatif", "umur");
  }
  return true;
}

try {
  validasiUmur(-5);
} catch (error) {
  if (error instanceof ValidationError) {
    console.log(`Input salah pada "${error.field}": ${error.message}`);
  } else {
    throw error; // error tak dikenal: lempar kembali, jangan ditelan
  }
}
```

Perhatikan `instanceof` untuk memeriksa jenis error, dan `throw error` di bagian `else` agar error yang tidak dikenali tidak hilang begitu saja.

### 12.6 Membungkus Error dengan `cause`

Saat menangkap error tingkat rendah dan melemparkannya sebagai error yang lebih bermakna, simpan error aslinya lewat opsi `cause`:

```js
function bacaKonfigurasi(teks) {
  try {
    return JSON.parse(teks);
  } catch (error) {
    throw new Error("Konfigurasi tidak valid", { cause: error });
  }
}

try {
  bacaKonfigurasi("{rusak");
} catch (error) {
  console.log(error.message); // "Konfigurasi tidak valid"
  console.log(error.cause.name); // "SyntaxError"
}
```

### 12.7 Prinsip Penanganan Error di Backend

1. **Jangan menelan error diam-diam.** Blok `catch` yang kosong menyembunyikan bug.
    
    ```js
    // Buruk
    try { jalankan(); } catch (e) {}
    ```
    
2. **Tangani di tempat yang tepat.** Tangkap error di tempat Anda bisa melakukan sesuatu yang berguna (misalnya mengirim respons 400). Jika tidak bisa berbuat apa-apa, biarkan naik ke lapisan atas.
    
3. **Bedakan error yang bisa diprediksi dari bug.** Input pengguna salah (bisa diprediksi) ditangani dengan respons yang sopan. `TypeError` karena bug program harus dicatat dan diperbaiki.
    
4. **Jangan bocorkan detail internal ke pengguna.** Tampilkan pesan umum kepada klien, dan catat detail lengkap (termasuk stack trace) di log server.
    
5. **Validasi input sedini mungkin** (fail fast) sebelum data diproses lebih jauh.

## Bab 13: JavaScript Asynchronous

### Tujuan Bab Ini

- Memahami perbedaan kode sinkron dan asynchronous.
- Memahami secara konseptual bagaimana event loop bekerja.
- Menguasai callback, Promise, dan `async/await`.
- Menjalankan beberapa tugas asynchronous secara paralel.

Ini adalah bab yang paling penting untuk backend developer JavaScript. Luangkan waktu ekstra di sini.

### 13.1 Sinkron vs Asynchronous

**Sinkron:** kode dijalankan satu per satu, dan baris berikutnya **menunggu** baris sebelumnya selesai.

**Asynchronous:** operasi yang lambat (membaca file, memanggil database, mengakses jaringan) **dimulai dulu**, program melanjutkan pekerjaan lain, dan hasilnya diproses **nanti saat sudah siap**.

Analogi **restoran**:

- **Sinkron:** pelayan menerima pesanan, berdiri menunggu di dapur sampai makanan matang, baru melayani pelanggan lain. Pelanggan lain menunggu lama.
- **Asynchronous:** pelayan menerima pesanan, menyerahkannya ke dapur, lalu melayani pelanggan lain. Saat makanan siap, dapur memberi tanda dan pelayan mengantarnya.

Node.js hanya memiliki **satu pelayan** (satu thread utama), tetapi karena ia tidak pernah menunggu dengan berdiri diam, satu pelayan itu bisa melayani banyak pelanggan sekaligus.

### 13.2 Event Loop (Gambaran Konseptual)

```text
   Kode Anda berjalan di sini
   +---------------------+
   |    Call Stack       |   <- tempat fungsi dieksekusi satu per satu
   +---------------------+
              |
   operasi lambat diserahkan ke sistem (timer, file, jaringan)
              |
              v
   +-------------------------+      selesai       +-----------------+
   |  Sistem / thread pool   |  ---------------->  |  Antrean tugas  |
   |  (dikerjakan di latar)  |                     |  (callback)     |
   +-------------------------+                     +-----------------+
                                                          |
   EVENT LOOP: "Jika call stack kosong, ambil tugas berikutnya dari antrean"
                                                          |
                                                          v
                                                    dieksekusi di Call Stack
```

Prinsip yang harus diingat: **callback baru dijalankan setelah semua kode sinkron yang sedang berjalan selesai**, meskipun waktunya `0` milidetik.

```js
console.log("1: mulai");

setTimeout(() => {
  console.log("2: dari setTimeout");
}, 0);

Promise.resolve().then(() => {
  console.log("3: dari Promise");
});

console.log("4: selesai");
```

Output:

```text
1: mulai
4: selesai
3: dari Promise
2: dari setTimeout
```

Penjelasan: kode sinkron (1 dan 4) berjalan lebih dulu. Setelah itu, tugas dari Promise (**microtask queue**) diprioritaskan sebelum tugas dari `setTimeout` (**macrotask/timer queue**). Detail urutan ini tidak perlu dihafal sekarang. Yang penting: **kode asynchronous tidak pernah berjalan "di tengah-tengah" kode sinkron**.

### 13.3 Callback

Cara paling awal: berikan fungsi yang akan **dipanggil kembali** ketika pekerjaan selesai.

```js
console.log("Memesan kopi...");

setTimeout(() => {
  console.log("Kopi siap!");
}, 1000);

console.log("Sambil menunggu, saya baca buku.");
```

Output:

```text
Memesan kopi...
Sambil menunggu, saya baca buku.
Kopi siap!
```

Masalah muncul ketika ada banyak langkah berurutan yang saling bergantung, hasilnya bersarang dalam ("callback hell"):

```js
ambilPengguna(1, (pengguna) => {
  ambilPesanan(pengguna.id, (pesanan) => {
    ambilProduk(pesanan[0].produkId, (produk) => {
      console.log(produk); // semakin menjorok ke dalam, sulit dibaca dan sulit menangani error
    });
  });
});
```

Karena itu lahirlah Promise.

### 13.4 Promise

**Promise** adalah objek yang mewakili hasil dari operasi asynchronous yang **akan selesai di masa depan**. Analoginya **struk antrean** di restoran: bukan makanannya, tetapi janji bahwa makanan akan datang.

Sebuah Promise selalu berada di salah satu dari tiga keadaan:

|Keadaan|Arti|
|---|---|
|`pending`|Masih diproses|
|`fulfilled`|Berhasil, membawa hasil|
|`rejected`|Gagal, membawa alasan (error)|

Membuat Promise:

```js
function ambilPengguna(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id <= 0) {
        reject(new Error("ID tidak valid")); // gagal
      } else {
        resolve({ id, nama: "Sari" }); // berhasil
      }
    }, 500);
  });
}
```

Memakai Promise dengan `.then`, `.catch`, `.finally`:

```js
ambilPengguna(1)
  .then((pengguna) => {
    console.log("Dapat:", pengguna);
    return pengguna.id; // hasil dilempar ke .then berikutnya
  })
  .then((id) => console.log("ID:", id))
  .catch((error) => console.log("Gagal:", error.message))
  .finally(() => console.log("Selesai"));
```

Rantai `.then` jauh lebih rapi daripada callback bersarang, tetapi ada cara yang lebih nyaman lagi.

### 13.5 `async` dan `await`

Ini adalah gaya penulisan modern yang membuat kode asynchronous **terlihat seperti kode sinkron**.

- Kata kunci `async` di depan fungsi membuat fungsi itu **selalu mengembalikan Promise**.
- Kata kunci `await` di depan sebuah Promise **menunggu hasilnya** (tanpa memblokir program lain), lalu memberikan nilainya.
- `await` hanya boleh dipakai di dalam fungsi `async` atau di level atas file ES Module (top-level await).

```js
const tunggu = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function ambilPengguna(id) {
  await tunggu(500); // simulasi delay
  if (id <= 0) throw new Error("ID tidak valid");
  return { id, nama: "Sari" };
}

async function utama() {
  try {
    const pengguna = await ambilPengguna(1);
    console.log("Dapat:", pengguna);

    const gagal = await ambilPengguna(0); // melempar error
    console.log(gagal); // tidak dijalankan
  } catch (error) {
    console.log("Gagal:", error.message);
  } finally {
    console.log("Selesai");
  }
}

utama();
```

Perhatikan bahwa penanganan error kembali memakai **`try...catch`** biasa, sama seperti kode sinkron. Inilah alasan utama `async/await` menjadi standar.

Pada ES Module, Anda bisa memakai **top-level await** tanpa membungkusnya dalam fungsi:

```js
const pengguna = await ambilPengguna(1);
console.log(pengguna);
```

### 13.6 Menjalankan Tugas Secara Paralel

Kesalahan yang sering terjadi: menunggu tugas yang **tidak saling bergantung** satu per satu.

```js
const tunggu = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// LAMBAT: berurutan, total sekitar 3 detik
console.time("berurutan");
await tunggu(1000);
await tunggu(1000);
await tunggu(1000);
console.timeEnd("berurutan");

// CEPAT: paralel, total sekitar 1 detik
console.time("paralel");
await Promise.all([tunggu(1000), tunggu(1000), tunggu(1000)]);
console.timeEnd("paralel");
```

Method `Promise` yang perlu Anda kenal:

|Method|Perilaku|
|---|---|
|`Promise.all([...])`|Menunggu **semua** berhasil. Jika ada satu yang gagal, langsung gagal.|
|`Promise.allSettled([...])`|Menunggu semua **selesai** (berhasil atau gagal), dan melaporkan hasil masing-masing.|
|`Promise.race([...])`|Hasilnya mengikuti Promise yang **paling dulu selesai**.|
|`Promise.any([...])`|Hasilnya adalah Promise pertama yang **berhasil**.|

Contoh praktis:

```js
const [pengguna, pesanan, produk] = await Promise.all([
  ambilPengguna(1),
  ambilPesanan(1),
  ambilProduk(1),
]);
```

Contoh `allSettled` ketika Anda ingin tahu hasil masing-masing meski ada yang gagal:

```js
const hasil = await Promise.allSettled([
  Promise.resolve("berhasil"),
  Promise.reject(new Error("gagal")),
]);

console.log(hasil);
// [
//   { status: 'fulfilled', value: 'berhasil' },
//   { status: 'rejected', reason: Error: gagal ... }
// ]
```

**Kapan berurutan, kapan paralel?**

- Jika langkah kedua **membutuhkan hasil** langkah pertama: berurutan (`await` satu per satu).
- Jika langkah-langkahnya **independen**: paralel (`Promise.all`).

### 13.7 Timer

```js
// Menjalankan sekali setelah jeda
const idTimeout = setTimeout(() => console.log("sekali"), 1000);
clearTimeout(idTimeout); // membatalkan

// Menjalankan berulang setiap interval
let hitung = 0;
const idInterval = setInterval(() => {
  hitung++;
  console.log(`Tick ${hitung}`);
  if (hitung === 3) clearInterval(idInterval); // hentikan setelah 3 kali
}, 500);
```

### 13.8 Kesalahan Umum pada Asynchronous

**1. Lupa `await`.** Anda mendapat Promise, bukan hasilnya.

```js
const pengguna = ambilPengguna(1); // lupa await
console.log(pengguna); // Promise { <pending> }
```

**2. Memakai `await` di dalam `forEach`.** `forEach` tidak menunggu fungsi async di dalamnya.

```js
// Salah: "selesai" tercetak sebelum semua tugas benar-benar selesai
[1, 2, 3].forEach(async (id) => {
  await ambilPengguna(id);
});
console.log("selesai");

// Benar (berurutan)
for (const id of [1, 2, 3]) {
  await ambilPengguna(id);
}

// Benar (paralel)
await Promise.all([1, 2, 3].map((id) => ambilPengguna(id)));
```

**3. Memblokir event loop.** Perulangan berat yang sinkron membuat **seluruh server berhenti melayani** selama perulangan berjalan.

```js
// Buruk di server: semua permintaan lain menunggu
while (true) {}
```

Untuk komputasi berat, gunakan Worker Threads atau layanan terpisah (topik lanjutan). Untuk pekerjaan I/O, selalu pilih versi asynchronous (misalnya `fs/promises`, bukan `fs.readFileSync`, di dalam server).

**4. Promise yang ditolak tanpa `catch`.** Ini menghasilkan `unhandled rejection` yang, pada Node.js modern, dapat **menghentikan proses**. Selalu tangani error dengan `try...catch` atau `.catch()`.

## Bab 14: Module dan npm

### Tujuan Bab Ini

- Membagi kode ke beberapa file menggunakan module.
- Membedakan ES Modules dan CommonJS.
- Memahami `package.json` dan cara memakai npm.

### 14.1 Mengapa Butuh Module

Menulis semua kode dalam satu file yang panjang membuatnya sulit dirawat. **Module** memungkinkan Anda memecah program menjadi file-file kecil yang masing-masing punya satu tanggung jawab, lalu saling menggunakannya.

### 14.2 ES Modules (ESM): Cara Modern

Ini standar resmi JavaScript, dan yang dipakai di buku ini. Pastikan `package.json` Anda memuat `"type": "module"` (atau gunakan ekstensi file `.mjs`).

**File `matematika.js` (yang mengekspor):**

```js
// Named export: bisa banyak per file
export const PI = 3.14159;

export function tambah(a, b) {
  return a + b;
}

// Default export: maksimal satu per file
export default function kali(a, b) {
  return a * b;
}
```

**File `main.js` (yang mengimpor):**

```js
import kali, { PI, tambah } from "./matematika.js";

console.log(tambah(2, 3)); // 5
console.log(kali(2, 3)); // 6
console.log(PI); // 3.14159
```

Hal yang perlu diperhatikan:

- Untuk file buatan sendiri, **path relatif wajib diawali `./` atau `../`** dan **ekstensi `.js` wajib ditulis** pada Node.js.
- Named import memakai kurung kurawal dan **nama harus sama** (bisa diganti dengan `as`): `import { tambah as jumlah } from "./matematika.js";`
- Default import tanpa kurung kurawal dan nama bebas.
- Mengimpor semua sekaligus: `import * as mat from "./matematika.js";`

Contoh membagi kode backend ke beberapa file:

```text
proyek/
  package.json
  src/
    index.js          <- titik masuk aplikasi
    config.js         <- pengaturan
    utils/
      format.js       <- fungsi bantu
    services/
      pengguna.js     <- logika bisnis pengguna
```

### 14.3 CommonJS (CJS): Cara Lama

Sebelum ESM ada, Node.js memakai CommonJS. Anda akan **masih sering menemuinya** di banyak proyek lama dan tutorial.

```js
// matematika.cjs
const tambah = (a, b) => a + b;
module.exports = { tambah };

// main.cjs
const { tambah } = require("./matematika.cjs");
console.log(tambah(2, 3));
```

Perbandingan singkat:

||ES Modules|CommonJS|
|---|---|---|
|Impor|`import ... from "..."`|`require("...")`|
|Ekspor|`export` / `export default`|`module.exports`|
|Standar|Standar resmi JavaScript|Khusus Node.js|
|Top-level `await`|Bisa|Tidak bisa|
|Aktif jika|`"type": "module"` atau `.mjs`|Default tanpa `"type"`, atau `.cjs`|

> **Saran:** Untuk proyek baru, gunakan **ES Modules**. Cukup kenali CommonJS agar bisa membaca kode lama.

### 14.4 Module Bawaan Node.js

Node.js menyediakan banyak module siap pakai. Awali dengan **`node:`** untuk menegaskan bahwa itu module bawaan:

```js
import { readFile } from "node:fs/promises";
import path from "node:path";
import os from "node:os";
import { randomUUID } from "node:crypto";

console.log(randomUUID()); // ID unik acak yang aman
console.log(os.platform()); // "linux", "darwin", atau "win32"
```

### 14.5 npm dan `package.json`

**npm (Node Package Manager)** adalah alat untuk memasang dan mengelola paket buatan orang lain. Registry npm adalah salah satu ekosistem paket terbesar di dunia.

Isi `package.json` yang umum:

```json
{
  "name": "proyek-saya",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "start": "node src/index.js",
    "dev": "node --watch src/index.js",
    "test": "node --test"
  },
  "dependencies": {
    "dayjs": "^1.11.0"
  },
  "devDependencies": {}
}
```

|Bagian|Fungsi|
|---|---|
|`name`, `version`|Identitas proyek|
|`type`|`"module"` untuk ESM|
|`scripts`|Perintah pintas yang dijalankan dengan `npm run <nama>`|
|`dependencies`|Paket yang dibutuhkan aplikasi saat berjalan|
|`devDependencies`|Paket yang hanya dibutuhkan saat pengembangan (testing, linter, dan lainnya)|

Perintah npm yang wajib dikuasai:

```bash
npm init -y                     # membuat package.json
npm install dayjs               # memasang paket (masuk ke dependencies)
npm install --save-dev eslint   # memasang paket untuk pengembangan
npm uninstall dayjs             # menghapus paket
npm install                     # memasang semua dependensi dari package.json
npm run dev                     # menjalankan script "dev"
npm start                       # pintasan untuk script "start"
npm test                        # pintasan untuk script "test"
npm outdated                    # melihat paket yang punya versi baru
npm audit                       # memeriksa kerentanan keamanan pada dependensi
```

Setelah memasang paket, akan muncul:

- folder **`node_modules/`**: tempat semua paket disimpan. **Jangan dimasukkan ke Git** dan jangan diedit manual.
- file **`package-lock.json`**: mengunci versi persis semua paket agar setiap orang mendapat hasil yang sama. **Sertakan ke Git.**

Contoh memakai paket:

```js
import dayjs from "dayjs";

console.log(dayjs().format("YYYY-MM-DD"));
```

### 14.6 Semantic Versioning (SemVer)

Versi paket berbentuk `MAJOR.MINOR.PATCH`, misalnya `1.11.4`:

- **PATCH** (`1.11.4` ke `1.11.5`): perbaikan bug, aman.
- **MINOR** (`1.11.x` ke `1.12.0`): fitur baru yang kompatibel.
- **MAJOR** (`1.x.x` ke `2.0.0`): perubahan yang **bisa merusak** kode lama.

Tanda di depan versi pada `package.json`:

|Penulisan|Artinya|
|---|---|
|`^1.11.0`|Boleh naik selama MAJOR sama (`1.11.0` sampai sebelum `2.0.0`)|
|`~1.11.0`|Boleh naik hanya PATCH (`1.11.0` sampai sebelum `1.12.0`)|
|`1.11.0`|Harus persis versi itu|

### 14.7 File `.gitignore`

Buat file `.gitignore` di akar proyek agar file tertentu tidak ikut tersimpan di Git:

```text
node_modules/
.env
*.log
```

### 14.8 Keamanan Dependensi

Setiap paket yang Anda pasang adalah kode orang lain yang berjalan di server Anda. Biasakan:

1. **Pasang hanya paket yang benar-benar perlu.** Semakin sedikit dependensi, semakin kecil risikonya.
2. **Periksa reputasi paket**: jumlah unduhan, pemeliharaan terakhir, dan repositorinya.
3. **Waspadai salah ketik nama paket** (typosquatting), yaitu paket berbahaya bernama mirip paket populer.
4. **Jalankan `npm audit`** secara berkala dan perbarui dependensi yang rentan.
5. **Selalu commit `package-lock.json`.**

## Bab 15: Class dan Pemrograman Berorientasi Objek Dasar

### Tujuan Bab Ini

- Membuat class, constructor, dan method.
- Memahami pewarisan (`extends`) dan `super`.
- Memakai properti private, getter, setter, dan static.
- Menghindari jebakan `this`.

### 15.1 Apa Itu Class

**Class** adalah **cetakan (blueprint)** untuk membuat object dengan struktur dan perilaku yang sama. Analoginya **cetakan kue**: satu cetakan bisa menghasilkan banyak kue. Setiap kue yang dihasilkan disebut **instance**.

```js
class Pengguna {
  constructor(nama, email) {
    this.nama = nama;
    this.email = email;
  }

  sapa() {
    return `Halo, saya ${this.nama}`;
  }
}

const sari = new Pengguna("Sari", "sari@contoh.com");
const budi = new Pengguna("Budi", "budi@contoh.com");

console.log(sari.sapa()); // Halo, saya Sari
console.log(budi.sapa()); // Halo, saya Budi
console.log(sari instanceof Pengguna); // true
```

- `constructor` dijalankan otomatis saat `new` dipanggil, dipakai untuk menyiapkan data awal.
- `this` di dalam class merujuk pada **instance yang sedang dipakai**.
- `new` wajib dipakai untuk membuat instance.

### 15.2 Properti Private, Getter, Setter, dan Static

```js
class RekeningBank {
  #saldo = 0; // properti private: hanya bisa diakses di dalam class
  static jumlahRekening = 0; // milik class, bukan milik instance

  constructor(pemilik, saldoAwal = 0) {
    this.pemilik = pemilik;
    this.#saldo = saldoAwal;
    RekeningBank.jumlahRekening++;
  }

  // Getter: dibaca seperti properti, bukan dipanggil seperti fungsi
  get saldo() {
    return this.#saldo;
  }

  setor(jumlah) {
    if (jumlah <= 0) throw new Error("Jumlah setor harus positif");
    this.#saldo += jumlah;
  }

  tarik(jumlah) {
    if (jumlah > this.#saldo) throw new Error("Saldo tidak cukup");
    this.#saldo -= jumlah;
  }

  // Static method: dipanggil lewat nama class
  static bandingkan(a, b) {
    return a.saldo - b.saldo;
  }
}

const rek = new RekeningBank("Sari", 100000);
rek.setor(50000);
console.log(rek.saldo); // 150000  (memakai getter)
// console.log(rek.#saldo); // SyntaxError: properti private tidak bisa diakses dari luar
// rek.saldo = 1;  // tidak berpengaruh/error: getter tanpa setter

console.log(RekeningBank.jumlahRekening); // 1
```

Properti private (diawali `#`) melindungi data agar hanya bisa diubah lewat method yang Anda sediakan. Ini disebut **enkapsulasi**, dan mencegah data dirusak dari luar.

### 15.3 Pewarisan (`extends`)

Class dapat **mewarisi** properti dan method dari class lain.

```js
class Hewan {
  constructor(nama) {
    this.nama = nama;
  }

  bersuara() {
    return `${this.nama} bersuara`;
  }
}

class Kucing extends Hewan {
  constructor(nama, warna) {
    super(nama); // WAJIB dipanggil dulu, memanggil constructor class induk
    this.warna = warna;
  }

  // Menimpa (override) method milik induk
  bersuara() {
    return `${this.nama} berkata: meong`;
  }

  info() {
    return `${super.bersuara()} dan berwarna ${this.warna}`; // memakai method induk
  }
}

const tom = new Kucing("Tom", "abu-abu");
console.log(tom.bersuara()); // Tom berkata: meong
console.log(tom.info()); // Tom bersuara dan berwarna abu-abu
console.log(tom instanceof Kucing); // true
console.log(tom instanceof Hewan); // true
```

> **Saran desain:** Jangan terlalu bergantung pada pewarisan berlapis-lapis. Pewarisan yang dalam membuat kode kaku dan sulit dipahami. Banyak developer lebih memilih **komposisi** (menyusun object dari bagian-bagian kecil yang dipakai bersama) dibanding pewarisan. Class dan pewarisan cukup dipakai di tempat yang benar-benar cocok, misalnya membuat error khusus seperti di Bab 12.

### 15.4 Jebakan `this`

Nilai `this` ditentukan oleh **cara fungsi dipanggil**, bukan tempat ia ditulis (kecuali pada arrow function). Ini penyebab bug klasik ketika method dipisahkan dari instance-nya:

```js
class Penghitung {
  hitungan = 0;

  tambah() {
    this.hitungan++;
  }
}

const p = new Penghitung();
p.tambah(); // berfungsi, this = p
console.log(p.hitungan); // 1

const fungsiLepas = p.tambah;
// fungsiLepas(); // TypeError: Cannot read properties of undefined (this hilang)
```

Ada dua solusi umum:

```js
class PenghitungAman {
  hitungan = 0;

  // Solusi 1: arrow function sebagai class field (this terkunci ke instance)
  tambah = () => {
    this.hitungan++;
  };
}

const pa = new PenghitungAman();
const fungsi = pa.tambah;
fungsi(); // aman
console.log(pa.hitungan); // 1

// Solusi 2: bind pada method biasa
// const fungsiBind = p.tambah.bind(p);
```

**Arrow function tidak punya `this` sendiri.** Ia memakai `this` dari lingkungan tempat ia ditulis. Karena itu, arrow function sangat berguna untuk callback di dalam method:

```js
class Timer {
  detik = 0;

  mulai() {
    const id = setInterval(() => {
      this.detik++; // this masih merujuk ke instance Timer
      console.log(this.detik);
      if (this.detik === 3) clearInterval(id);
    }, 1000);
  }
}

new Timer().mulai();
```

### 15.5 Sekilas tentang Prototype

Di balik layar, class di JavaScript dibangun di atas mekanisme bernama **prototype**. Setiap object punya "induk" tempat JavaScript mencari properti yang tidak ditemukan pada object itu sendiri. Anda tidak perlu mendalaminya sekarang. Cukup ketahui bahwa `class` adalah sintaks yang lebih nyaman untuk mekanisme tersebut.

## Bab 16: Node.js untuk Backend

### Tujuan Bab Ini

### 16.1 Objek `process`

`process` adalah objek global yang berisi informasi tentang program yang sedang berjalan.

```js
console.log(process.version); // versi Node.js, misalnya "v24.x.x"
console.log(process.platform); // "linux", "darwin", "win32"
console.log(process.cwd()); // folder kerja saat ini

**Argumen baris perintah.** Jalankan `node salam.js Sari Budi`:

// salam.js

```

**Mengakhiri program:**

```js
process.exit(0); // 0 = sukses, angka lain = gagal
```

### 16.2 Environment Variable

**Environment variable** adalah pengaturan yang disimpan **di luar kode**, misalnya port server, alamat database, dan kunci rahasia. Ini praktik standar di backend karena:

- pengaturan bisa berbeda tiap lingkungan (laptop, staging, produksi) tanpa mengubah kode;
- **rahasia tidak ikut tersimpan di repositori Git**.

Baca dengan `process.env`. Nilainya **selalu string**, dan bisa `undefined`.

```js
const port = Number(process.env.PORT) || 3000;
const mode = process.env.NODE_ENV ?? "development";
console.log(port, mode);
```

Untuk memuat dari file `.env`, Node.js modern menyediakan opsi bawaan:

File `.env`:

```text
PORT=4000
API_KEY=rahasia-jangan-disebar
```

Jalankan:

```bash
node --env-file=.env index.js
```

> **Peringatan keamanan:** File `.env` berisi rahasia. **Wajib dimasukkan ke `.gitignore`** dan tidak boleh diunggah ke GitHub. Sertakan file contoh bernama `.env.example` berisi nama variabel tanpa nilai rahasia.

### 16.3 Membaca dan Menulis File

Gunakan **`node:fs/promises`** yang berbasis Promise (tidak memblokir program):

```js
import { readFile, writeFile, appendFile, readdir, mkdir } from "node:fs/promises";

// Menulis (menimpa) file
await writeFile("catatan.txt", "Baris pertama\n", "utf-8");

// Menambah isi di akhir file
await appendFile("catatan.txt", "Baris kedua\n", "utf-8");

// Membaca file sebagai teks
const isi = await readFile("catatan.txt", "utf-8");
console.log(isi);

// Membuat folder (recursive: tidak error jika sudah ada)
await mkdir("keluaran/laporan", { recursive: true });

// Melihat isi folder
const daftar = await readdir(".");
console.log(daftar);
```

Menangani file yang tidak ada:

```js
try {
  await readFile("tidak-ada.txt", "utf-8");
} catch (error) {
  if (error.code === "ENOENT") {
    console.log("File tidak ditemukan");
  } else {
    throw error;
  }
}
```

Contoh menyimpan dan memuat data JSON dari file (bentuk paling sederhana dari "database"):

```js
import { readFile, writeFile } from "node:fs/promises";

async function muatData(lokasi) {
  try {
    return JSON.parse(await readFile(lokasi, "utf-8"));
  } catch (error) {
    if (error.code === "ENOENT") return []; // file belum ada, mulai dari kosong
    throw error;
  }
}

async function simpanData(lokasi, data) {
  await writeFile(lokasi, JSON.stringify(data, null, 2), "utf-8");
}

const tugas = await muatData("tugas.json");
tugas.push({ id: tugas.length + 1, judul: "Belajar Node.js" });
await simpanData("tugas.json", tugas);
```

> **Catatan:** Menyimpan data ke file JSON hanya cocok untuk belajar atau skala sangat kecil. Aplikasi sungguhan memakai database karena file tidak aman terhadap akses bersamaan dan tidak efisien untuk data besar.

### 16.4 Modul `path`

Jangan menyambung path dengan `+` atau `/` secara manual, karena Windows memakai `\` sedangkan macOS/Linux memakai `/`. Gunakan `path`:

```js
import path from "node:path";

console.log(path.join("data", "laporan", "2026.json")); // data/laporan/2026.json
console.log(path.basename("/a/b/laporan.json")); // "laporan.json"
console.log(path.extname("laporan.json")); // ".json"
console.log(path.dirname("/a/b/laporan.json")); // "/a/b"
console.log(path.resolve("data")); // path absolut dari folder kerja
```

Pada ES Module, lokasi file yang sedang berjalan bisa didapat dengan `import.meta.dirname` (Node.js 20.11 ke atas):

```js
import path from "node:path";

const lokasiData = path.join(import.meta.dirname, "data", "tugas.json");
console.log(lokasiData);
```

### 16.5 `fetch`: Memanggil API dari Node.js

Node.js modern menyertakan `fetch` bawaan (tidak perlu memasang paket tambahan). Contoh di bawah membutuhkan koneksi internet:

```js
const respons = await fetch("https://jsonplaceholder.typicode.com/todos/1");

if (!respons.ok) {
  throw new Error(`Permintaan gagal dengan status ${respons.status}`);
}

const data = await respons.json();
console.log(data);
```

Mengirim data dengan `POST`:

```js
const respons = await fetch("https://jsonplaceholder.typicode.com/posts", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Halo", body: "Isi pos", userId: 1 }),
});

console.log(respons.status); // 201
console.log(await respons.json());
```

Perhatikan bahwa `fetch` **tidak melempar error untuk status seperti 404 atau 500**. Ia hanya error jika jaringan gagal. Karena itu Anda **wajib memeriksa `respons.ok`** sendiri.

Praktik baik: beri **batas waktu (timeout)** agar permintaan tidak menggantung selamanya:

```js
const respons = await fetch("https://jsonplaceholder.typicode.com/todos/1", {
  signal: AbortSignal.timeout(5000), // batal setelah 5 detik
});
```

### 16.6 Membuat Server HTTP Sederhana

Node.js dapat menjalankan server web hanya dengan module bawaan `node:http`:

```js
import http from "node:http";

const server = http.createServer((req, res) => {
  console.log(`${req.method} ${req.url}`);

  res.writeHead(200, { "Content-Type": "text/plain; charset=utf-8" });
  res.end("Halo dari server Node.js!");
});

server.listen(3000, () => {
  console.log("Server berjalan di http://localhost:3000");
});
```

Jalankan file tersebut, lalu buka `http://localhost:3000` di browser. Anda melihat teks dari server Anda sendiri.

Istilah yang muncul:

- **`req` (request):** informasi permintaan dari klien (method seperti GET/POST, URL, header).
- **`res` (response):** alat untuk membalas klien (status code, header, isi).
- **Status code:** `200` OK, `201` Created, `400` Bad Request, `404` Not Found, `500` Internal Server Error.
- **Port:** "pintu" tempat server menerima permintaan (di sini 3000).

Di Bab 18 Anda akan mengembangkannya menjadi REST API sederhana. Pada proyek nyata, kebanyakan developer memakai framework seperti **Express**, **Fastify**, **Hono**, atau **NestJS** yang menyederhanakan routing dan middleware, tetapi konsep dasarnya sama seperti di atas.

### 16.7 EventEmitter

emitter.on("pesanan-dibuat", (pesanan) => {

## Bab 17: Praktik Baik dan Debugging

### Tujuan Bab Ini

- Menerapkan kebiasaan menulis kode yang bersih dan mudah dirawat.
- Mengenal alat bantu kualitas kode (ESLint, Prettier).
- Melakukan debugging secara sistematis.
- Mengenal dasar keamanan yang wajib diketahui pemula.

### 17.1 Kebiasaan Menulis Kode yang Baik

1. **Gunakan `const` secara default**, `let` bila perlu, dan jangan pakai `var`.
    
2. **Selalu pakai `===` dan `!==`.**
    
3. **Beri nama yang jelas.** Nama yang baik menghilangkan kebutuhan komentar.
    
4. **Buat fungsi kecil dengan satu tugas.**
    
5. **Hindari angka ajaib (magic number).** Beri nama pada nilai-nilai penting:
    
    ```js
    // Buruk
    if (percobaan > 5) { /* ... */ }
    
    // Baik
    const MAKS_PERCOBAAN_LOGIN = 5;
    if (percobaan > MAKS_PERCOBAAN_LOGIN) { /* ... */ }
    ```
    
6. **Gunakan guard clause** untuk mengurangi `if` bersarang (Bab 6).
    
7. **Tangani error dengan sengaja** (Bab 12), jangan ditelan.
    
8. **Hindari variabel global** dan efek samping tersembunyi.
    
9. **Jangan mengulang kode** (DRY), tetapi jangan pula terlalu cepat membuat abstraksi yang rumit.
    
10. **Tulis komentar untuk menjelaskan "mengapa", bukan "apa".**
    
    ```js
    // Buruk: hanya mengulang isi kode
    // tambah 1 ke i
    i++;
    
    // Baik: menjelaskan alasan
    // API pihak ketiga membatasi 100 permintaan per menit, jadi kita beri jeda
    await tunggu(600);
    ```
    

### 17.2 Strict Mode

**Strict mode** membuat JavaScript lebih ketat sehingga kesalahan tertentu langsung menjadi error, bukan diam-diam diabaikan. **ES Modules otomatis berjalan dalam strict mode**, jadi Anda sudah terlindungi jika memakai `"type": "module"`. Pada file CommonJS, tambahkan `"use strict";` di baris paling atas.

### 17.3 Dokumentasi dengan JSDoc

Anda dapat mendokumentasikan tipe parameter langsung di komentar. Editor seperti VS Code akan memberikan saran otomatis dan peringatan kesalahan tipe, bahkan tanpa TypeScript.

```js
/**
 * Menghitung total harga setelah diskon.
 * @param {number} harga - Harga satuan.
 * @param {number} jumlah - Jumlah barang.

function hitungTotal(harga, jumlah, diskonPersen = 0) {
  const kotor = harga * jumlah;

```

### 17.4 ESLint dan Prettier

- **ESLint** menganalisis kode dan memperingatkan potensi bug atau gaya yang buruk (misalnya variabel tidak terpakai).

### 17.5 Membaca Pesan Error

Pesan error bukan musuh. Ia adalah **petunjuk**. Contoh:

```text
/home/sari/proyek/src/index.js:5
  console.log(pengguna.alamat.kota);
                              ^

TypeError: Cannot read properties of undefined (reading 'kota')
    at tampilkanKota (/home/sari/proyek/src/index.js:5:31)
    at main (/home/sari/proyek/src/index.js:10:3)
```

Cara membacanya:

1. **Jenis dan pesan error:** `TypeError: Cannot read properties of undefined (reading 'kota')` berarti Anda mencoba membaca `.kota` dari sesuatu yang bernilai `undefined`. Artinya `pengguna.alamat` tidak ada.
2. **Lokasi:** `index.js:5:31` (file, baris 5, kolom 31).
3. **Stack trace:** urutan fungsi yang dipanggil hingga error terjadi. Baris paling atas adalah tempat error muncul, baris di bawahnya adalah "siapa yang memanggil".

Kebiasaan pertama saat error: **baca pesannya sampai habis**, lalu buka file dan baris yang disebutkan.

### 17.6 Teknik Debugging

**1. Cetak nilai dengan `console.log` (paling cepat).** Cetak nilai variabel di titik-titik penting untuk memastikan asumsi Anda benar. Beri label agar mudah dibaca:

```js
console.log("pengguna:", pengguna);
console.log("tipe umur:", typeof umur, umur);
```

**2. Gunakan debugger.** Anda dapat menjeda program pada baris tertentu (breakpoint), lalu melihat semua nilai variabel dan menjalankan kode selangkah demi selangkah.

- Di **VS Code**: klik di sebelah kiri nomor baris untuk memasang breakpoint, lalu buka terminal khusus melalui **Run and Debug > JavaScript Debug Terminal** dan jalankan `node index.js` di sana.
- Dari terminal: `node --inspect-brk index.js`, lalu sambungkan dengan debugger yang Anda pakai.

**3. Langkah sistematis:**

1. **Reproduksi:** temukan langkah pasti yang memunculkan bug.
2. **Persempit:** hapus atau komentari bagian kode sampai Anda menemukan bagian kecil yang bermasalah.
3. **Buat hipotesis:** "Saya kira `umur` bertipe string."
4. **Uji hipotesis:** cetak atau debug untuk membuktikannya.
5. **Perbaiki lalu verifikasi**, dan idealnya tambahkan test agar bug tidak kembali.

**4. Rubber duck debugging.** Jelaskan kode Anda baris demi baris kepada benda apa saja (bahkan bebek karet). Sering kali kesalahan ditemukan saat Anda sedang menjelaskannya.

### 17.7 Bug Umum Pemula (Daftar Periksa)

|Gejala|Kemungkinan penyebab|
|---|---|
|`undefined` muncul di tempat yang tak terduga|Salah ketik nama properti, lupa `return`, atau lupa `await`|
|`NaN` di hasil hitungan|Mengoperasikan string non-angka atau `undefined`|
|Hasil `"53"` bukan `8`|Penggabungan string, bukan penjumlahan; ubah ke `Number` dulu|
|Data berubah sendiri|Menyalin object/array dengan referensi yang sama (Bab 10.7)|

|Perulangan tak berhenti|Kondisi tidak pernah menjadi salah|
|`this` bernilai `undefined`|Method dilepas dari instance-nya (Bab 15.4)|
|`Cannot use import statement outside a module`|Belum ada `"type": "module"`|

### 17.8 Dasar Keamanan untuk Pemula Backend

Keamanan bukan fitur tambahan, ia harus menjadi kebiasaan sejak awal.

1. **Jangan pernah mempercayai input dari luar.** Semua data dari pengguna (body, query, header, file) harus **divalidasi**: tipe, panjang, format, dan rentang.
2. **Jangan menyimpan rahasia di dalam kode.** Password, API key, dan token disimpan di environment variable, dan **jangan pernah di-commit ke Git**.

5. **Jangan bocorkan detail error ke klien.** Kirim pesan umum ke pengguna, simpan detail di log server.
6. **Perbarui dependensi secara berkala** dan jalankan `npm audit`.
7. **Gunakan `crypto`** (bukan `Math.random`) untuk nilai acak yang berkaitan dengan keamanan.

## Bab 18: Proyek Mini, REST API Task Manager

### Tujuan Bab Ini

Menggabungkan hampir semua yang sudah dipelajari menjadi satu proyek nyata: **REST API sederhana untuk mengelola daftar tugas**, hanya memakai module bawaan Node.js.

### 18.1 Gambaran Proyek

**REST API** adalah cara server menyediakan data melalui URL dan method HTTP. Bentuknya:

|Method|URL|Fungsi|Status sukses|
|---|---|---|---|
|`GET`|`/tasks`|Ambil semua tugas|`200`|
|`POST`|`/tasks`|Buat tugas baru|`201`|
|`GET`|`/tasks/:id`|Ambil satu tugas|`200`|
|`PATCH`|`/tasks/:id`|Ubah sebagian data tugas|`200`|
|`DELETE`|`/tasks/:id`|Hapus tugas|`204`|

Bentuk data satu tugas:

```json
{ "id": 1, "title": "Belajar JavaScript", "done": false }
```

Kode status kesalahan yang dipakai: `400` (data dari klien salah), `404` (tidak ditemukan), `500` (kesalahan server).

Konsep yang akan Anda pakai: fungsi, array, object, `async/await`, `try...catch`, environment variable, `JSON`, dan `node:http`.

### 18.2 Menyiapkan Proyek

```bash
mkdir task-api
cd task-api
npm init -y
```

Edit `package.json`:

```json
{
  "name": "task-api",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "start": "node server.js",
    "dev": "node --watch server.js"
  }
}
```

### 18.3 Kode Server

Buat file `server.js`:

```js
import http from "node:http";

const PORT = Number(process.env.PORT) || 3000;

// "Database" sementara di memori. Data hilang saat server dimatikan.
let tasks = [];
let nextId = 1;

/**
 * Mengirim respons JSON dengan status tertentu.
 */
function sendJson(res, statusCode, data) {
  const body = JSON.stringify(data);
  res.writeHead(statusCode, {
    "Content-Type": "application/json; charset=utf-8",
    "Content-Length": Buffer.byteLength(body),
  });
  res.end(body);
}

/**
 * Membaca dan mem-parse body JSON dari request.
 * Melempar SyntaxError jika JSON tidak valid.
 */
async function readJsonBody(req) {
  const chunks = [];
  for await (const chunk of req) {
    chunks.push(chunk);
  }
  const raw = Buffer.concat(chunks).toString("utf-8");
  if (raw.length === 0) return {};
  return JSON.parse(raw);
}

const server = http.createServer(async (req, res) => {
  try {
    const url = new URL(req.url, `http://${req.headers.host}`);
    const pathname = url.pathname;
    const method = req.method;

    // GET /tasks
    if (method === "GET" && pathname === "/tasks") {
      return sendJson(res, 200, tasks);
    }

    // POST /tasks
    if (method === "POST" && pathname === "/tasks") {
      const body = await readJsonBody(req);

      if (typeof body.title !== "string" || body.title.trim() === "") {
        return sendJson(res, 400, { error: "title wajib berupa teks dan tidak boleh kosong" });
      }

      const task = { id: nextId++, title: body.title.trim(), done: false };
      tasks.push(task);
      return sendJson(res, 201, task);
    }

    // Route dengan id: /tasks/123
    const match = pathname.match(/^\/tasks\/(\d+)$/);
    if (match) {
      const id = Number(match[1]);
      const task = tasks.find((t) => t.id === id);

      if (!task) {
        return sendJson(res, 404, { error: "Tugas tidak ditemukan" });
      }

      // GET /tasks/:id
      if (method === "GET") {
        return sendJson(res, 200, task);
      }

      // PATCH /tasks/:id
      if (method === "PATCH") {
        const body = await readJsonBody(req);

        if (body.title !== undefined) {
          if (typeof body.title !== "string" || body.title.trim() === "") {
            return sendJson(res, 400, { error: "title harus berupa teks yang tidak kosong" });
          }
          task.title = body.title.trim();
        }

        if (body.done !== undefined) {
          if (typeof body.done !== "boolean") {
            return sendJson(res, 400, { error: "done harus berupa boolean" });
          }
          task.done = body.done;
        }

        return sendJson(res, 200, task);
      }

      // DELETE /tasks/:id
      if (method === "DELETE") {
        tasks = tasks.filter((t) => t.id !== id);
        res.writeHead(204);
        return res.end();
      }
    }

    return sendJson(res, 404, { error: "Route tidak ditemukan" });
  } catch (error) {
    if (error instanceof SyntaxError) {
      return sendJson(res, 400, { error: "Body bukan JSON yang valid" });
    }
    console.error(error); // detail lengkap hanya di log server
    return sendJson(res, 500, { error: "Terjadi kesalahan pada server" });
  }
});

server.listen(PORT, () => {
  console.log(`Server berjalan di http://localhost:${PORT}`);
});
```

Jalankan:

```bash
npm run dev
```

### 18.5 Mencoba API dengan Skrip Node.js

Buat file `uji.js` (jalankan dengan `node uji.js` saat server hidup):

```js
const BASE = "http://localhost:3000";

async function panggil(path, options) {
  const respons = await fetch(BASE + path, options);
  const teks = await respons.text();
  return { status: respons.status, body: teks ? JSON.parse(teks) : null };
}

const jsonHeaders = { "Content-Type": "application/json" };

console.log("Buat tugas:", await panggil("/tasks", {
  method: "POST",
  headers: jsonHeaders,
  body: JSON.stringify({ title: "Belajar JavaScript" }),
}));

console.log("Buat tugas tidak valid:", await panggil("/tasks", {
  method: "POST",
  headers: jsonHeaders,
  body: JSON.stringify({ title: "" }),
}));

console.log("Semua tugas:", await panggil("/tasks"));

console.log("Tandai selesai:", await panggil("/tasks/1", {
  method: "PATCH",
  headers: jsonHeaders,
  body: JSON.stringify({ done: true }),
}));

console.log("Hapus:", await panggil("/tasks/1", { method: "DELETE" }));
console.log("Cari yang dihapus:", await panggil("/tasks/1"));
```

Hasil yang diharapkan: pembuatan bernilai status `201`, data kosong ditolak dengan `400`, pembaruan `200`, penghapusan `204`, dan pencarian setelah dihapus `404`.

### 18.8 Tantangan Lanjutan

Kerjakan berurutan dari yang termudah:

1. **Tambahkan field `createdAt`** (waktu pembuatan dalam format ISO UTC) pada setiap tugas.
2. **Filter:** dukung `GET /tasks?done=true` untuk hanya menampilkan tugas yang sudah selesai (petunjuk: `url.searchParams.get("done")`).
3. **Persistensi:** simpan `tasks` ke file `tasks.json` menggunakan `fs/promises` (Bab 16.3), dan muat saat server dinyalakan.
4. **Pagination:** dukung `GET /tasks?page=1&limit=10`.
5. **Refactor:** pindahkan logika ke beberapa file (`routes.js`, `storage.js`, `http-utils.js`) memakai ES Modules.
6. **Test:** tulis test dengan `node:test` untuk fungsi validasi.
7. **Bandingkan:** tulis ulang API ini dengan framework (misalnya Express atau Fastify) dan rasakan perbedaannya.
